# Control and coverage decisions

Use this table when similar signals, divergent timing or multiple actors make a control choice ambiguous. Concrete source-index examples are in the [San d'Oria authoring record](../../../../timelines/sandoria.authoring.md); its encounter IDs and timings are not general rules.

| Situation                                 | Decision and check                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Several IDs share a cue and continuation  | Use one display and accept the observed ID set. Verify each ID against the same display. R12S Double Sobat is an example.                                                                                                                                                                                                                              |
| Player response or subsequent cues differ | Use separate paths when a signal distinguishes them. Keep shared cues outside the branch until the selector arrives. R12S Netherwrath Near and Far differ even though the timing agrees.                                                                                                                                                               |
| A known route drifts                      | Sync to an observed event and verify a forecast made before the next major impact.                                                                                                                                                                                                                                                                     |
| The first selector is missing             | Use `when resume-at` when the same option can resume at a known offset. Use a fallback option when the observed recovery signal requires its own timing or remaining schedule. Compare original and signal-removal replay.                                                                                                                             |
| Checkpoint can start independently        | Check independent entry, cancellation of the preceding schedule, and restart after a wipe. Use a phase-scoped completion signal when it is observed and specific to that boundary.                                                                                                                                                                     |
| Same ability on different routes          | Find an earlier distinctive source or neighboring signal. A later shared ability is not automatically a selector. Replay subsequent shared signals to check conflicting selections.                                                                                                                                                                    |
| Choice visible only shortly before impact | Measure selection-to-impact time. Set an achievable lead for that first conditional event, record why, and keep longer warning goals for later events.                                                                                                                                                                                                 |
| Opening ability reused later              | Check whether another phase would make the old entry signal restart the schedule. Keep one phase when event syncs suffice, or constrain transitions with observed context.                                                                                                                                                                             |
| Merge near a scheduled display            | Test control just before, at and after the display, including raw milliseconds that round to the same tenth. The merge may cancel option events. An earlier cast start can replace the schedule before impact while the option supplies the initial warning.                                                                                           |
| Several bosses casting concurrently       | Keep simultaneous displays distinct. Check whether a sync shifts another boss's schedule. If the joint schedule ends at a death, identify the actual runtime signal and state whether the survivor's tail is authored.                                                                                                                                 |
| Earlier progression                       | Widening an Ability window can repair execution too late for advance warning. Check whether a sufficiently long StartsUsing signal can restore the schedule before the query cutoff.                                                                                                                                                                   |
| Repeated block                            | Separate a complete observed body, an actual next boundary, and a synthetic future iteration. Use `count` when the encounter establishes a fixed cap. Test the last complete body, suppression of the next iteration, and any earlier `until`. If the exit starts a fresh schedule, use a phase transition and check cancellation of the old schedule. |

For R12S Raptor and Serpentine, impact identifies a known offset in the selected path. For San d’Oria Kirin, the ADCD and Double Cast recovery schedules have separate signal anchors and lead-time evidence. Preserve that distinction until a shared offset is verified.

For each consequential decision, preserve the source indices, competing interpretation, chosen control and user-visible effect. Scope changes and relaxed lead targets are model revisions: record them before fresh independent evaluation.

A compact coverage table should identify each choice/loop, development observations, held-out observations and synthetic checks. Use `review.coverage` for signal selections, bounded display bodies, and first body gaps; preserve its role and unmatched-display warnings. Check `body_coverage_inputs` before interpreting zero counts from an older report. A terminal body without the next observed anchor remains unverified; combine separate test evidence explicitly. An unobserved held-out route stays unverified even when every held-out file passes. See the [evaluation contract](../../../../docs/AUTHORED_EVALUATION.md#분기반복-커버리지) for each metric's limits.

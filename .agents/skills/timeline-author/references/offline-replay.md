# 오프라인 타임라인 검증: 첫 구현

최종 타임라인 KDL의 구조 검사와 lifecycle·phase·event·sync·branch·loop 재생을 구현했다. `compare`는 정규화 관측 JSON과 이 도구가 수집한 FFLogs 전투 파일을 받는다. [생성기](generation.md)는 FFLogs JSON과 mode에서 lifecycle·공통 시전 일정·Ability 동기화를 생성한다. `compare`의 FFLogs 입력은 아래 원본 관측 계약을 유지하며 생성된 실행 조건을 검증하는 runtime 관측으로 자동 변환하지 않는다.

생성 evidence의 `automatic-draft-validation-v1`은 보고서 전체를 보류해 대표 경로·분기·지원된 반복을 재학습하는 구조 검사다. 반복의 실제 관측 순서와 다음 발생 전 종료 여부를 평가하며, 최종 KDL의 시각·window·미래 예고·실행을 검증한 결과와 구분한다. 지원 범위는 [생성 계약](generation.md)의 독립 검증 항목을 따른다.

사용 가능성은 [실용적인 품질 기준](generation.md#실용적인-품질-기준)에 따라 주요 기믹의 사전 예고·제어 안전성·후속 신호를 통한 복구로 평가한다. 엄격한 관측 대응의 `unresolved`는 그 원인과 영향을 함께 해석하며, 실행기 규칙 위반·잘못된 제어와 구분한다. 현재 자동 검사는 이 실용성 평가 전체를 구현하지 않는다. 근사 표시를 허용해도 KDL 구조 검사와 명시된 실행 제약은 그대로 적용된다.

체크포인트 검증은 구간별 로그에서의 독립 진입·예고와, 연속 기록에서의 종료·예약 취소·재시작을 구분한다. 합성 기록에 종료나 전멸 신호를 추가해 실행 규칙을 점검할 수 있다. 실제 전투의 신호 시각과 순서를 확인하려면 해당 구간을 잇는 ACT 기록이 필요하다.

| 명령                                                           | 현재 동작                                                                                                            |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `btimeline validate timeline.kdl`                              | KDL 2 파싱, 노드·속성·타입, ID·참조·순환, window, 중첩 및 명확한 회차 범위를 검사한다. 미검사 범위를 함께 출력한다.  |
| `btimeline validate timeline.kdl --json`                       | 이름과 `catalog`의 이벤트 정의·분기 선택지·반복 기준점 및 소유 문맥을 반환한다. 평가 profile의 ID 바인딩에 사용한다. |
| `btimeline compare timeline.kdl recording.json`                | 독립적인 관측 기록을 재생하고 사람이 읽는 실행 기록을 출력한다.                                                      |
| `btimeline compare timeline.kdl first.json second.json --json` | 각 기록을 독립적으로 재생하고 원본 밀리초를 보존하는 JSON을 출력한다. 결과에는 미검사 범위도 포함한다.               |

실행 예:

```sh
cargo run -- validate tests/fixtures/timeline/basic.kdl
cargo run -- compare tests/fixtures/timeline/basic.kdl tests/fixtures/timeline/basic.json
cargo run -- compare tests/fixtures/timeline/fflogs-native.kdl tests/fixtures/pull.json --json
```

## 미래 일정 조회

```sh
btimeline forecast timeline.kdl recording.json --at-ms 10000 --horizon-ms 30000
```

항상 JSON을 출력한다. 입력은 아래의 정규화 관측 JSON이며 FFLogs 원본을 직접 받지 않는다. 현재 기록을 10초까지 재생한 상태에서, 추가 신호가 없다는 가정으로 이후 30초의 예정된 표시를 조회한다. 기존 `compare`와 같은 실행 코드를 사용하며 KDL 문법·실행 의미는 변경하지 않는다.

| 필드·규칙                    | 의미                                                                                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `at_ms`, `until_ms`          | 실제 밀리초 기준 조회 시각과 끝. 반환 범위는 `(at_ms, until_ms]`                                                                  |
| `status`, `phase`, `run`     | 조회 시점의 활성/유휴 상태(`active`/`idle`), 활성 phase 또는 null, 전투 시도 번호. 품질 통과 상태가 아님                          |
| `observations_used`          | 조회 시점 이하의 관측 수. 같은 밀리초의 모든 관측·제어를 적용한 뒤 조회                                                           |
| `events`                     | 예정된 visible 이벤트의 `id`, `name`, `at_ms`, `lead_ms`, `duration_ms`, `run`, `context`. 반복은 같은 ID의 여러 예정 시각을 반환 |
| 완료·hidden 이벤트           | 이미 처리했거나 조회 시각에 처리한 이벤트, `visible=#false` 이벤트는 제외. 과거 이벤트의 지속 중인 표시 조회는 범위 밖            |
| 분기·합류·탈출               | 이미 관측한 선택·합류·탈출은 반영. 미선택 option이나 미래 신호로만 정해지는 phase·merge·until 동작은 추측하지 않음                |
| `diagnostics`                | 조회 시점까지 발생한 ambiguous·violation·unresolved. 가상 미래에서 선택 창이 닫히는 진단을 현재 사실로 섞지 않음                  |
| `assumptions`, `not_checked` | 미래 신호 없음이라는 조건과 ACT·게임·UI 미검증 범위                                                                               |
| 입력 범위                    | `0 <= at_ms <= recording.end_ms`, `horizon_ms > 0`. 전체 정규화 기록의 무결성·정렬은 검사하되 미래 관측은 실행에 사용하지 않음    |
| 조회 범위                    | 관측 종료 이후까지도 예측 가능. 끝은 10조 ms 이하이며 기존의 반복·분기 처리량 제한 적용                                           |

조회 결과는 현재 알려진 경로를 그대로 진행했을 때의 조건부 일정이다. 이후 sync·종료·전환이 오면 바뀌거나 취소될 수 있다. 이 API에서 5초 전 일정이 나온다는 사실은 실제 UI에서 그 표시를 5초 전에 보였다는 증거가 아니다.

`projection_diagnostics`는 추가 신호 없이 가상 미래를 진행하며 생긴 진단이다. 예를 들어 아직 미선택인 분기의 close 도달은 이 배열의 `unresolved`이며 현재 사실인 `diagnostics`와 구분한다. 예측 구간의 제어 충돌·실행 제약 위반도 이 배열에서 확인한다.

## 실행 식별자

JSON 실행 행의 `event`에는 `id`, `name`, `visible`, `duration_ms`를 제공한다. `detail` 문자열을 파싱해 이벤트를 식별하지 않는다. 이벤트와 phase·option·merge·until 제어 행의 `context`는 정적인 `phase`, `loop_id`, `branch`, `option`과 동적인 `phase_instance`, `iteration`을 제공한다. 해당하지 않는 소유자는 null이다. 분기 옵션 안 반복은 상위 선택지 소유를 유지한다.

이전 JSON의 `context.on_exit`는 제거됐다. 반복 뒤의 새 일정은 `phase` 행과 후속 표시의 `context.phase_instance`로 추적한다. `until` 행은 현재 phase에서 반복만 닫았음을 나타낸다.

| 식별 값          | 의미                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `run`            | 기록 안의 전투 시작 회차                                                                                                  |
| `phase_instance` | 기록 안의 성공한 phase 진입마다 증가. 같은 phase 재진입도 구별. phase 밖 이벤트는 0                                       |
| `iteration`      | 반복 첫 회차는 1. 반복 밖은 null. sync로 같은 회차를 재설정해도 유지하며 phase 시간 점프로 건너뛴 회차는 모델 번호에 반영 |

`(run, phase_instance, event.id, iteration)`으로 같은 이벤트 정의의 실행 발생을 구별하며 forecast도 같은 문맥을 반환한다. 이 필드들은 추적용 메타데이터다. 실행 시각·선택·동기화 규칙이나 외부 실행기의 KDL 문법을 바꾸지 않는다.

## 작성 타임라인의 평가

`btimeline evaluate MANIFEST --profile PROFILE -o REPORT`는 명시한 profile의 FFLogs 투영 가정으로 기존 재생·forecast를 실행한다. Mistwake·Clyteum·산도리아의 공통 TypeScript 평가기를 대체한다. 입력 누락/품질 제외와 실행 오류/예고 실패를 구분하고, 적격 입력이 없으면 통과하지 않는다. KDL·profile·manifest 해시와 원본 위치를 보고서에 연결한다.

전체 판정·profile 필드·기존 결과와의 대조는 [작성 평가 계약](authored-evaluation.md)을 따른다. profile은 검증용 자료이고 KDL의 외부 실행 의존성이 아니다. FFLogs를 직접 넣은 `compare`의 신호 의미와 ACT/UI 미검증 경계는 유지한다.

`review REPORT --limit 8`은 기존 결과를 다시 재생하지 않고 실패·미분류를 제한된 예시로 요약한다. `evidence INPUT --around-index N --limit 40`은 해당 원본 관측 주변의 FFLogs 시전만 조회한다. 두 명령은 생략 수와 근거 파일 해시를 제공하며, 잘린 출력이나 감사가 없는 과거 보고서에서 전체 커버리지를 추정하지 않는다.

## 입력 관측

```json
{
  "version": 1,
  "end_ms": 2000,
  "observations": [
    { "at_ms": 0, "type": "InCombat", "fields": { "inGameCombat": "1" } },
    { "at_ms": 1500, "type": "Ability", "fields": { "id": "A001", "source": "Boss" } }
  ]
}
```

| 필드             | 계약                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------- |
| `version`        | 현재 1만 허용한다.                                                                           |
| `end_ms`         | 관측 종료 시각. 상대 밀리초 정수이며 0 이상이다.                                             |
| `observations`   | 원본 시각순 배열. 시각이 같으면 배열 순서를 보존한다.                                        |
| `at_ms`          | 0 이상 end_ms 이하의 상대 밀리초 정수. 정렬되지 않은 입력은 오류이며 자동 재정렬하지 않는다. |
| `type`, `fields` | 로그 타입 이름과 문자열 필드 맵. 필드가 없으면 해당 조건은 일치하지 않는다.                  |

관측 시각은 밀리초를 보존하고, 타임라인의 예정 시각·window 비교는 정수 0.1초 단위로 처리한다. 현재 구현의 최대 입력 시각은 10조 밀리초이며 계산 범위를 위한 제한이다. 게임 전투 길이 제한을 의미하지 않는다.

동일한 원본 밀리초의 관측은 배열 순서대로 모두 처리한 뒤 그 시각의 예정 이벤트를 실행한다. 예를 들어 같은 시각의 무관한 로그 뒤에 전멸 신호가 오면 전멸이 해당 시각의 이벤트를 취소한다. 반올림 후에만 같은 0.1초가 된 관측은 묶지 않는다.

## 수집된 FFLogs 입력

수집 완료·페이지·전투 범위·액터 참조는 `inspect`와 같은 검증을 거친다. 이벤트의 시각이 배열 순서와 다르면 원본 인덱스를 보존하며 시각순으로 안정 정렬하고, 같은 시각의 원본 순서는 유지한다. 전투 시작 시각은 상대 밀리초를 계산하는 기준일 뿐이며 start·wipe·finish 신호를 자동으로 생성하지 않는다.

| FFLogs 원본           | 재생에서 사용하는 값                                                                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이벤트 타입 `cast` 등 | 독립적인 `FFLogs.cast` 등. ACT의 `Ability`·`StartsUsing`과 동일하다고 가정하지 않는다.                                                                          |
| `abilityGameID`       | 문자열 `raw.abilityGameID`와, 음이 아닌 경우 대문자 16진수 `id`. 이벤트 타입별 의미는 원본을 따른다.                                                            |
| 액터 참조             | masterData의 이름을 `source`·`target`으로 사용한다. `raw.sourceID`·`raw.targetID`는 보고서 내부 ID다. 이름의 언어와 번역 정확도는 별도 확인이 필요하다.         |
| 그 밖의 이벤트 필드   | `raw.필드명`으로 보존한다. 문자열은 그대로, 숫자·불리언·null 및 배열·객체는 JSON 텍스트로 표현한다.                                                             |
| 원본 위치             | 해당 관측이 직접 일으킨 start·phase·option·sync 등의 JSON 결과에 0부터 시작하는 `source_event_index`를 기록한다. 예정 이벤트 자체에는 인덱스를 추정하지 않는다. |

예를 들어 수집 파일의 `cast`, `abilityGameID: 46376`, `sourceID: 10`이 masterData에서 `Synthetic Boss`를 가리키면 `FFLogs.cast`, `id="B528"`, `source="Synthetic Boss"`로 매칭할 수 있다. FFLogs [공식 API 문서](https://www.fflogs.com/v2-api-docs/ff/report.doc.html)는 이벤트와 masterData를 별도로 제공한다. 이 매핑은 ACT 신호와의 동등성을 뜻하지 않는다.

실제 수집 파일로 확인한 범위와 입력 해시는 [FFLogs 입력 재생 확인](../../../../docs/fflogs-replay-verification.md)에 기록한다.

## 결과와 한계

`compare`는 입력마다 상태, 관측 수와 시작된 전투 시도 수를 요약한다. JSON에서는 `summaries`에 입력 경로별로 `status`, `observations`, `started_runs`를 제공하며 실행 기록은 `recordings`에 유지한다.

| 상태              | 의미                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `replayed`        | 시작 조건이 일치해 재생했다. 검증 통과나 누락 없는 비교를 의미하지 않는다.                         |
| `not_started`     | 관측은 있지만 시작 조건이 일치하지 않았다. 관측 불가와 실제 시작 신호 누락은 아직 구별하지 않는다. |
| `no_observations` | 입력에 관측이 없어 비교하지 못했다.                                                                |

명령의 성공 종료는 입력 처리 완료를 뜻한다. 상태와 실행 기록, 미검사 범위를 함께 확인해야 한다.

생성 과정에서는 학습에서 제외한 전멸 로그에 대해 [참조 접두부 정렬 검사](generation.md#미처치-로그의-참조-검사)를 근거에 기록한다. 이 분석용 대응은 `compare`의 runtime 재생과 별개다. FFLogs를 ACT 신호로 변환하거나 KDL 실행 조건의 관측을 합성하지 않는다.

dungeon·alliance 생성기의 보스 시도 선택과 처치 경계도 분석용이다. 관측된 보스 진입부터 독립 정렬 검사를 수행하고 실제 보스 처치 이후를 오른쪽 검열로 검사하지만, `compare`에 처치·전멸 신호를 자동 주입하지 않는다. Clyteum의 완료된 시도만 cast→Ability로 투영한 재생은 실패한 시도의 재시작이나 ACT 동등성을 검증하지 않는다. 종료 신호가 없는 KDL의 처치 후 불필요한 표시는 [감사 결과](../../../../docs/clyteum-omission-audit.md)에 별도 집계한다.

자동 생성 loop의 별도 개발 검증은 `bun scripts/replay_dungeon_loops.ts FIT.evidence.json OBSERVED.evidence.json target/debug/btimeline REPORT.json`으로 재현한다. 입력·KDL 해시와 관측 구조가 같은지 확인하고 원본 시도를 각각 cast→Ability로 투영해 실제 `compare`를 실행한다. 학습에서 빠진 trace는 holdout으로 표시한다. 이 도구는 각 원본 멤버에 가장 가까운 같은 신호의 표시를 측정하며 일대일 경로 대응 검사는 아니다. 구조 검증·원본 커버리지 감사와 함께 해석하며, 시도들을 분리한 결과를 보스 처치 취소·전멸·재시작의 검증으로 취급하지 않는다. [던전 반복 검증](../../../../docs/dungeon-loop-validation.md)에 별도 결과를 기록한다.

이 비교에는 관측 코퍼스의 helper 표시 후보도 포함한다. `associated_helper_members`로 별도 집계하며, 학습 KDL이 해당 예고를 만들지 않으면 예측 없음으로 남긴다. helper를 실행용 sync로 채택하거나 원본 미분류를 해제하지 않는다. [helper 표시 검증](../../../../docs/helper-display-validation.md)에 본체·보조 발동의 보류 재생과 한계를 기록한다.

자동 생성한 유한 블록 이력도 진입 신호만 둔 기록에서 후속 예고를 평가한다. [블록 이력 검증](../../../../docs/block-history-validation.md)은 알려진 경로의 보류 pull과 별도 보고서, 미학습 순서를 구분한다. 일치하는 phase 진입이 없을 때 `compare`에 진단이 없더라도 원본 대응·예고가 빠질 수 있으므로 실행 오류 수만으로 전체 경로를 통과시키지 않는다.

발생 그래프의 미분류 NPC 시전도 이 개발 투영에는 포함한다. 이름이 없는 경우 source 필드를 생략해 관측을 유지하며 가짜 이름이나 null 문자열을 만들지 않는다. 보고서의 `unclassified_casts`·`unnamed_sources`로 범위를 기록한다. 이 관측들의 미래 예측 커버리지나 모든 sync 경쟁이 검증됐다는 뜻은 아니다. 현재 학습된 loop 멤버의 최근접 표시 측정과 별개다.

| 구분                       | 현재 처리                                                                                                                                                                                                                                                 |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시작·전멸·종료·보스 처치   | 수명주기 우선순위에 따라 초기화·대기·재시작한다. 재시작마다 run 번호가 증가한다.                                                                                                                                                                          |
| phase 진입                 | 유휴 enter를 무시하고, start와 첫 enter의 같은 관측을 허용한다. from과 이전 phase의 window로 전환을 평가한다.                                                                                                                                             |
| 이벤트                     | 예정 시각에 기록한다. hidden·표시 지속시간도 기록하되 UI는 구현하지 않는다. 전환과 같은 시각의 이전 phase 이벤트는 취소된다.                                                                                                                              |
| sync                       | 보정 전 window를 검사한다. 앞으로 보정해 건너뛴 이벤트를 skipped로 기록하고 뒤로 보정해도 중복 실행하지 않는다.                                                                                                                                           |
| 모호한 대응                | 여러 phase 목적지 또는 서로 다른 sync 목적지가 일치하면 ambiguous로 기록한다.                                                                                                                                                                             |
| 전멸·관측 종료             | 활성 구간의 미처리 미래 이벤트는 각 전투 시도와 시각을 함께 unobserved로 기록한다.                                                                                                                                                                        |
| branch·merge 재생          | phase 직속 branch의 선택, 선행 선택, 합류와 공유 phase 시계 보정을 처리한다. 충돌은 ambiguous, 선택 창이 닫힌 미선택은 unresolved로 기록한다.                                                                                                             |
| loop 재생                  | phase 또는 선택된 option의 loop를 재생한다. 시작 전 탈출 감시와 본문 실행을 구분하고, 두 번째 본문 시작은 violation으로 기록하며 차단한다. 하나의 관측에 여러 탈출이나 선택·탈출이 일치하면 ambiguous로 기록한다. 각 회차의 sync와 phase sync를 처리한다. |
| loop 안 branch             | phase나 option의 loop 안에서 각 회차의 선택·합류와 선택 이력을 재생한다. 다른 loop 및 phase branch와 함께 사용할 수 있고 phase·회차·option·merge sync도 처리한다.                                                                                         |
| 로그 타입·필드 목록        | 아직 고정하지 않았다. 타입·필드 이름의 게임상 유효성은 검사하지 않으며 문자열 조건의 구조와 매칭만 확인한다.                                                                                                                                              |
| 정적 충돌·동적 제약        | 같은 branch에서 선행 선택 조건이 동일한 option의 리터럴 신호가 겹치면 오류로 검사한다. 정규식이나 서로 다른 선행 조건을 포함한 겹침과 동시 반복은 해당 기록을 재생할 때 확인한다. validate가 전체 계약이나 모든 실행 경로를 보장하지 않는다.              |
| 누락 신호·실제 게임 정확성 | 아직 판정하지 않는다. 재생 기록 자체가 누락 없는 모델이나 실제 게임 동작의 증거는 아니다.                                                                                                                                                                 |

정규식은 regress의 ECMAScript 문법을 사용한다. 문자열 필드 전체에 일치하며 플래그는 기본값(대소문자 구분, multiline 비활성)이다. `/패턴/플래그` 형식이 아닌 패턴 문자열을 입력한다. 비캡처 그룹으로 감싸므로 역참조 번호를 바꾸지 않으며, 부분 일치나 마지막 개행 앞에서만 끝나는 일치는 인정하지 않는다. 예를 들어 KDL의 `regex "source" #"(Boss)\1"#`는 `BossBoss` 전체에 일치한다. 지원하지 않는 패턴은 오류로 보고한다.

반복 재생은 과도한 출력과 계산을 막기 위해 전체 기록 길이를 반복 주기로 나눈 값이 100만을 초과하면 오류로 거부한다. 반복 안 branch는 이 값과 branch 수를 곱한 값도 100만을 초과할 수 없다. 실제 반복이 더 일찍 끝날 수 있어도 이 보수적인 제한이 적용된다. 보정으로 건너뛰는 회차 또는 이벤트와 branch 보고의 합이 100만을 초과할 때도 오류로 거부한다.

아직 시작하지 않은 loop의 시작점을 phase sync로 지나치면 지난 회차와 현재 회차의 지난 이벤트를 `skipped`로 기록한 뒤 보정된 회차부터 실행한다. 시작점을 지나치지 않는 보정은 대기 중인 loop의 시작 시각을 옮기며, 이미 시작한 회차는 phase 보정으로 옮기지 않는다.

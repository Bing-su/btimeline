# 전투 종료까지 반복하는 보스 기믹

2026-10-15 검증 기록. `generate`와 `prepare`에서 기존 도입부를 보존하고, 관측된 보스 후반 반복을 `label`과 `forcejump`로 출력한다. 던전·연합 레이드의 보스별 반복과 단일 레이드 반복을 같은 경로로 처리한다.

| 조건                                                                                      | 처리                                          |
| ----------------------------------------------------------------------------------------- | --------------------------------------------- |
| 한 주기 이후의 부분 회차에서 시작 행과 후속 두 행이 재현되고, 적어도 두 보고서에서 관측됨 | 간격·문맥·원본 재생까지 통과한 후보만 압축    |
| 기존 ID 대안 배열, 역할, 시전 시작/완료 대응, 시전자 targetability가 다름                 | 후보 거부 또는 기존 대안 배열 보존            |
| 반복 본문에 분기·비활성 sync가 있음                                                       | 유한 행 보존                                  |
| 보스 처치·전멸이 회차 중간에 발생                                                         | 이후 기믹을 미관측으로 처리하고 반복 정지     |
| 검증 로그가 학습 로그보다 더 많은 회차를 포함함                                           | 원본 시전 순서에서 각 회차의 근거를 다시 구성 |
| 재시도가 포함된 던전의 마지막 보스 시도가 더 긴 기믹 순서를 제공함                        | 입력 선택에서 보존                            |

원본 유한 타임라인·보고서는 `repeats.finiteYaml`과 `repeats.finiteEvidence`, 행 대응은 `slotMapping`, 반복 구조는 `loops`에 남긴다. 시전 원본 패킷과 동시 발동 근거도 유지한다. 내부 예고 검사는 예정된 `forcejump`를 따라 다음 회차를 탐색한다.

추가 던전의 보스 구간 fixture는 `out/loop-boss-fixtures/`에 있다. 이벤트 내용과 타임스탬프를 보존하고 보스 관측 구간으로 전투 범위만 제한했다. 출처 경로·원본 SHA-256은 각 fixture의 `collection.derivedFrom`과 `out/loop-boss-fixtures/manifest.json`에 기록했다. 보스 도달 전 종료된 Mistwake 로그 1개는 구간 fixture에서 제외했다. 같은 보고서의 전투는 학습과 검증으로 나누지 않았다.

기존 감사 도구 기준으로 Clyteum 업로드 3개의 중복 후보가 발견되었으며 모두 학습 쪽이다. 분할을 넘는 중복 후보는 0개다. 입력 파일 수나 `supportingReports`의 업로드 보고서 수를 독립적인 클리어 횟수로 해석하면 안 된다. 결과는 `out/unbounded-final/duplicate-upload-audit.json`에 기록했다.

커버리지는 `scripts/evaluate_quality.ts`의 `auditCoverage`로 원본을 다시 계산하고, 선언된 표현 index가 실제 출력 행의 sample에도 남아 있는지 별도로 확인한다. 초기 시도의 원본은 재생하지만 위 학습 커버리지 분모는 선택된 마지막 시도다.

검증 로그의 전체 커버리지를 통과했다고 주장하지 않는다. Clyteum 별도 검증 보고서에는 일반 몹 시전 500개와 `Launch` 33개가 미표현으로 남는다. 추가 던전 보스 구간의 별도 검증에는 61개 시전이 미표현이다. 선택된 sync의 재생·엔진 검사가 통과하는 것과 모든 원본 기믹을 예측하는 것은 별도의 검사다.

추가 던전 전체 입력의 생성도 비교했다. 다음 오류는 변경 전 바이너리와 변경 후 바이너리에서 동일하게 발생한다. 보스 구간 검증을 던전 전체 생성 성공으로 해석하면 안 된다.

## 재현

```sh
target/release/btimeline prepare logs/clyteum --mode dungeon --convert \
  -o out/recheck-clyteum.yaml
target/release/btimeline replay out/recheck-clyteum.yaml out/clyteum-loop-holdout \
  -o out/recheck-clyteum-holdout.replay.json
bun scripts/verify_phase_schedule.ts out/recheck-clyteum.yaml \
  /home/ks2515/workspace/cactbot out/recheck-clyteum-holdout.replay.json
```

검증 산출물과 해시는 `out/unbounded-final/validation.json` 및 같은 디렉터리에 보존했다. `out/clyteum.*`는 검증된 결과로 갱신했고 이전 파일은 `out/before-unbounded/`에 백업했다. Rust 단위 테스트 390개와 CLI 테스트 4개, Clippy 경고 금지 검사, Rust 포맷·diff 검사를 통과했다. 회귀 테스트에는 보스 3개의 독립 반복, 단일 레이드, 더 긴 검증 회차, 짧은 처치, 시전자·targetability 변경, 회차 중간 누락, 동시 패킷 순서 반전, 단일 보고서의 불충분한 근거, 경계 너머 예고를 포함한다.

## 초기 Chort 보완 재검증 — 아래 36.6초 추정은 폐기됨

위 초기 검증 이후, 다음 회차 본문 두 행을 요구하던 조건을 시작 행과 후속 행 한 개로 조정했다. Chort처럼 시전과 약 750ms 뒤의 효과까지만 남은 경우도 후보가 된다. 시작 행만 재등장하거나 후속 행의 ID·간격이 다르면 채택하지 않는다. 모든 관측 시전의 순서·문맥 및 원본 재생 검사는 유지한다.

`out/clyteum.txt`의 Chort는 8150.3초에 `boss-1-loop`를 두고, 8187.0초의 `Ripples of Gloom`에서 되돌아간다. 실제 관측된 반환 시전은 8186.8초이며 예정된 타이머 점프는 그보다 늦게 둔다. 시전 행은 121개에서 120개로 줄고, 보스 세 구간 모두 반복을 갖는다.

| 재검증 범위                                      | 결과                                                                      |
| ------------------------------------------------ | ------------------------------------------------------------------------- |
| Clyteum 학습 21개 + 기존에 추가 수집한 검증 27개 | 원본 재생·실제 cactbot 엔진의 누락/예상 밖 sync 0                         |
| 선택된 Clyteum 학습 시전                         | 3,646개 중 3,632개 표현, 14개 명시적 제외, 설명되지 않은 누락 0           |
| 다른 던전 3종의 보스 구간 학습 19개              | 유한 출력 유지, 선택된 학습 시전 499/499 표현, cactbot sync 오류 0        |
| Meso Terminal·Mistwake 별도 보스 구간 6개        | 원본 재생·cactbot sync 오류 0                                             |
| Alexandria 별도 보스 구간 1개                    | 원본 재생 missing 1. 변경 전 바이너리와 텍스트 출력 및 재생 요약이 동일함 |
| Rust 검사                                        | 단위 테스트 394개·CLI 테스트 4개, Clippy 경고 금지, 포맷·diff 검사 통과   |

Chort의 다음 회차를 지지하는 보고서 3개는 앞서 확인한 같은 전투의 중복 업로드 후보다. 독립 전투 3개가 아니며, 추가 검증 로그에도 Chort의 더 긴 반복 본문은 없다. 긴 반복은 합성 검증 로그에서 네 회차까지 재생했다. 따라서 미관측 후속 기믹에 대한 외삽이라는 한계는 남는다.

보완 전 출력은 `out/chort-loop/before/`, 이번 생성·재생·엔진 결과와 커버리지는 `out/chort-loop/`에 둔다. 다른 던전의 이번 보스 구간은 `fixtures/`에 있고, 출처·해시는 `fixtures/manifest.json`에 기록했다. 이번 구간 추출은 첫 보스 전투 이벤트부터 사망까지이며, 위 초기 검증과 표본 경계·학습 분할이 달라 결과를 별도로 기록했다. 실제 ACT·게임 수신은 검증하지 않았다.

## 더 긴 로그로 재확인한 결과

새 전투 64개를 포함해 원본 68개를 다운로드하고 Chort 인스턴스 86개를 비교했다. 36.6초 점프는 실제 긴 전투와 모순된다. 서로 다른 날짜의 두 전투에서는 `BEF8`을 시작으로 같은 17행이 이어지고, 각각 71.150초·71.198초 뒤 다음 회차의 첫 8행이 재현된다. `Ripples of Gloom` 뒤의 `Bodyweight Exorcism` 연속 공격을 빠뜨린 것이 짧은 루프의 원인이다.

시작 시전과 그 효과만으로 후보를 채택하던 완화를 철회했다. 또한 긴 클리어 하나 때문에 두 번째 긴 재시도 관측을 제외하던 입력 선택을 고쳤다. 보스별로 긴 클리어 두 개가 이미 관측되었는지를 기준으로 중복 경로를 제외한다.

`out/clyteum.*`는 기존 21개와 새 긴 전투 두 개로 다시 생성했다. 처음에는 동일 시전자의 가까운 패킷을 시각 대신 역할·ID 순으로 정렬하여 Chort 본문에 가짜 `packetWave` 분기가 생겼다. 동일 이름의 본체·보조 개체는 실측 시각 순서를 유지하도록 고친 뒤, 분기 없이 약 71.2초·17행의 Chort 반복을 자동 출력한다. 새 Eye 표본의 후반 `Launch`는 반복 본문과 맞지 않아 Eye는 유한 행으로 남고, Chort와 Malphas 반복을 채택한다.

자세한 시각·원본·검증 범위는 [긴 Chort 로그 검증](chort-long-log-verification.md)에 기록했다. 긴 로그 조사 결과는 `out/chort-long/`, 가짜 분기 수정 결과와 보완 전 백업은 `out/chort-order/`에 있다.

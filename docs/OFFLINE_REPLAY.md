# 오프라인 타임라인 검증: 첫 구현

최종 타임라인 KDL의 구조 검사와 lifecycle·phase·event·sync·branch·loop 재생을 구현했다. `compare`는 정규화 관측 JSON과 이 도구가 수집한 FFLogs 전투 파일을 받는다. [첫 생성기](GENERATION.md)는 작성한 lifecycle과 기준점에서 공통 시전의 표시 일정을 생성하며 FFLogs/ACT 신호 변환은 구현하지 않는다.

| 명령                                                           | 현재 동작                                                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `btimeline validate timeline.kdl`                              | KDL 2 파싱, 노드·속성·타입, ID·참조·순환, window, 중첩 및 명확한 회차 범위를 검사한다. 미검사 범위를 함께 출력한다. |
| `btimeline compare timeline.kdl recording.json`                | 독립적인 관측 기록을 재생하고 사람이 읽는 실행 기록을 출력한다.                                                     |
| `btimeline compare timeline.kdl first.json second.json --json` | 각 기록을 독립적으로 재생하고 원본 밀리초를 보존하는 JSON을 출력한다. 결과에는 미검사 범위도 포함한다.              |

실행 예:

```sh
cargo run -- validate tests/fixtures/timeline/basic.kdl
cargo run -- compare tests/fixtures/timeline/basic.kdl tests/fixtures/timeline/basic.json
cargo run -- compare tests/fixtures/timeline/fflogs-native.kdl tests/fixtures/pull.json --json
```

## 입력 관측

```json
{
  "version": 1,
  "end_ms": 2000,
  "observations": [
    { "at_ms": 0, "type": "InCombat", "fields": { "inGameCombat": "1" } },
    { "at_ms": 1500, "type": "Ability", "fields": { "id": "A001", "source": "Boss" } }
  ]
}
```

| 필드             | 계약                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------- |
| `version`        | 현재 1만 허용한다.                                                                           |
| `end_ms`         | 관측 종료 시각. 상대 밀리초 정수이며 0 이상이다.                                             |
| `observations`   | 원본 시각순 배열. 시각이 같으면 배열 순서를 보존한다.                                        |
| `at_ms`          | 0 이상 end_ms 이하의 상대 밀리초 정수. 정렬되지 않은 입력은 오류이며 자동 재정렬하지 않는다. |
| `type`, `fields` | 로그 타입 이름과 문자열 필드 맵. 필드가 없으면 해당 조건은 일치하지 않는다.                  |

관측 시각은 밀리초를 보존하고, 타임라인의 예정 시각·window 비교는 정수 0.1초 단위로 처리한다. 현재 구현의 최대 입력 시각은 10조 밀리초이며 계산 범위를 위한 제한이다. 게임 전투 길이 제한을 의미하지 않는다.

동일한 원본 밀리초의 관측은 배열 순서대로 모두 처리한 뒤 그 시각의 예정 이벤트를 실행한다. 예를 들어 같은 시각의 무관한 로그 뒤에 전멸 신호가 오면 전멸이 해당 시각의 이벤트를 취소한다. 반올림 후에만 같은 0.1초가 된 관측은 묶지 않는다.

## 수집된 FFLogs 입력

수집 완료·페이지·전투 범위·액터 참조는 `inspect`와 같은 검증을 거친다. 이벤트의 시각이 배열 순서와 다르면 원본 인덱스를 보존하며 시각순으로 안정 정렬하고, 같은 시각의 원본 순서는 유지한다. 전투 시작 시각은 상대 밀리초를 계산하는 기준일 뿐이며 start·wipe·finish 신호를 자동으로 생성하지 않는다.

| FFLogs 원본           | 재생에서 사용하는 값                                                                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이벤트 타입 `cast` 등 | 독립적인 `FFLogs.cast` 등. ACT의 `Ability`·`StartsUsing`과 동일하다고 가정하지 않는다.                                                                          |
| `abilityGameID`       | 문자열 `raw.abilityGameID`와, 음이 아닌 경우 대문자 16진수 `id`. 이벤트 타입별 의미는 원본을 따른다.                                                            |
| 액터 참조             | masterData의 이름을 `source`·`target`으로 사용한다. `raw.sourceID`·`raw.targetID`는 보고서 내부 ID다. 이름의 언어와 번역 정확도는 별도 확인이 필요하다.         |
| 그 밖의 이벤트 필드   | `raw.필드명`으로 보존한다. 문자열은 그대로, 숫자·불리언·null 및 배열·객체는 JSON 텍스트로 표현한다.                                                             |
| 원본 위치             | 해당 관측이 직접 일으킨 start·phase·option·sync 등의 JSON 결과에 0부터 시작하는 `source_event_index`를 기록한다. 예정 이벤트 자체에는 인덱스를 추정하지 않는다. |

예를 들어 수집 파일의 `cast`, `abilityGameID: 46376`, `sourceID: 10`이 masterData에서 `Synthetic Boss`를 가리키면 `FFLogs.cast`, `id="B528"`, `source="Synthetic Boss"`로 매칭할 수 있다. FFLogs [공식 API 문서](https://www.fflogs.com/v2-api-docs/ff/report.doc.html)는 이벤트와 masterData를 별도로 제공한다. 이 매핑은 ACT 신호와의 동등성을 뜻하지 않는다.

실제 수집 파일로 확인한 범위와 입력 해시는 [FFLogs 입력 재생 확인](FFLOGS_REPLAY_VERIFICATION.md)에 기록한다.

## 결과와 한계

`compare`는 입력마다 상태, 관측 수와 시작된 전투 시도 수를 요약한다. JSON에서는 `summaries`에 입력 경로별로 `status`, `observations`, `started_runs`를 제공하며 실행 기록은 `recordings`에 유지한다.

| 상태              | 의미                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `replayed`        | 시작 조건이 일치해 재생했다. 검증 통과나 누락 없는 비교를 의미하지 않는다.                         |
| `not_started`     | 관측은 있지만 시작 조건이 일치하지 않았다. 관측 불가와 실제 시작 신호 누락은 아직 구별하지 않는다. |
| `no_observations` | 입력에 관측이 없어 비교하지 못했다.                                                                |

명령의 성공 종료는 입력 처리 완료를 뜻한다. 상태와 실행 기록, 미검사 범위를 함께 확인해야 한다.

| 구분                       | 현재 처리                                                                                                                                                                                                                                                         |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시작·전멸·종료·보스 처치   | 수명주기 우선순위에 따라 초기화·대기·재시작한다. 재시작마다 run 번호가 증가한다.                                                                                                                                                                                  |
| phase 진입                 | 유휴 enter를 무시하고, start와 첫 enter의 같은 관측을 허용한다. from과 이전 phase의 window로 전환을 평가한다.                                                                                                                                                     |
| 이벤트                     | 예정 시각에 기록한다. hidden·표시 지속시간도 기록하되 UI는 구현하지 않는다. 전환과 같은 시각의 이전 phase 이벤트는 취소된다.                                                                                                                                      |
| sync                       | 보정 전 window를 검사한다. 앞으로 보정해 건너뛴 이벤트를 skipped로 기록하고 뒤로 보정해도 중복 실행하지 않는다.                                                                                                                                                   |
| 모호한 대응                | 여러 phase 목적지 또는 서로 다른 sync 목적지가 일치하면 ambiguous로 기록한다.                                                                                                                                                                                     |
| 전멸·관측 종료             | 활성 구간의 미처리 미래 이벤트는 각 전투 시도와 시각을 함께 unobserved로 기록한다.                                                                                                                                                                                |
| branch·merge 재생          | phase 직속 branch의 선택, 선행 선택, 합류와 공유 phase 시계 보정을 처리한다. 충돌은 ambiguous, 선택 창이 닫힌 미선택은 unresolved로 기록한다.                                                                                                                     |
| loop 재생                  | phase 또는 선택된 option의 loop를 재생한다. 시작 전 탈출 감시와 본문 실행을 구분하고, 두 번째 본문 시작은 violation으로 기록하며 차단한다. 하나의 관측에 여러 탈출이나 선택·탈출이 일치하면 ambiguous로 기록한다. 각 회차의 sync와 phase·on-exit sync를 처리한다. |
| loop 안 branch             | phase나 option의 loop 안에서 각 회차의 선택·합류와 선택 이력을 재생한다. 다른 loop 및 phase branch와 함께 사용할 수 있고 phase·회차·option·merge·on-exit sync도 처리한다.                                                                                         |
| 로그 타입·필드 목록        | 아직 고정하지 않았다. 타입·필드 이름의 게임상 유효성은 검사하지 않으며 문자열 조건의 구조와 매칭만 확인한다.                                                                                                                                                      |
| 정적 충돌·동적 제약        | 같은 branch에서 선행 선택 조건이 동일한 option의 리터럴 신호가 겹치면 오류로 검사한다. 정규식이나 서로 다른 선행 조건을 포함한 겹침과 동시 반복은 해당 기록을 재생할 때 확인한다. validate가 전체 계약이나 모든 실행 경로를 보장하지 않는다.                      |
| 누락 신호·실제 게임 정확성 | 아직 판정하지 않는다. 재생 기록 자체가 누락 없는 모델이나 실제 게임 동작의 증거는 아니다.                                                                                                                                                                         |

정규식은 regress의 ECMAScript 문법을 사용한다. 문자열 필드 전체에 일치하며 플래그는 기본값(대소문자 구분, multiline 비활성)이다. `/패턴/플래그` 형식이 아닌 패턴 문자열을 입력한다. 비캡처 그룹으로 감싸므로 역참조 번호를 바꾸지 않으며, 부분 일치나 마지막 개행 앞에서만 끝나는 일치는 인정하지 않는다. 예를 들어 KDL의 `regex "source" #"(Boss)\1"#`는 `BossBoss` 전체에 일치한다. 지원하지 않는 패턴은 오류로 보고한다.

반복 재생은 과도한 출력과 계산을 막기 위해 전체 기록 길이를 반복 주기로 나눈 값이 100만을 초과하면 오류로 거부한다. 반복 안 branch는 이 값과 branch 수를 곱한 값도 100만을 초과할 수 없다. 실제 반복이 더 일찍 끝날 수 있어도 이 보수적인 제한이 적용된다. 보정으로 건너뛰는 회차 또는 이벤트와 branch 보고의 합이 100만을 초과할 때도 오류로 거부한다.

아직 시작하지 않은 loop의 시작점을 phase sync로 지나치면 지난 회차와 현재 회차의 지난 이벤트를 `skipped`로 기록한 뒤 보정된 회차부터 실행한다. 시작점을 지나치지 않는 보정은 대기 중인 loop의 시작 시각을 옮기며, 이미 시작한 회차는 phase 보정으로 옮기지 않는다.

# 타임라인 재설계 계획

## 목표와 범위

FFLogs에서 사람이 검토하고 편집할 수 있는 실행 가능한 타임라인을 만든다. 실제 전투에 연결하는 실시간 실행기는 외부에서 구현하며, 이 저장소에는 최종 KDL을 검증할 오프라인 재생기를 둔다. 외부 실행기가 별도 evidence 없이 최종 KDL 하나로 실행할 수 있도록 설계한다. 번역은 별도 제공한다. cactbot의 신호와 사례는 참고하지만 cactbot 타임라인 파일과의 호환은 목표가 아니다. 기존 v2 KDL, evidence, JSON 및 CLI 계약과의 호환성은 유지하지 않는다. 현재 FFLogs 수집·입력 검사와 직접 후속 그래프 분석, 새 KDL의 구조 검사 및 lifecycle·phase·event·sync·phase 직속 branch와 제한적인 loop 재생의 첫 구현이 있다. 자동 타임라인 생성과 반복 재생의 나머지 조합은 남아 있다. 작성용 KDL의 초안 계약은 [타임라인 스키마](TIMELINE_SCHEMA.md)에 정의하고, 현재 사용법과 한계는 [오프라인 재생 안내](OFFLINE_REPLAY.md)에 정리한다.

| R11S 문제                               | 목표                                                                  |
| --------------------------------------- | --------------------------------------------------------------------- |
| 풀마다 전체 전투가 별도 브랜치로 출력됨 | 공통 진행을 공유하고 실제로 갈라지는 구간만 브랜치로 표현             |
| 전투 시작·재시작 신호가 없음            | 시작, 종료, 리셋과 재시작의 실행 의미를 명시                          |
| 페이즈 구분이 없음                      | 근거가 있는 전환 신호와 페이즈를 연결하고 불확실한 경계는 후보로 표시 |
| source가 숫자 ID임                      | NPC 이름으로 매칭하고 원본 ID는 evidence에 보존                       |
| 이벤트가 능력 ID에 제한됨               | cactbot이 지원하는 로그 타입과 필드 조건을 표현                       |

구현 우선순위는 원본 관측 보존 → 발생 후보·부분 순서 정리 → 진행 그래프 구성 → 사용하기에 충분한 시간 추정 → 최종 KDL 생성 → 독립 로그 검증이다. 진행 구조와 예정 시각 추정을 분리한다. 시간은 정확히 재현할 필요가 없으며 기믹 순서·선택·회차를 파악할 수 있는 실용적인 일정이면 된다. 0.1초는 출력 단위이지 정확도 보장이 아니다. 상세 책임·이행 순서·완료 조건은 [진행 그래프와 시간 추정의 분리 계획](PROGRESSION_AND_TIMING.md)에 정의한다.

시간 차이가 수 초·수십 초라는 이유만으로 구조 대응을 제외하지 않는다. 그래프의 진행 위치와 선택·회차를 먼저 식별하고 시간표를 초기 예상 일정으로 사용한다. 큰 시계 보정과 가상 구간 jump를 구분하며, 모호함은 가능한 대응에 따라 사용·실행 결과가 달라지는지를 기준으로 평가한다. 고유 시각 기준점·경계·묶음 대응 때문에 관측된 구조까지 버렸던 문제와 선택 이력 미반영을 각각 개선·검증한다.

## 1. 신호와 런타임 근거 조사

- [ ] ACT와 cactbot의 로그 타입·필드 및 실제 콘텐츠의 시작·리셋·페이즈 신호를 조사하고 근거 버전을 기록한다.
- [ ] FFLogs와 원본 로그의 관측 가능 범위 및 변환할 수 없는 필드를 구분한다.
- [ ] FFLogs 전용 관측과 외부 실행기가 실제로 받을 수 있는 신호를 구분한다. `FFLogs.*` 같은 내부 합성 신호를 실시간 실행 조건의 근거로 사용하지 않는다.
- [ ] cactbot의 타임라인 자료는 전투 관측의 참고 자료로 비교하고, 독자적 실행 의미를 억지로 cactbot 구문에 맞추지 않는다.
- [ ] 개발 스크립트는 Bun으로 실행하고 cactbot 공식 검증에 필요한 해당 체크아웃의 의존성을 명시한다.

완료 조건: 신호의 출처와 관측 가능·미지원 범위, 비교 방법이 명시돼야 한다.

## 2. 타임라인과 신호 계약

- [ ] 이벤트의 표시 시각·이름·지속시간·숨김과 여러 시점의 독립적인 동기화 조건을 구현한다.
- [ ] 이벤트마다 사람이 읽을 수 있는 문서 전체 고유 ID를 부여하고, 기존 문서 수정·재생성 시 ID와 반복 회차의 근거를 보존한다.
- [ ] 최종 타임라인 시간은 0.1초 단위로 표시하고 원본 관측의 밀리초와 반올림 근거는 evidence에 보존한다.
- [ ] 최소한 기준 cactbot에서 사용할 수 있는 모든 로그 타입과 필드, 필드별 복수 대안과 정규식을 표현한다. 리터럴과 정규식을 구분하고 지원되지 않는 신호는 명시한다.
- [ ] source는 영어 NPC 이름으로 매칭한다. 동일한 이름의 개체를 자동으로 구별했다고 가정하지 않으며, 언어별 동기화 조건과 표시 텍스트의 번역은 별도 리소스로 제공한다.
- [ ] 전투·phase·반복 회차 시계와 phase 진입 window, 페이즈 간 선택 유지, 명시적 합류와 반복 동기화를 구현한다. option·merge·on-exit은 별도 보정 시계 없이 상대 기준점으로 작성하고 가장 가까운 phase 또는 반복 회차의 보정을 공유한다. 근거는 [시계 조사](CACTBOT_CLOCK_RESEARCH.md)에 정리한다.
- [ ] 선택지별 무한 반복과 window 내 신호에 의한 탈출, lifecycle 상태 전이를 구현한다.
- [ ] KDL 생성기·파서·검증기와 로그 비교를 구현한다. 오프라인 재생기로 실행 의미를 검증하고 실시간 실행기는 구현하지 않는다. 관측과의 분석용 연결은 실행에 필요하지 않은 별도 evidence에 둔다.
- [ ] 실행기가 공유하는 시계·전환 의미와 문서 작성 제약을 구분한다. 정적으로 증명되는 조건 충돌은 오류로, 재생 중 드러나는 모호함은 `ambiguous`로 보고한다. 실제 전투를 표현하지 못하면 임의 신호로 채우지 않고 스키마 한계로 기록한다.
- [ ] 작성 구조를 제한한다. branch는 phase·loop 바로 아래에 두고, loop는 간접 중첩도 금지하며 merge·on-exit의 실행 본문은 event로 한정한다. requires의 잘못된 참조·자기 참조·순환 참조는 정적으로 검사하고 선행 실행 결과의 존재는 재생에서 확인한다. 미래 선택 대기·소급 적용은 허용하지 않는다.
- [ ] 같은 phase에서 본문 실행 중인 loop는 최대 하나로 제한하며 시작 전 탈출 감시는 제외한다. 반복 안 merge에는 유한한 window를 요구하고 명확한 회차 범위 초과를 정적으로 검사한다. 관측에 의존하는 위반은 재생에서 검사하며, 모든 실행 경로의 증명을 요구하지 않는다. 넓은 window는 전체 선택 조건이 구별되면 허용한다.
- [ ] 원본 시간순 관측 처리와 0.1초 window 비교를 구분한다. 한 관측의 경쟁 동작, 유휴 상태의 enter 차단, start와 첫 enter의 동시 성립, branch 선택 종료 후 재개 금지를 공통 실행 규칙으로 구현한다.

완료 조건: KDL 하나에 시간·신호·상태 전이를 표현하고 생성·검증 및 오프라인 재생과 로그 비교 테스트를 통과한다. 외부 실행기의 실제 동작 검증은 별도로 보고한다.

### 오프라인 재생 검증

- [ ] 최종 KDL과 시각이 있는 기록 신호를 입력받아 가상 시계로 재생하고, 예정 이벤트·관측된 신호·시계 보정·상태 전이와 그 결과를 확인한다. 실행에 evidence는 요구하지 않는다.
- [ ] 시작·전멸·재시작, phase 전환, 선택·합류, 반복과 탈출, 시계 보정 및 window 경계를 작은 합성 사례로 검증한다. 같은 신호가 여러 제어 조건에 일치하는 경우와 0.1초 반올림 경계도 포함한다.
- [ ] 조사한 분기·합류·탈출 사례를 공유 시간축으로 재생한다. 기준점을 중복 보정하지 않는지, 후속 sync가 같은 phase의 이벤트와 window를 함께 옮기는지, 반복 보정은 부모로 소급 전파되지 않는지 확인한다. 이 마지막 범위 규칙은 cactbot 소스만으로 검증된 것으로 취급하지 않는다.
- [ ] 정적 구조·범위 오류, 특정 재생에서 발견한 제약 위반, 미검사 조건을 구분한다. 일부 로그의 통과를 모든 경로의 보장으로 표시하지 않는다. 감시 중인 loop와 본문 실행 중인 loop를 구분하고 두 번째 본문 시작 시 위반을 보고한다.
- [ ] 재생이 시작되어 비교가 이루어진 경우와 시작 신호를 관찰하지 못했거나 비교 가능한 신호가 없는 경우를 구분한다. 빈 재생 결과를 검증 성공으로 취급하지 않는다.
- [ ] 실제 독립 로그를 재생해 `unobserved`, `unobservable`, `ambiguous`, `unresolved`, `mismatch`를 구분하고 원본 관측에 연결한다. FFLogs에 없는 신호는 불일치로 단정하지 않는다.
- [ ] 사람이 사용하는 `validate`와 `compare` 흐름에서 결과를 확인할 수 있게 한다. 별도 재생 명령은 필요성이 확인될 때만 추가한다.

완료 조건: 합성 사례와 독립 로그에 대해 재현 가능한 결과를 제공하고 미관측·미지원과 실제 불일치를 구분한다. 오프라인 재생 통과를 실제 게임·ACT 또는 외부 실행기의 호환성 검증으로 간주하지 않는다.

## 3. 관측과 evidence

- [ ] 원본 관측, 정규화된 발생 후보, 타임라인을 분리한다. 대상별 중복, 동시 시전자, 별도 파동을 구분한다.
- [x] 시전뿐 아니라 상태 이상·징표·연결 등 수집된 이벤트와 추가 필드를 분석 그래프의 원본 인덱스·시각·액터 이름에 연결해 보존한다.
- [ ] 보존한 시전 외 관측에서도 활동 후보를 찾고 최종 타임라인에는 근거와 목적이 있는 신호만 선택한다.
- [x] 적대 액터가 관여한 상태 변화와 징표·연결에서 활동 후보를 찾는다. 능력·징표·연결의 식별자 영역을 구분하고 파티원 이름은 활동 키에서 제외한다. 최종 실행 신호와의 대응은 별도로 검증한다.
- [x] 원본 로그 언어가 다르다는 이유만으로 같은 전투의 입력을 배제하지 않고, 원본 언어를 각 trace의 근거로 보존한다.
- [ ] 최종 출력의 영어 NPC·기술 이름을 확인해 정규화한다.
- [ ] 후보에 원본 파일 해시, 이벤트 인덱스, 묶은 이유와 불확실성을 기록한다. 게임 ID와 보고서별 actor ID도 추적용으로 보존한다.
- [ ] FFLogs 관측과 ACT 신호의 대응은 검증된 범위만 사용한다. 관측할 수 없는 신호는 수동 작성·출력할 수 있게 하고 비교에서는 관측 불가로 보고한다.

완료 조건: 원본으로 추적할 수 있고 다중 대상, 동시 시전자, 반복 파동과 누락 관측을 잘못 합치지 않는다.

## 4. 공통 진행과 브랜치

일반 난이도·던전 보스의 후반 반복을 유한 추가 이벤트만으로 다루지 않는다. [일반 던전 반복 검증](DUNGEON_LOOP_VALIDATION.md)은 cactbot 9개 보스·32개 입력을 다룬다. Chirurgeon General과 Thundergust Griffin에 본체 이름의 무한 loop를 생성하며 Griffin의 다른 이름 helper 누락과 나머지 7개 보스는 미완료다. 원본 발생 문맥에서 반복·대안을 먼저 학습하고 시간은 뒤에 추정한다. cactbot은 검증 oracle이며 생성기 입력이나 전투별 규칙으로 사용하지 않는다.

다음 구현은 [진행 그래프와 시간 추정의 분리 계획](PROGRESSION_AND_TIMING.md)을 우선한다. [기법 보완안](PROCESS_MINING_TECHNIQUES.md#누락-감사-이후의-우선순위)의 파동·부분 순서·선택 이력 분석을 아래 단계에 배치한다. trace별 발생·부분 순서 보존과 출력 노드 참조를 받는 시간 추정기를 먼저 분리했다. trace 간 조건부 진행 학습은 기존 분석에 남아 있으며, 시간 기준점의 부재나 추정 실패만으로 구조 후보를 제거하지 않는다.

| 4    | 고정된 그래프에 실용적인 시간 추정        | 경로별 근사 시각·변동·근거를 추정. 시간 조정으로 구조·ID를 바꾸지 않고 추정 불가 노드도 유지 |
| 5    | 그래프와 시간 추정 결과에서 KDL 생성      | 기존 문법·시계·mode·CLI·단독 실행 계약 유지. 표시와 sync 채택 기준 분리                      |
| 6    | 구조·시간·경로별 독립 검증                | 임시 학습에서 관측 대응부터 시간 추정까지 검증 입력 누출 방지. 구조·실용성·sync를 따로 평가  |

- [x] 인접 기준점 사이 표시용 정렬의 경계 근접을 허용하고 sync·분기·참조 검증과 분리한다.
- [x] 인접 기준점 사이에서 다른 trace의 단일 파동 지지·강제 묶음 대응·겹치지 않는 개체·100ms 범위를 확인해 분절 파동을 표시용으로 대응한다. 원본 분절과 최종 다중집합 정렬을 보존하고 독립 검증 입력의 누출 및 지원된 후반 일정 소실을 회귀 검사한다.
- [ ] 위 1–6단계로 진행 그래프와 시간 추정을 분리하고 다른 raid/dungeon 및 합성 변형에서 검증한다. 새 라이브러리·runtime 확률·수동 중간 파일·CLI 옵션은 선행 조건으로 요구하지 않는다.
- [x] trace별 시전 발생·부분 순서를 예정 시각 없이 보존하고 출력 후보의 노드 참조를 별도 시간 추정기로 전달한다. R11S·R9S·R10S·Clyteum의 기존 KDL 출력을 유지하며 반복 helper·원본 대응·부분 순서·큰 시간 차이의 회귀를 검사했다. trace 간 선택·반복의 통합은 후속 작업이다.
- [x] 발생 저장을 `petgraph::StableDiGraph`로 옮기고 삭제 후 참조 안정성·원본 표본 검증·도달 가능성·위상 정렬 회귀를 유지했다. 내부 노드 인덱스와 KDL 이벤트 ID는 구분한다.
- [x] dungeon·alliance의 첫 고유 기준점 이전을 해당 보스 자신의 첫 시전부터 복원한다. Clyteum 3개 입력에서 45→80개 정의를 생성하고 독립 KDL의 보스 진입·반복 신호 무시·보스별 시계를 합성 재생으로 확인했다. [감사](CLYTEUM_OMISSION_AUDIT.md)의 잔여 누락과 검증 범위는 별도다.
- [x] dungeon·alliance에서 본체 actor/instance와 관측된 처치로 학습할 보스 시도를 구분한다. 전체 입력과 원본 그래프는 보존하고 완료된 시도만 학습 뷰에 반영한다. 동시 개체를 재시도로 확정하지 않고 불명확한 종료·여러 완료 시도는 보류한다.
- [x] 고유 시전이 없어도 동일한 단일 보스 진입과 그 뒤의 모든 최적 정렬에서 강제되는 발생을 표시한다. Clyteum 21개 전체 입력에서 3개 보스·80개 정의를 생성하고, 기존 3개 입력은 80→87개 정의로 개선했다. 표시와 sync 채택은 구분한다.
- [x] 처치가 관측된 보스의 진입부터 독립 검증을 수행하고 그 보스의 종료로 후반 검열을 판정한다. 반복 진입 ID의 후속 발생을 첫 발생으로 오인하지 않는 회귀를 검사한다.
- [ ] 보스 진입 자체의 대안·부분 순서·선택 이력과 더 긴 반복 경로를 통합한다. Clyteum 완료 시도의 파동 후보 2,094개 중 현재 1,264개가 출력에 대응하며 이 수를 기믹 개수로 해석하지 않는다.
- [ ] 실제 관측 가능한 보스 처치 신호의 생성 정책과 실패한 보스 시도의 재시작·전체 재생을 구현한다. Clyteum 완료 시도 합성 재생의 처치 후 표시 189건을 해결하고 FFLogs 종료를 runtime 신호로 합성해 우회하지 않는다.

- [ ] 정규화된 풀을 정렬해 공통 진행과 국소적인 분기·합류 후보를 찾는다. 여러 풀에 나타난 같은 선택지는 공유한다.
- [x] 순서가 뒤바뀐 고유 시전에서 모든 최장 공통 순서 사슬의 공유 기준점을 추출한다. raid의 한 국소 순서 분기를 선택 신호·옵션별 본문·공통 후속 일정으로 생성하고, 다른 구간의 상관 선택은 독립 분기로 추정하지 않는다. R11S 도입부 순서 교환과 선택 누락·전멸 후 재선택을 확인한다.
- [ ] 후속 분기의 선택 이력과 `requires`, 가변 시각의 명시적 `merge`, dungeon·alliance의 국소 분기와 자동 검증의 분기 경로 평가를 구현한다.
- [x] 둘 이상의 완료 로그에서 단일 발생의 공통 기준점 후보와 전투별 시각 근거를 추출한다. 일치하는 선후 관계를 공통 진행 그래프로 출력하고 반복·미관측 회차는 임의로 대응시키지 않는다.
- [x] 같은 NPC의 인접 고유 기준점 사이에 삽입·삭제 정렬을 적용한다. 모든 최적 대응에서 강제되는 반복 시전을 표시 event로 생성하고, 동률·근접 관측·페이즈 경계·계산 제한·구간 밖 미대응 발생은 근거에 남긴다. 발생 순번을 반복 회차로 확정하거나 반복 신호에 자동 sync를 추가하지 않는다.
- [x] 100ms 이내 연속 관측을 순서 미확정 다중집합으로 정렬한다. 동일 구성·개수의 묶음 대응이 모든 최적 정렬에서 강제될 때만 내부 단일 발생을 생성하고 원본 시각·구성 관측을 보존한다. 이를 동시 실행이나 독립성으로 확정하지 않는다.
- [ ] 불확실성 묶음의 부분 대응·부분 순서 활용, 구간 양끝 밖의 발생과 wipe 접두부 평가를 확장하고 독립 로그에서 대응 품질을 검증한다.
- [x] 미처치 로그를 고유 기준점 이후의 참조 접두부에 대응시킨다. 미관측 뒷부분은 무료 종료로, 내부 삽입·삭제는 비용으로 처리하고 모든 최적 대응·종료 위치를 보존한다. 후반 학습에 사용한 trace는 `training=true`로 구별한다. 생성 이벤트에 해당하는 대응·모호함·차이·미해결을 근거에 기록하며 종료 전 침묵 구간을 정상 미관측으로 숨기지 않는다.
- [x] 입력 완료 로그가 3개 이상이면 검증용 한 개를 결정적으로 자동 선택한다. 그 로그를 제외한 임시 모델로 평가하고 최종 KDL은 전체 입력에서 허용되는 완료·후반 표본으로 생성한다. 선택 정책·분할·임시 모델·검사 결과와 자료 부족·학습 실패를 근거에 기록한다. 별도 holdout CLI 입력은 요구하지 않으며 최종 KDL의 독립 검증으로 과장하지 않는다.
- [x] 정확히 같은 밀리초의 동일 이름·능력 시전을 표시 파동으로 집계하고 원본 복수 개체 수를 보존한다. 서로 다른 밀리초의 반복은 합치지 않는다.
- [x] NPC별 마지막 공통 기준점 뒤를 종료 검열 접두부 정렬로 학습한다. 최소 두 trace의 강제 대응과 나머지 유효 trace의 종료 시각을 검사한다. raid의 긴 미처치 로그도 사용하며, 후반 이벤트에는 자동 sync를 추가하지 않는다.
- [x] 전체 순서가 다르더라도 모든 완료 로그에서 일치하는 부분 선후 관계는 보존한다. 전이적으로 중복되는 간선을 제거하고 순서가 미확정인 후보를 독립 실행·기믹 분기로 확정하지 않는다.
- [x] 동시 신호 집합을 개별 활동으로 분리해 공통 신호의 동일성을 보존한다. 같은 시각의 신호 사이에는 간선을 만들지 않고 동시 관측의 원본 인덱스를 보존한다.
- [ ] 밀리초 단위 기록 차이로 달라지는 인접 관계를 분석해 허위 분기를 방지한다. 활동의 동일성 보존만으로 시간 노이즈를 해결했다고 간주하지 않는다.
- [x] 공통 기준점 간 관계에 100ms 분석 해상도를 명시적으로 적용한다. 근접 시각을 임의로 동시성 묶음으로 만들지 않고 원본 밀리초·통계를 유지한다. 반복·분기 생성에서의 시간 노이즈 검증은 별도로 수행한다.
- [ ] 공통 신호로 합류할 수 있으며 페이즈 간 상관된 선택을 보존한다. 실제 사례를 비교해 신호 없는 option 완료 기준 합류와 `requires`가 필요한지 확인한다.
- [ ] [일반 토벌전 반복 조사](CACTBOT_NORMAL_TRIAL_LOOPS.md)를 참고해 선택지별 반복과 반복 진입 전 전환을 표현한다.
- [x] cactbot에 타임라인이 있는 Alexandria·Mistwake·Meso Terminal의 반복 경계와 본문을 조사하고 순서 감사·독립 KDL 실행기 fixture를 추가했다. Chirurgeon General의 세 기록에서 본문과 다음 경계를 확인했으며 다른 8개 보스의 정확한 본문 대응은 미완료다.
- [x] dungeon·alliance의 말단 반복 첫 구현: 원본 시도별 opener·본문·다음 prefix를 대응하고 관측된 순서 교환 블록을 보존한다. 별도 회차 시간 추정과 sync로 무한 loop를 생성하며, 원본 노드 대응·진입/본문 누락 거부·미래 회차 표시를 검사한다. 실제 던전 15개 범위와 보고서 전체 보류 2개 범위를 투영 재생했다. 자동 검증의 기존 참조 정렬과 loop 재생 검증은 구분한다.
- [x] 고유 회차 경계 안에서 같은 신호의 여러 발생을 순서대로 구분한다. Griffin의 21파동 반복을 생성하고, 서로 다른 보고서 집합 8개↔4개 입력을 양방향 보류해 원본 멤버 480개에 대한 예측을 검사했다. 최대 차이는 994ms다. cactbot 전체 본문 감사는 이름이 다른 helper 누락으로 미완료이며, 그 연결과 lifecycle을 다음 검증 대상으로 남긴다.
- [ ] 일반 던전 반복 검증 코퍼스에서 원본 그래프의 반복 본문·ID 대안·helper와 여러 회차 대응을 학습해 무한 loop를 생성한다. 유한 관측 횟수나 같은 ID의 재등장만으로 반복을 결정하지 않는다. 회차 보정·다음 회차 사전 표시·짧은 처치·경계 누락을 별도로 검증한다.
- [x] `enemyNPCs`에 없는 소유자 미보고 NPC의 cast·begincast를 미분류 후보로 보존하고 기존 실행 학습과 분리한다. Griffin의 Shock Storm 12개 시전을 그래프에 복원하고 원본 참조 본문 전체 8회와 출력 16/17 대응을 구분했다. 이름 누락은 null로 유지하며 기존 KDL·loop는 바꾸지 않는다.
- [ ] 미분류 후보를 반복 문맥과 보스 소속에 연결하고 runtime 신호 경쟁을 검증한다. Griffin의 Shock Storm을 우선 회귀 자료로 삼고 시간 근접도만으로 귀속시키지 않는다. 소유자가 있는 명단 밖 NPC와 미분류 시전 외 신호도 별도로 다룬다.
- [x] 각 로그에서 페이즈 경계를 넘지 않는 정확한 연속 반복 후보와 회차별 원본 시각·묶음 위치를 보존한다. 관측된 횟수를 무한 반복·탈출 조건으로 확정하지 않고 미완성 회차는 원본 근거로 남긴다.
- [ ] 조기 종료 이후는 미관측으로 취급한다. 누락, 패킷 순서, 사망에 따른 차이를 기믹 분기로 단정하지 않는다.
- [ ] 분기 신호나 합류 지점이 불명확하면 후보로 남긴다. 독립적이라는 증거 없이 미관측 경로 조합을 만들지 않는다.
- [ ] 학습에 사용하지 않은 풀에서 누락·잘못된 병합·브랜치 선택과 합류를 평가한다.

완료 조건: R11S의 풀별 전투 전체 복제가 사라지고 관측 근거와 미해결 항목을 확인할 수 있다. 파일 크기만으로 성공을 판정하지 않는다.

## 5. lifecycle과 페이즈

기준 cactbot 소스와 사례는 [생명주기 조사](CACTBOT_LIFECYCLE_RESEARCH.md)에 정리하고, 제안하는 정책과 신호 표현은 [타임라인 스키마](TIMELINE_SCHEMA.md#전투-수명주기)에 정의한다.

- [ ] 전투 시작, 종료, 전멸·리셋, 재시작의 동작과 분기·시계 상태 초기화를 정의한다. 던전의 보스 리셋과 구역 종료도 구분한다.
- [ ] FFLogs fight 경계와 ACT 실시간 신호의 근거를 분리한다. 하나를 다른 하나의 증거로 취급하지 않는다.
- [ ] FFLogs phase transitions, 대상 지정 가능 여부, 고유 시전 등에서 페이즈 경계 후보를 찾고 독립 관측으로 검토한다. 편집용 구분과 실제 시계 전환을 구분한다.
- [x] 수집한 FFLogs phase transitions를 검증 후 입력 검사 결과와 분석 그래프의 근거로 보존한다. 이를 실행 페이즈로 자동 확정하지 않는다.
- [ ] 시작 → 진행 → 리셋 → 재시작, 처치 종료, 페이즈 이동과 반복 진입을 KDL과 오프라인 신호 재생으로 검증한다. 외부 실행기를 사용할 수 있으면 그 동작도 별도로 확인한다.

## 6. 사람이 사용하기 쉬운 CLI

사용 흐름은 입력 확인 → 생성 → 검토 → 검증·비교로 정리한다. generate는 FFLogs JSON들과 mode만 받아 검사·프로세스 분석·그래프 구성·KDL 생성·구조 검증을 수행한다. 템플릿과 중간 파일을 요구하지 않으며 mine은 동일한 분석 결과를 확인하는 선택적 명령이다. compare는 정규화 관측 JSON과 수집 FFLogs 파일을 받되 원본 FFLogs 관측을 runtime 신호로 자동 변환하지 않는다. 현재 생성 범위와 mode 정책은 [생성 계약](GENERATION.md)에 정의하며 review는 아직 미구현이다.

| 작업        | 명령 초안                                                    |
| ----------- | ------------------------------------------------------------ |
| 입력 확인   | `btimeline inspect LOG...`                                   |
| 생성        | `btimeline generate LOG.json... --mode raid -o timeline.kdl` |
| 검토        | `btimeline review timeline.kdl`                              |
| 유효성 확인 | `btimeline validate timeline.kdl`                            |
| 로그 비교   | `btimeline compare timeline.kdl LOG...`                      |

- [ ] 기본 출력은 사람이 읽기 쉬운 요약과 다음 행동을 제공하고, 자동화용 JSON은 명시적으로 요청한다.
- [x] FFLogs JSON들을 직접 받는 generate와 raid·dungeon·alliance mode 정책을 구현한다. 시작·리셋·공통 시전·동기화와 별도 근거를 생성하고 중간 KDL을 입출력 경계로 사용하지 않는다.
- [x] dungeon·alliance는 적대 Boss 메타데이터와 공통 시전으로 보스별 phase·진입 조건을 생성한다. 잡몹을 제외하고 이동 시간과 시계를 분리하며 이후 보스의 전멸·재시작도 허용한다.
- [x] 생성 후 구조 검사와 KDL 단독 재생·동기화·전멸·구역 변경·재시작을 합성 사례로 검증한다. 실제 게임·ACT 실행 검증은 별도로 남긴다.
- [ ] 시전 외 이벤트·보스 내부 페이즈·분기·반복 생성, helper 소속·서로 다른 encounter 연결과 콘텐츠별 lifecycle 예외 처리를 이어 구현한다.
- [x] `inspect`의 기본 출력을 전투별 요약과 다음 분석 명령으로 제공하고 상세 관측·근거 JSON은 `--json`으로 요청한다. 모든 입력을 검사한 뒤 출력해 부분 결과를 방지한다.
- [ ] 사용자가 자주 결정하는 설정만 기본 옵션으로 노출한다. 오류는 문제와 수정 방법을 함께 표시한다.
- [ ] 기존 파일은 명시적 요청 없이 덮어쓰지 않는다. 상세 원본 근거는 필요할 때 확인할 수 있게 한다.
- [ ] 처음 사용하는 사람이 도움말만으로 생성·검토·출력 흐름을 수행할 수 있는지 확인한다.

## 7. R11S와 회귀 검증

긴 전투 자료 확보와 기존 후반 복원 실적은 [R11S 후반 복원 계획](R11S_TAIL_IMPROVEMENT.md)에 기록한다. 이후 구현 순서는 [진행 그래프와 시간 추정의 분리 계획](PROGRESSION_AND_TIMING.md)을 따른다. 기존에 지지된 마지막 시전까지 구조와 후반 근거를 유지하면서, 발생·경로 누락과 시간표의 실용성을 나누어 검증한다.

- [ ] R11S를 새 계약으로 재생성하고 입력 목록, 학습·검증 분리, 미확정 브랜치·페이즈와 원본 evidence를 기록한다.
- [ ] 여러 입력에서 최종 KDL 생성부터 독립 로그 비교까지 실행한다. 시전 외 신호, 원본 언어 차이, 동시 신호와 밀리초 차이, 페이즈 근거, 시작되지 않은 재생을 포함한다.
- [ ] 미관측·모호·불일치를 분리해 보고하고, ACT 로그와 실제 실행에서 확인한 범위를 명시한다.
- [ ] 다른 레이드와 던전에서도 회귀 검증해 R11S 전용 규칙을 피한다.
- [x] R9S 도입부가 첫 고유 기준점 이전이라는 이유로 분석 범위에서 빠진 문제를 확인하고 raid 공통 도입부 표시 정렬로 보완했다. 첫 일정은 171.8→11.2초, 정의 수는 58→82개다. [감사와 잔여 한계](R9S_OPENING_AUDIT.md)를 기록하고 전투 ID 없는 합성 회귀로 유지한다.
- [ ] R9S 도입부의 나머지 파동·활동 대안·부분 순서를 그래프 대응으로 분석하고, 최초 고유 기준점 이전도 독립 검증의 평가 범위에 포함한다. 단일 시각·원본 대응의 모호함과 실제 기믹 누락을 구분한다.
- [ ] `cargo test`, Clippy, 포맷 검사와 관련 스크립트를 실행하고 README 및 CLI 도움말을 갱신한다.

FFLogs는 ACT 원본 로그가 아니므로 일부 신호를 제공하지 않는다. 실제 게임·ACT 동작과 다국어 이름은 별도 검증 전까지 확정하지 않는다.

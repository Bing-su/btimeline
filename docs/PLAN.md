# 타임라인 재설계 계획

## 목표와 범위

FFLogs에서 사람이 검토하고 편집할 수 있는 실행 가능한 타임라인을 만든다. 실제 전투에 연결하는 실시간 실행기는 외부에서 구현하며, 이 저장소에는 최종 KDL을 검증할 오프라인 재생기를 둔다. 외부 실행기가 별도 evidence 없이 최종 KDL 하나로 실행할 수 있도록 설계한다. 번역은 별도 제공한다. cactbot의 신호와 사례는 참고하지만 cactbot 타임라인 파일과의 호환은 목표가 아니다. 기존 v2 KDL, evidence, JSON 및 CLI 계약과의 호환성은 유지하지 않는다. 현재 FFLogs 수집·입력 검사와 직접 후속 그래프 분석, 새 KDL의 구조 검사 및 lifecycle·phase·event·sync·phase 직속 branch 재생의 첫 구현이 있다. 자동 타임라인 생성과 반복 재생은 남아 있다. 작성용 KDL의 초안 계약은 [타임라인 스키마](TIMELINE_SCHEMA.md)에 정의하고, 현재 사용법과 한계는 [오프라인 재생 안내](OFFLINE_REPLAY.md)에 정리한다.

| R11S 문제                               | 목표                                                                  |
| --------------------------------------- | --------------------------------------------------------------------- |
| 풀마다 전체 전투가 별도 브랜치로 출력됨 | 공통 진행을 공유하고 실제로 갈라지는 구간만 브랜치로 표현             |
| 전투 시작·재시작 신호가 없음            | 시작, 종료, 리셋과 재시작의 실행 의미를 명시                          |
| 페이즈 구분이 없음                      | 근거가 있는 전환 신호와 페이즈를 연결하고 불확실한 경계는 후보로 표시 |
| source가 숫자 ID임                      | NPC 이름으로 매칭하고 원본 ID는 evidence에 보존                       |
| 이벤트가 능력 ID에 제한됨               | cactbot이 지원하는 로그 타입과 필드 조건을 표현                       |

## 1. 신호와 런타임 근거 조사

- [ ] ACT와 cactbot의 로그 타입·필드 및 실제 콘텐츠의 시작·리셋·페이즈 신호를 조사하고 근거 버전을 기록한다.
- [ ] FFLogs와 원본 로그의 관측 가능 범위 및 변환할 수 없는 필드를 구분한다.
- [ ] cactbot의 타임라인 자료는 전투 관측의 참고 자료로 비교하고, 독자적 실행 의미를 억지로 cactbot 구문에 맞추지 않는다.
- [ ] 개발 스크립트는 Bun으로 실행하고 cactbot 공식 검증에 필요한 해당 체크아웃의 의존성을 명시한다.

완료 조건: 신호의 출처와 관측 가능·미지원 범위, 비교 방법이 명시돼야 한다.

## 2. 타임라인과 신호 계약

- [ ] 이벤트의 표시 시각·이름·지속시간·숨김과 여러 시점의 독립적인 동기화 조건을 구현한다.
- [ ] 이벤트마다 사람이 읽을 수 있는 문서 전체 고유 ID를 부여하고, 기존 문서 수정·재생성 시 ID와 반복 회차의 근거를 보존한다.
- [ ] 최종 타임라인 시간은 0.1초 단위로 표시하고 원본 관측의 밀리초와 반올림 근거는 evidence에 보존한다.
- [ ] 최소한 기준 cactbot에서 사용할 수 있는 모든 로그 타입과 필드, 필드별 복수 대안과 정규식을 표현한다. 리터럴과 정규식을 구분하고 지원되지 않는 신호는 명시한다.
- [ ] source는 영어 NPC 이름으로 매칭한다. 동일한 이름의 개체를 자동으로 구별했다고 가정하지 않으며, 언어별 동기화 조건과 표시 텍스트의 번역은 별도 리소스로 제공한다.
- [ ] 전투·phase·반복 회차 시계와 phase 진입 window, 페이즈 간 선택 유지, 명시적 합류와 반복 동기화를 구현한다. option·merge·on-exit은 별도 보정 시계 없이 상대 기준점으로 작성하고 가장 가까운 phase 또는 반복 회차의 보정을 공유한다. 근거는 [시계 조사](CACTBOT_CLOCK_RESEARCH.md)에 정리한다.
- [ ] 선택지별 무한 반복과 window 내 신호에 의한 탈출, lifecycle 상태 전이를 구현한다.
- [ ] KDL 생성기·파서·검증기와 로그 비교를 구현한다. 오프라인 재생기로 실행 의미를 검증하고 실시간 실행기는 구현하지 않는다. 관측과의 분석용 연결은 실행에 필요하지 않은 별도 evidence에 둔다.
- [ ] 실행기가 공유하는 시계·전환 의미와 문서 작성 제약을 구분한다. 정적으로 증명되는 조건 충돌은 오류로, 재생 중 드러나는 모호함은 `ambiguous`로 보고한다. 실제 전투를 표현하지 못하면 임의 신호로 채우지 않고 스키마 한계로 기록한다.
- [ ] 작성 구조를 제한한다. branch는 phase·loop 바로 아래에 두고, loop는 간접 중첩도 금지하며 merge·on-exit의 실행 본문은 event로 한정한다. requires의 잘못된 참조·자기 참조·순환 참조는 정적으로 검사하고 선행 실행 결과의 존재는 재생에서 확인한다. 미래 선택 대기·소급 적용은 허용하지 않는다.
- [ ] 같은 phase에서 본문 실행 중인 loop는 최대 하나로 제한하며 시작 전 탈출 감시는 제외한다. 반복 안 merge에는 유한한 window를 요구하고 명확한 회차 범위 초과를 정적으로 검사한다. 관측에 의존하는 위반은 재생에서 검사하며, 모든 실행 경로의 증명을 요구하지 않는다. 넓은 window는 전체 선택 조건이 구별되면 허용한다.
- [ ] 원본 시간순 관측 처리와 0.1초 window 비교를 구분한다. 한 관측의 경쟁 동작, 유휴 상태의 enter 차단, start와 첫 enter의 동시 성립, branch 선택 종료 후 재개 금지를 공통 실행 규칙으로 구현한다.

완료 조건: KDL 하나에 시간·신호·상태 전이를 표현하고 생성·검증 및 오프라인 재생과 로그 비교 테스트를 통과한다. 외부 실행기의 실제 동작 검증은 별도로 보고한다.

### 오프라인 재생 검증

- [ ] 최종 KDL과 시각이 있는 기록 신호를 입력받아 가상 시계로 재생하고, 예정 이벤트·관측된 신호·시계 보정·상태 전이와 그 결과를 확인한다. 실행에 evidence는 요구하지 않는다.
- [ ] 시작·전멸·재시작, phase 전환, 선택·합류, 반복과 탈출, 시계 보정 및 window 경계를 작은 합성 사례로 검증한다. 같은 신호가 여러 제어 조건에 일치하는 경우와 0.1초 반올림 경계도 포함한다.
- [ ] 조사한 분기·합류·탈출 사례를 공유 시간축으로 재생한다. 기준점을 중복 보정하지 않는지, 후속 sync가 같은 phase의 이벤트와 window를 함께 옮기는지, 반복 보정은 부모로 소급 전파되지 않는지 확인한다. 이 마지막 범위 규칙은 cactbot 소스만으로 검증된 것으로 취급하지 않는다.
- [ ] 정적 구조·범위 오류, 특정 재생에서 발견한 제약 위반, 미검사 조건을 구분한다. 일부 로그의 통과를 모든 경로의 보장으로 표시하지 않는다. 감시 중인 loop와 본문 실행 중인 loop를 구분하고 두 번째 본문 시작 시 위반을 보고한다.
- [ ] 실제 독립 로그를 재생해 `unobserved`, `unobservable`, `ambiguous`, `unresolved`, `mismatch`를 구분하고 원본 관측에 연결한다. FFLogs에 없는 신호는 불일치로 단정하지 않는다.
- [ ] 사람이 사용하는 `validate`와 `compare` 흐름에서 결과를 확인할 수 있게 한다. 별도 재생 명령은 필요성이 확인될 때만 추가한다.

완료 조건: 합성 사례와 독립 로그에 대해 재현 가능한 결과를 제공하고 미관측·미지원과 실제 불일치를 구분한다. 오프라인 재생 통과를 실제 게임·ACT 또는 외부 실행기의 호환성 검증으로 간주하지 않는다.

## 3. 관측과 evidence

- [ ] 원본 관측, 정규화된 발생 후보, 타임라인을 분리한다. 대상별 중복, 동시 시전자, 별도 파동을 구분한다.
- [ ] 후보에 원본 파일 해시, 이벤트 인덱스, 묶은 이유와 불확실성을 기록한다. 게임 ID와 보고서별 actor ID도 추적용으로 보존한다.
- [ ] FFLogs 관측과 ACT 신호의 대응은 검증된 범위만 사용한다. 관측할 수 없는 신호는 수동 작성·출력할 수 있게 하고 비교에서는 관측 불가로 보고한다.

완료 조건: 원본으로 추적할 수 있고 다중 대상, 동시 시전자, 반복 파동과 누락 관측을 잘못 합치지 않는다.

## 4. 공통 진행과 브랜치

- [ ] 정규화된 풀을 정렬해 공통 진행과 국소적인 분기·합류 후보를 찾는다. 여러 풀에 나타난 같은 선택지는 공유한다.
- [ ] 공통 신호로 합류할 수 있으며 페이즈 간 상관된 선택을 보존한다. 실제 사례를 비교해 신호 없는 option 완료 기준 합류와 `requires`가 필요한지 확인한다.
- [ ] [일반 토벌전 반복 조사](CACTBOT_NORMAL_TRIAL_LOOPS.md)를 참고해 선택지별 반복과 반복 진입 전 전환을 표현한다.
- [ ] 조기 종료 이후는 미관측으로 취급한다. 누락, 패킷 순서, 사망에 따른 차이를 기믹 분기로 단정하지 않는다.
- [ ] 분기 신호나 합류 지점이 불명확하면 후보로 남긴다. 독립적이라는 증거 없이 미관측 경로 조합을 만들지 않는다.
- [ ] 학습에 사용하지 않은 풀에서 누락·잘못된 병합·브랜치 선택과 합류를 평가한다.

완료 조건: R11S의 풀별 전투 전체 복제가 사라지고 관측 근거와 미해결 항목을 확인할 수 있다. 파일 크기만으로 성공을 판정하지 않는다.

## 5. lifecycle과 페이즈

기준 cactbot 소스와 사례는 [생명주기 조사](CACTBOT_LIFECYCLE_RESEARCH.md)에 정리하고, 제안하는 정책과 신호 표현은 [타임라인 스키마](TIMELINE_SCHEMA.md#전투-수명주기)에 정의한다.

- [ ] 전투 시작, 종료, 전멸·리셋, 재시작의 동작과 분기·시계 상태 초기화를 정의한다. 던전의 보스 리셋과 구역 종료도 구분한다.
- [ ] FFLogs fight 경계와 ACT 실시간 신호의 근거를 분리한다. 하나를 다른 하나의 증거로 취급하지 않는다.
- [ ] FFLogs phase transitions, 대상 지정 가능 여부, 고유 시전 등에서 페이즈 경계 후보를 찾고 독립 관측으로 검토한다. 편집용 구분과 실제 시계 전환을 구분한다.
- [ ] 시작 → 진행 → 리셋 → 재시작, 처치 종료, 페이즈 이동과 반복 진입을 KDL과 오프라인 신호 재생으로 검증한다. 외부 실행기를 사용할 수 있으면 그 동작도 별도로 확인한다.

## 6. 사람이 사용하기 쉬운 CLI

사용 흐름은 입력 확인 → 생성 → 검토 → 검증·비교 → 최종 타임라인 출력으로 정리한다. 아래 표에서 inspect는 구현되어 있고 validate·compare는 제한된 첫 구현이 있다. compare는 아직 FFLogs 원본 대신 정규화 관측 JSON을 받는다. generate·review는 미구현 초안이다. 별도의 mine 명령은 직접 후속 그래프 분석 초안을 생성한다.

| 작업        | 명령 초안                                   |
| ----------- | ------------------------------------------- |
| 입력 확인   | `btimeline inspect LOG...`                  |
| 생성        | `btimeline generate LOG... -o timeline.kdl` |
| 검토        | `btimeline review timeline.kdl`             |
| 유효성 확인 | `btimeline validate timeline.kdl`           |
| 로그 비교   | `btimeline compare timeline.kdl LOG...`     |

- [ ] 기본 출력은 사람이 읽기 쉬운 요약과 다음 행동을 제공하고, 자동화용 JSON은 명시적으로 요청한다.
- [ ] 사용자가 자주 결정하는 설정만 기본 옵션으로 노출한다. 오류는 문제와 수정 방법을 함께 표시한다.
- [ ] 기존 파일은 명시적 요청 없이 덮어쓰지 않는다. 상세 원본 근거는 필요할 때 확인할 수 있게 한다.
- [ ] 처음 사용하는 사람이 도움말만으로 생성·검토·출력 흐름을 수행할 수 있는지 확인한다.

## 7. R11S와 회귀 검증

- [ ] R11S를 새 계약으로 재생성하고 입력 목록, 학습·검증 분리, 미확정 브랜치·페이즈와 원본 evidence를 기록한다.
- [ ] 미관측·모호·불일치를 분리해 보고하고, ACT 로그와 실제 실행에서 확인한 범위를 명시한다.
- [ ] 다른 레이드와 던전에서도 회귀 검증해 R11S 전용 규칙을 피한다.
- [ ] `cargo test`, Clippy, 포맷 검사와 관련 스크립트를 실행하고 README 및 CLI 도움말을 갱신한다.

FFLogs는 ACT 원본 로그가 아니므로 일부 신호를 제공하지 않는다. 실제 게임·ACT 동작과 다국어 이름은 별도 검증 전까지 확정하지 않는다.

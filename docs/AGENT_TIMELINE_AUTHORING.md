# 에이전트가 작성하는 타임라인

2026-11-02 합의. 사람이 로그를 해석해 cactbot 타임라인을 작성하던 역할을 에이전트가 수행한다. 목표는 [실용적인 품질 기준](GENERATION.md#실용적인-품질-기준)에 맞는 사전 예고·제어 안전성·복구다. 기존 결정적 분석은 관측 정리와 검증 도구로 활용하고, 에이전트는 그 자료를 해석해 KDL을 작성한다.

## 역할과 저장 위치

| 담당·위치                                                           | 책임                                                                                       |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `AGENTS.md`                                                         | 저장소 전체에 적용하는 품질·원본 보존·실행 경계                                            |
| 기존 계약 문서                                                      | KDL 문법, 생성·재생의 의미, 품질 기준의 단일 근거                                          |
| [timeline-author skill](../.agents/skills/timeline-author/SKILL.md) | 입력 역할 고정 → 관측 확인 → 기믹 해석 → KDL 작성 → 재생·수정 → 독립 평가의 반복 절차      |
| btimeline CLI                                                       | 입력 무결성·발생·부분 순서·보스 범위 분석, 초안 생성, KDL 구조 검사와 기록 재생            |
| 에이전트                                                            | 주요 기믹 선정, 동시/대안/반복/누락/종료 해석, 표시·제어 신호 선택, 근거를 남기는 KDL 작성 |
| 전투별 KDL·작성 기록                                                | 능력 ID·일정과 그 전투에 대한 해석·불확실성·검증 결과                                      |

우선 저장소에 skill 하나를 두고 기존 CLI를 사용한다. 전투별 ID·시간표를 skill이나 범용 생성기의 조건문에 축적하지 않는다. 별도 해석 DSL·범용 에이전트 실행 프로그램·새 의존성은 이번 합의에 포함하지 않는다. 여러 전투의 일괄 처리·재시도·비용·실행 이력 관리가 실제로 필요해지면 별도 실행 프로그램을 검토한다.

## 현행 도구와 한계

아래는 저장소 루트에서 빌드한 `btimeline` 실행 파일의 현행 명령 형태다. `TRAIN.json`·`draft.kdl` 등은 실제 경로로 바꾸며 생성·mine 출력에는 새 경로를 사용한다.

| 작업        | 명령                                                        | 해석                                                                            |
| ----------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 관측 확인   | `btimeline inspect TRAIN.json --json`                       | 원본 관측·보스·시도 범위 확인. 큰 로그는 대상 구간을 골라 읽음                  |
| 발생 그래프 | `btimeline mine TRAIN.json -o observations.kdl`             | 검토용 `process 1`. 실행용 `timeline 1`과 구분                                  |
| 선택적 초안 | `btimeline generate TRAIN.json --mode dungeon -o draft.kdl` | 지원하는 경로의 초안·evidence. 경로 학습 실패는 원본 해석을 계속할 수 있는 진단 |
| 구조 검사   | `btimeline validate authored.kdl`                           | 문법·작성 제약 검사. 실제 전투 정확성 판정과 구분                               |
| 실행 확인   | `btimeline compare authored.kdl recording.json --json`      | 정규화된 관측으로 실행 기록 확인. 성공 종료만으로 품질 통과를 주장하지 않음     |

`inspect`·`mine`·`generate`는 여러 학습 파일도 받을 수 있다. 보류 파일은 이 작성 단계의 입력에 넣지 않는다. 현재 `generate`에는 `--verify`가 없으며 계획 문서에 있는 해당 옵션을 실행 가능한 기능으로 안내하지 않는다.

`compare`에 FFLogs JSON을 직접 넣으면 `FFLogs.cast` 등으로 재생하며 자동으로 ACT의 `Ability`가 되지 않는다. 생성 KDL의 제어 신호를 시험하려면 [재생 입력 계약](OFFLINE_REPLAY.md#입력-관측)에 맞는 정규화 기록을 만들고 변환·시작·종료 신호 가정을 명시한다. KDL의 실행 신호를 FFLogs 전용 신호로 바꿔 통과시키지 않는다.

현재 도구는 예상 일정의 일반적인 미래 조회나 실용성 종합 판정을 제공하지 않는다. 제한된 관측만 공급한 재생의 예정 이벤트로 예측 동작을 확인할 수 있으나, UI에서 실제로 몇 초 전에 보였는지 검증한 것과 구분한다. 미래 조회·오류 구간 피드백 등 부족한 도구 기능은 별도 구현 과제로 기록한다.

## 산출물과 근거

| 산출물                                 | 기록할 내용                                                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 최종 KDL                               | 외부 실행기가 단독으로 실행할 표시·신호·window·분기·반복. 해석 의도가 필요한 곳에 주석 작성                                                       |
| 작성 기록 (`authored.authoring.md` 등) | 입력 경로·해시·학습/보류 역할, report/fight·원본 인덱스/노드, 주요 결정·반례·불확실성·사용자 영향, 최종 KDL 해시, 평가 대상·명령·결과·미검사 범위 |
| 초안 evidence                          | 자동 분석의 원본 근거와 당시 KDL 해시를 그대로 보존. 에이전트가 수정한 최종 KDL의 생성 근거인 것처럼 덮어쓰지 않음                                |
| 재생 기록·결과                         | 실제 사용한 관측·가정과 후보 KDL 해시를 연결. 후반 정답 신호를 빼고도 예고되는지, 잘못된 제어와 복구가 있는지 확인                                |

작성 기록은 검토용 evidence이며 새 실행 문법이나 필수 runtime 입력이 아니다. 기존 KDL을 수정할 때 원래 파일·사용자 편집을 보존하고, 수정본과 초안의 관계를 기록한다. 근거 없는 표시·제어를 추가해 완성한 것처럼 보이게 하지 않는다.

학습 로그로 해석·수정한 뒤 후보 KDL과 평가할 주요 기믹·예고 목표를 고정한다. 그때까지 보류 로그의 전투 내용을 작성에 사용하지 않는다. 보류 결과를 보고 수정하면 그 자료는 개발 근거로 바꾸고 새 보류 자료로 독립 평가한다. 명목상 다른 보고서라도 중복 업로드·같은 시도의 복사본이면 독립 근거로 세지 않는다.

초안 evidence의 자동 보고서 보류 결과는 그 임시 자동 모델에 대한 진단이다. 에이전트가 읽고 수정에 사용한 학습 자료의 자동 검사 결과를 최종 작성 KDL의 독립 검증으로 승격하지 않는다.

## 첫 적용과 완료 범위

첫 실험은 Mistwake의 Thundergust Griffin 한 보스를 권장한다. 현재의 복합 파동·도입부 차이를 원본 근거로 해석하고, 기존 결과와 주요 기믹 예고·제어 안전성·복구를 비교한다. 이미 기존 구현 수정·평가에 사용한 Mistwake 로그는 개발 자료로 취급하고, 독립 평가에는 미사용 자료가 필요하다. 다른 대상이나 자료를 사용자가 지정하면 그 범위를 따른다.

후속 첫 파일럿으로 [Griffin KDL](../timelines/mistwake-griffin.kdl)과 [작성·검증 기록](../timelines/mistwake-griffin.authoring.md)을 추가했다. 12개 개발 로그의 선정한 주요 기믹과 합성 제어·복구를 확인했으며 미사용 로그의 독립 검증·실제 ACT 실행은 남아 있다. 여러 에이전트 실행의 성공률 평가와 CLI의 일반 실용성 평가 기능은 아직 구현하지 않았다. 확인한 범위의 결과만 보고한다.

추가 시 skill frontmatter·참조 링크를 검사하고 `tests/fixtures/pull.json`으로 위 `inspect`·`mine`·`generate`·`validate`·`compare` 명령을 확인했다. 합성 `Ability B528` 시작 관측 하나를 공급한 dungeon 초안 재생에서 0·4·8초의 세 이벤트가 실행됐으며 후속 시전 관측은 공급하지 않았다. 이는 CLI 연결과 추가 신호 없는 예측 동작의 확인이며 실제 에이전트 해석·UI 예고 시간·ACT 동등성 검증은 아니다.

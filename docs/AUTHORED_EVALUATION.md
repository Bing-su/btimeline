# 작성 타임라인의 공통 평가

Mistwake·Clyteum·산도리아의 로그 투영·해시/중복 검사·재생·사전 조회·보고서 작성은 Rust `evaluate`로 통합했다. 전투별 실행 스크립트를 추가하지 않고, 해석한 ID·표시 이름·범위만 전투 옆의 `*.evaluation.json`에 둔다. 이 파일은 검증용 자료이며 최종 KDL 실행 의존성이 아니다.

```sh
cargo build
target/debug/btimeline evaluate tests/fixtures/authored/sandoria-fresh-holdout-plan.json --profile timelines/sandoria.evaluation.json -o out/sandoria-rust-new.json
cargo test evaluate
```

명령은 입력·KDL을 한 번 읽고 기존 Rust 검증기·재생기·forecast를 직접 호출한다. cutoff마다 별도 프로세스를 실행하거나 정규화 임시 파일을 만들지 않는다. stdout은 선정·제외·적격·통과 수의 짧은 JSON이다. 원본 인덱스·개별 예고 오차·실행 진단은 `-o`의 전체 JSON에 보존한다.

## 입력과 판정

| 입력      | 의미                                                                                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| manifest  | 기존 작성 평가 계획. `timeline`, `timeline_sha256`, `role`, `forecast_lead_ms`, `horizon_ms`, `tolerance_ms`, `inputs[{input,sha256}]`, 선택적 `excluded_fingerprints` |
| profile   | 아래의 명시적 투영 사실. 읽은 파일의 `profile_sha256`을 보고서에 추가                                                                                                  |
| 경로 기준 | manifest·profile 안의 경로와 CLI 경로는 실행 작업 디렉터리 기준. 저장소 루트에서 실행                                                                                  |

| 결과                                                          | 처리                                            |
| ------------------------------------------------------------- | ----------------------------------------------- |
| 입력 누락·중복·이름 누락·약속한 완료/본체 미확인·HP 회복 의심 | `excluded`, 근거와 원본 인덱스 보존             |
| 원본 무결성·해시 오류·재생/조회 실패                          | `error` 또는 평가 실패. 제외로 전환하지 않음    |
| 실제 예고 오차·진입/제어 진단                                 | 평가 실패. 보고서를 쓴 뒤 명령 실패             |
| 적격 0개                                                      | 통과하지 않음                                   |
| KDL·manifest·profile의 실행 중 변경                           | 결과를 게시하지 않음                            |
| 기존 출력 경로                                                | 덮어쓰지 않음. 새 보고서는 원자적 생성으로 게시 |

`compare`에 FFLogs 파일을 직접 넣을 때의 `FFLogs.*` 의미는 바꾸지 않는다. `evaluate`는 아래 profile이 선언한 **검증용 가정**으로만 Ability/StartsUsing을 투영한다. HP=0을 WasDefeated·finish로 합성하지 않는다.

## Profile v1

알 수 없는 profile 필드는 오류다. 기술 ID는 대문자 16진수이며 예고 간격은 양의 밀리초다. 실제 예시는 [Mistwake](../timelines/mistwake.evaluation.json), [Clyteum](../timelines/clyteum.evaluation.json), [산도리아](../timelines/sandoria.evaluation.json)를 따른다.

| 필드                  | 의미                                                                                                                                               |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`             | 현재 1                                                                                                                                             |
| `observations`        | `all_casts`: 모든 cast의 시전자 확인 후 마지막 구간까지 전달. `scoped_casts`: 평가 구간 안 cast. `scoped_casts_and_starts`: 구간 안 cast·begincast |
| `segments`            | 실행/평가 순서의 구간. `phase`, `source`, `entry` ID 배열, `targets` 필요. 선택적 `encounter`로 한 FFLogs 전투에 적용할 구간 제한                  |
| `completion`          | `defeat`: 처치 필수. `fight_end`: 완료/전멸 기록 끝. `first_defeat`: 첫 본체 처치 또는 기록 끝                                                     |
| `max_duration_ms`     | 첫 대표 cast부터 유한 평가 상한. 기록·처치 끝과 비교해 이른 값 사용                                                                                |
| `require_main_actor`  | 이름마다 Boss actor 하나 요구. 추가 공동 본체는 `other_sources`에 지정                                                                             |
| `reject_health_reset` | 본체 HP가 75% 미만에서 90% 초과로 회복하면 제외. 명확한 본체 요구와 함께 사용                                                                      |
| `targets`             | ID별 `name`, 선택적 `source`, `group`, `lead_ms`. 기본 시전자는 구간 source, 기본 예고는 manifest 값                                               |
| `group`               | 100ms 이내 중복 대상 패킷을 요약할 공통 키. 생략하면 ID별. 동일 표시 이름이라고 자동으로 합치지 않음                                               |
| `not_checked`         | 전투별 미검증 범위                                                                                                                                 |

구간 선택·진입·처치 근거·대상 패킷 요약을 공통 코드가 처리한다. 전투 시간표·분기·반복 해석은 KDL 작성자가 결정한다. 기존 평가의 이름/가장 가까운 시각 대응은 보존했으며, 이벤트별 일대일 대응이나 모든 새 기믹의 누락 탐지는 아직 제공하지 않는다. Varis·Queen·Griffin의 특수 구간 해석/별도 평가와 cactbot 공식 TypeScript 연동은 이번 이전 범위 밖이다.

## 기존 결과와의 대조

| 대상               | 선정 | 제외 | 적격 통과 |
| ------------------ | ---- | ---- | --------- |
| Mistwake 개발      | 17   | 8    | 9         |
| Mistwake 보류      | 6    | 1    | 5         |
| Clyteum 개발       | 31   | 8    | 23        |
| Clyteum 보류       | 6    | 1    | 5         |
| 산도리아 확장 개발 | 28   | 2    | 26        |
| 산도리아 새 보류   | 16   | 0    | 16        |
| 합계               | 104  | 20   | 84        |

기존 보고서와 Rust 결과의 모든 평가 대상·조회·오차·fingerprint·제외 근거·집계를 의미 값으로 대조했다. 제외 메시지는 공통 표현으로 통일했으며 판정 근거는 유지한다. 이는 같은 입력에 대한 이전 동작 보존 검사이고 새로운 독립 평가를 주장하지 않는다. 기존 manifest와 작성 validation 기록은 변경하지 않는다.

## 타임라인 작성 토큰 절감

| 단계           | 에이전트가 먼저 읽을 것                    | 상세를 읽는 조건                           |
| -------------- | ------------------------------------------ | ------------------------------------------ |
| 개발 자료 선정 | 메타데이터·진행 길이·기술/시전자 차이 요약 | 새로운 진행 또는 구분할 선택지를 조사할 때 |
| 대표 경로 작성 | 한 대표 경로의 주요 시전열·원본 인덱스     | 동시/대안/반복을 구별할 근거가 필요할 때   |
| 수정           | 실패 종류·첫 실패 위치·복구 시점           | 해당 원본 위치 주변의 제한된 관측 범위     |
| 전체 검사      | 공통 CLI의 집계                            | 실패한 입력의 상세 결과만 확인             |
| 재개           | 현재 후보·해석 결정·남은 불확실성          | 변경된 결정에 연결된 근거만 다시 확인      |

공통 검증 코드를 매 전투마다 작성하거나 읽지 않고 CLI를 실행한다. 원본과 전체 보고서는 파일로 보존하고 대화에는 필요한 일부만 전달한다. 향후 공통 Rust 도구의 우선순위는 **원본 인덱스를 보존한 구간 관측 조회 → 실패 원인별 요약 → 미분류 기술 목록**이다. 각각 기본 출력에 상한을 두고 전체 근거의 경로를 함께 반환해야 한다. 아직 이 구간 조회·실패 요약 기능은 구현하지 않았다.

스킬에는 공통 절차와 위 상세 조회 조건을 짧게 두고, 전투별 사례·긴 판정표는 필요할 때 읽는 참고 문서로 분리하는 편이 좋다. 결정적 필터링·계산·집계는 Rust가 수행하고 에이전트는 기믹 해석과 불확실성에 집중한다. 보류 내용을 미리 읽거나 검사를 줄여 토큰을 아끼지 않는다. 절감 효과는 아직 측정하지 않았으므로 비율을 주장하지 않는다.

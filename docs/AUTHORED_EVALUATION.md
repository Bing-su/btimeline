# 작성 타임라인의 공통 평가

Mistwake·Clyteum·산도리아와 단독 Griffin의 원본 로그 투영·해시/중복 검사·재생·사전 조회·보고서 작성은 Rust `evaluate`로 통합했다. 전투별 실행 스크립트를 추가하지 않고, 해석한 ID·표시 이름·범위만 전투 옆의 `*.evaluation.json`에 둔다. 이 파일은 검증용 자료이며 최종 KDL 실행 의존성이 아니다.

```sh
cargo build
target/debug/btimeline evaluate tests/fixtures/authored/sandoria-fresh-holdout-plan.json --profile timelines/sandoria.evaluation.json -o out/sandoria-rust-new.json
target/debug/btimeline review out/sandoria-rust-new.json --limit 8
target/debug/btimeline evidence logs/sandoria-authoring-development/PAq8bNtxvXWG16QZ_68.json --around-index 12105
cargo test evaluate
```

명령은 입력·KDL을 한 번 읽고 기존 Rust 검증기·재생기·forecast를 직접 호출한다. cutoff마다 별도 프로세스를 실행하거나 정규화 임시 파일을 만들지 않는다. stdout은 `summary`·`review_required`·보고서 경로의 짧은 JSON이다. 원본 인덱스·개별 예고 오차·실행 진단은 `-o`의 전체 JSON에 보존한다. `summary.passed`는 선택 대상의 예고 판정이고 전체 시전의 해석 완료를 뜻하지 않는다.

## Profile 없이 시작하기

`--profile`을 생략하면 KDL 근거로 평가 가능한 범위를 추론한다. manifest에는 같은 KDL·원본 입력 해시와 공통 예고 기준을 둔다. 독립 보류 평가에는 평가기 해시도 고정한다.

```sh
target/debug/btimeline evaluate tests/fixtures/authored/griffin-native-regression-plan.json -o out/griffin-inferred-new.json
target/debug/btimeline review out/griffin-inferred-new.json --limit 8
```

| 근거                                               | 자동 평가 처리                                                                                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 리터럴 `enter Ability` 또는 `StartsUsing`          | 관측된 진입을 원본 순서로 정렬한다. 다른 보스로 넘어갈 때는 다음 진입 전에 HP=0을 확인한다. 같은 보스는 `from`이 직전 phase를 가리키는 관측을 원본 순서대로 따라간다. |
| 표시와 같은 상대 시각에 명시한 본체 `Ability` sync | 리터럴 ID와 시전자로 관측을 연결한다. 첫 진입 패킷은 예고 점수에서 뺀다.                                                                                              |
| 이름만 같은 표시, 다른 시점의 sync, 모호한 alias   | 관측 연결을 추정하지 않는다. 같은 이름의 미연결 표시가 있으면 해당 이름으로 연결된 ID도 자동 점수에서 보류한다. 대응 없는 표시와 미분류 시전은 검토에 남긴다.         |
| 지원 범위를 식별할 수 없거나 조회할 예고가 없음    | `unverified`로 집계한다. 실제 재생 오류와 제어 진단은 실패로 유지한다.                                                                                                |

보고서의 `projection: "inferred"`는 이 경로를 나타낸다. 같은 보스의 전환 시각은 새 phase에 포함하고 마지막 phase는 기록 끝까지 평가한다. 진입 후보가 없거나, 같은 시각의 진입 후보를 구분할 수 없거나, 구간 경계의 근거가 부족하면 `unverified`로 분류한다. `review`에서 후보와 원본 인덱스를 확인할 수 있다. KDL의 전환 창과 순서는 실제 재생 결과를 원본에서 찾은 진입과 비교해 검사한다. 같은 전환 신호가 여러 시각에 나오면 재생에서 실제 진입으로 연결된 원본 관측을 우선한다. 앞선 패킷이 여러 phase의 후보여도 모든 전환 창이 닫혀 있었다면 후속 관측으로 진입할 수 있다. 하나의 원본 패킷이 여러 phase의 후보면, 재생 시계에서 전환 창을 적용해 유일하게 진입한 phase만 채택한다. 같은 시각에 서로 다른 패킷이 경쟁하면 패킷 순서에 의존할 수 있으므로 미확인으로 남긴다. HP=0은 평가 범위에만 쓰인다. `resume-at=0.0`으로 보호한 첫 진입도 지원한다. 예고를 확인할 수 없는 phase는 보고서에 남긴다. 자동 평가의 중복 fingerprint에는 선택한 phase 순서도 포함되므로 명시 profile의 목록과 별도로 관리한다.

Griffin의 기존 원본 6개를 재실행해 적격 4개의 대상 21개를 평가했고 모두 통과했다. 같은 전투의 명시 profile은 76개 대상을 평가한다.

산도리아의 기존 독립 검증 입력 43개를 자동 평가의 개발 회귀로 재사용했다. Kam 5개에서 자동 연결 대상 11개가 모두 통과했고, 37개는 미확인, 1개는 시전자 정보 부족으로 제외됐다. Kam의 초반과 후반 Proving Ground는 같은 ID를 공유하며 후반 표시만 명시 연결돼 있다. 따라서 해당 ID는 점수를 보류하고 미분류 시전으로 남겼다. 원본 [입력 목록](../tests/fixtures/authored/sandoria-adcd-independent-holdout-plan.json)을 다시 사용할 때는 기존 평가의 동결 profile·평가기 해시와 fingerprint 목록을 제거하고 개발 역할로 구분한다.

[Doomtrain 시험 KDL](../tests/fixtures/authored/doomtrain-inferred-pilot.kdl)은 `n7TpPm3y9q6vcg4D/20` 한 건에서 관측한 기술 ID 4개의 일정을 담는다. 작성에 쓰지 않은 [기존 수집 로그 5개](../tests/fixtures/authored/doomtrain-inferred-pilot-plan.json)를 같은 명령으로 평가했다. 1개가 통과했고, 4개에서 후반 Turret Crossing·Head-On Emission의 시각 오차 또는 대응 누락을 찾았다. 이 실험은 작성에 쓴 입력과 비교 입력을 구분했으며, 이전 작업에서 사용한 자료를 재사용했다.

Doomtrain 시험 KDL을 Runaway Train에서 같은 보스의 두 phase로 분리해 기존 비교 로그 5개를 다시 재생했다. 첫 진입에 `resume-at=0.0`을 둔 뒤 5개 모두 진입과 전환이 일치했다. 1개는 예고까지 통과했고, 4개는 후반 예고의 시각 오차 또는 누락이 남았다.

같은 신호가 반복되어도 현재 phase의 후속 전환에 해당하지 않으면 진입 근거로 쓰지 않는다. 다른 phase의 후속 전환에 해당하면 재사용할 수 있다. Varis의 자동 평가에는 소스가 바뀌거나 진입에 여러 직전 phase가 필요한 구간이 남아 있다. Queen은 일부 기술이 연결되지만, 공통 5초 기준과 기록 전체 범위를 사용하면 기존 Castellation 발췌 평가와 결과가 다르다.

서로 다른 보스가 이어지는 기존 던전 자료에서 Mistwake는 적격 5개·제외 1개, Clyteum은 적격 2개·미확인 1개·제외 3개였다. 적격 7개에서 각 3개 phase의 자동 대상 62개가 통과했다. Clyteum의 미확인 로그는 다음 보스 진입 전 HP=0을 확인할 수 없었다. 제외 4개는 시전자 이름 부족이다. 두 전투의 기존 평가 입력을 재사용한 개발 회귀다.

## 입력과 판정

| 입력      | 의미                                                                                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| manifest  | 기존 작성 평가 계획. `timeline`, `timeline_sha256`, `role`, `forecast_lead_ms`, `horizon_ms`, `tolerance_ms`, `inputs[{input,sha256}]`, 선택적 `excluded_fingerprints`, `profile_sha256`, `evaluator_sha256` |
| profile   | 아래의 명시적 투영 사실. 읽은 파일의 `profile_sha256`을 보고서에 추가                                                                                                                                        |
| 경로 기준 | manifest·profile 안의 경로와 CLI 경로는 실행 작업 디렉터리 기준. 저장소 루트에서 실행                                                                                                                        |

| 결과                                                          | 처리                                            |
| ------------------------------------------------------------- | ----------------------------------------------- |
| 입력 누락·중복·이름 누락·약속한 완료/본체 미확인·HP 회복 의심 | `excluded`, 근거와 원본 인덱스 보존             |
| 원본 무결성·해시 오류·재생/조회 실패                          | `error` 또는 평가 실패. 제외로 전환하지 않음    |
| 실제 예고 오차·진입/제어 진단                                 | 평가 실패. 보고서를 쓴 뒤 명령 실패             |
| 적격 0개                                                      | 통과하지 않음                                   |
| KDL·manifest·profile의 실행 중 변경                           | 결과를 게시하지 않음                            |
| 기존 출력 경로                                                | 덮어쓰지 않음. 새 보고서는 원자적 생성으로 게시 |

`compare`에 FFLogs 파일을 직접 넣을 때의 `FFLogs.*` 의미는 바꾸지 않는다. `evaluate`는 아래 profile이 선언한 **검증용 가정**으로만 Ability/StartsUsing을 투영한다. HP=0을 WasDefeated·finish로 합성하지 않는다.

새 독립 평가에서는 개발 보고서의 `evaluator_sha256`을 보류 manifest에 복사하고 `evidence_role: "held_out"`을 지정한다. 명시 profile을 사용하면 `profile_sha256`도 고정한다. 실행 파일의 실제 바이트 해시를 사용하므로 재빌드하면 바뀔 수 있다. 해시가 다르거나 고정한 profile을 생략하면 로그 평가 전에 거부한다. `evidence_role`은 `development`, `held_out`, `synthetic`, `unspecified` 중 하나이며 생략하면 `unspecified`다. 자유문 `role`이나 파일 이름으로 역할을 추정하지 않는다. 역할 선언·해시 고정 자체는 자료의 독립성을 증명하지 않는다. 기존 manifest는 계속 읽되 `bindings`에 동결 여부를 표시한다.

## Profile v1

알 수 없는 profile 필드는 오류다. 기술 ID는 대문자 16진수이며 예고 간격은 양의 밀리초다. 실제 예시는 [Mistwake](../timelines/mistwake.evaluation.json), [Clyteum](../timelines/clyteum.evaluation.json), [산도리아](../timelines/sandoria.evaluation.json)를 따른다.

| 필드                  | 의미                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `version`             | 현재 1                                                                                                                                                       |
| `observations`        | `all_casts`: 모든 cast의 시전자 확인 후 마지막 구간까지 전달. `scoped_casts`: 평가 구간 안 cast. `scoped_casts_and_starts`: 구간 안 cast·begincast           |
| `segments`            | 실행/평가 순서의 구간. `phase`, `source`, `entry` ID 배열, `targets` 필요. 선택적 `encounter`로 한 FFLogs 전투에 적용할 구간 제한                            |
| `completion`          | `defeat`: 처치 필수. `fight_end`: 완료/전멸 기록 끝. `first_defeat`: 첫 본체 처치 또는 기록 끝                                                               |
| `max_duration_ms`     | 첫 대표 cast부터 유한 평가 상한. 기록·처치 끝과 비교해 이른 값 사용                                                                                          |
| `require_main_actor`  | 이름마다 Boss actor 하나 요구. 추가 공동 본체는 `other_sources`에 지정                                                                                       |
| `reject_health_reset` | 본체 HP가 75% 미만에서 90% 초과로 회복하면 제외. 명확한 본체 요구와 함께 사용                                                                                |
| `targets`             | 기술 ID별 `name`, 필수 `events` KDL 이벤트 ID 배열, 선택적 `source`, `group`, `lead_ms`, `equivalents`. 기본 시전자는 구간 source, 기본 예고는 manifest 값   |
| `events`              | 이 기술의 가능한 실행 정의. 예: `['opening-hit', 'repeat-hit']`. 표시 가능한 같은 phase의 정의만 허용. 후보 집합은 다른 target과 같거나 완전히 분리되어야 함 |
| `equivalents`         | 선택적 ID 배열들의 배열. 예: `[['predicted-hit', 'merged-hit']]`. 합류에서 교체되는 같은 예고만 명시하며 각 집합은 events의 서로 겹치지 않는 부분집합        |
| `group`               | 100ms 이내 중복 대상 패킷을 요약할 공통 키. 생략하면 ID별. 동일 표시 이름이라고 자동으로 합치지 않음                                                         |
| `not_checked`         | 전투별 미검증 범위                                                                                                                                           |
| `ignored`             | 구간별 ID → 관측에 근거한 제외 사유. 공백 사유와 targets와의 ID 중복은 오류. 감사 분류에만 쓰며 원본 관측·표시·제어를 제거하지 않음                          |

`validate TIMELINE --json`의 `catalog.events`에서 ID와 소유 phase·분기·반복을 조회해 바인딩한다. 이름은 표시용이며 대응 판정에는 사용하지 않는다. 이전의 events 없는 profile은 거부하므로 새 배열을 추가해야 한다. 구간 선택·진입·처치 근거·대상 패킷 요약은 공통 코드가 처리하고 전투 시간표·분기·반복 해석은 작성자가 결정한다. Varis·Queen 특수 구간 평가, Griffin 합성 실험 및 cactbot 공식 TypeScript 연동은 별도 범위다.

후보 ID 집합마다 시간순 일대일 대응으로 허용 오차 안의 대응 수를 먼저 최대화하고, 전체 대응 수와 총 오차를 순서대로 비교한다. 같은 실행 행을 두 관측에 재사용하지 않는다. 동시 패킷을 한 표시로 요약하려면 같은 `name`·`events`와 명시적인 공통 `group`을 사용한다. `matched_event`에는 실제 ID·시각·실행 문맥을 보존한다. 사전 조회는 실제 대응한 정의와 같은 전투 시도·phase 진입·반복 회차를 요구한다. 합류 교체가 있는 경우에만 `equivalents`의 정의 간 인계를 인정한다. 단순히 같은 표시 이름이거나 events에 함께 있다는 이유로 서로 대신하지 않는다.

## 감사와 짧은 조회

| 도구·결과                         | 의미와 출력 상한                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evaluate`의 구간별 `audit`       | 선언한 source·other_sources·target source의 cast를 대상·사유 있는 제외·미분류로 집계. 대상별 중복 패킷도 원본 cast 수에 포함. 미분류는 ID/시전자별 이름·발생 수·첫/마지막 원본 인덱스·시각을 보존       |
| `review_required`                 | 미분류 또는 대응하지 않은 표시가 있으면 true. 예고 점수나 입력 적격 판정을 바꾸지 않으며, 단독으로 CLI 실패를 만들지는 않음                                                                             |
| `unmatched_displays`              | 대응되지 않은 표시를 `duplicate_candidate`(근처 관측의 후보), `unmatched_bound`(바인딩됐지만 근처 관측 없음), `unbound`로 분리. 기록 종료·누락 관측도 가능하므로 검토 근거로 사용                       |
| 중복 로그의 감사                  | 대상열 fingerprint가 같아 제외하더라도 `evidence.audit_only`에 감사를 보존. 새 미분류 시전이 중복 처리에 묻히지 않으며 독립 표본 수는 늘리지 않음                                                       |
| `review REPORT --limit 8`         | 재생 없이 phase별 대상·예고 수/간격/오차/실패 종류와 입력별 첫 문제, 미분류를 요약. 실제 실패를 제외 사례보다 먼저 표시. 각 목록 기본 8개·최대 50개. 전체 수와 생략 수 표시                             |
| `evidence INPUT --around-index N` | 원본 배열의 N번째 관측 시각 ±5초 안 NPC cast·begincast. `--before-ms`, `--after-ms`, `--source`로 좁히며 기본 40행·최대 200행. 중심에 가까운 행을 먼저 선택한 뒤 원본 인덱스를 유지하며 시간순으로 표시 |

감사는 **선언한 시전자·구간** 안의 선택하지 않은 시전을 드러낸다. 자동으로 기믹을 해석하거나 profile 밖의 새 helper·범위 밖 진행까지 검사하지 않는다. KDL 제어에만 등장하고 profile에는 없는 helper도 자동 감사 대상은 아니다. `evidence`는 enemyNPCs에 없는 helper를 포함한 NPC 시전을 조회하며, 명시적인 `--source`는 다른 actor도 조회할 수 있다.

미분류에는 평타·대표 기술에 요약한 후속 타격도 들어간다. 미분류 수를 누락 기믹 수로 해석하거나 모든 패킷 분류를 사용 가능성의 조건으로 삼지 않는다. 불확실한 항목은 범위·영향과 함께 남기고, 주요 예고·제어·복구에 영향을 주는 차이를 우선 조사한다.

`evidence`의 `at_ms`는 fight.startTime 기준이며 `origin_timestamp_ms`와 열 이름을 함께 출력한다. `around-index`는 damage 등 시전이 아닌 원본 관측도 중심점으로 사용할 수 있다. 시간 범위를 지정하려면 around-index가 필요하다. 전체 일치 수와 생략 수를 확인하며, 생략된 관측이 없다고 추정하지 않는다. 원본 무결성은 inspect와 같은 경계에서 검사하며 ACT로 투영하지 않는다.

`review`는 보고서의 집계와 trace가 일치하는지 확인한다. 감사가 없는 과거 보고서도 읽지만 `unavailable_or_partial`로 표시하며 기본 예고 간격을 추정하지 않는다. phase 진입이 다르면 예고 실패보다 먼저 `entry_mismatch`에 예상·재생 phase, 상대 시각과 원본 인덱스를 표시한다. 각 목록의 예시만 자르므로 전체 JSON은 그대로 남는다. 원본 행이나 긴 진단의 문자 수는 실제 모델 토큰 사용량과 같은 단위가 아니다.

미분류가 상한보다 많으면 `next_unclassified_offset`을 다음 호출의 `--unclassified-offset`으로 넘긴다. 이는 미분류 목록만 페이지로 나누며 phase·문제 목록의 상한과 우선순위는 유지한다. 생략 수는 페이지 앞뒤를 합한 수다. 같은 보고서 파일과 해시를 기준으로 조회한다.

대상별 `failure_reasons`는 표시 누락/오차, 사전 조회 누락/오차/제어 상태, 현재 진단과 가상 미래 진단을 구별한다. 전체 조회의 `diagnostics`는 호환을 위해 합친 배열을 유지하되 `current_diagnostics`와 `projection_diagnostics`도 각각 보존한다. 한 대상에 원인이 여럿일 수 있어 원인별 합계와 실패 대상 수가 다를 수 있다.

## 분기·반복 커버리지

전체 보고서의 trace별 `coverage`와 짧은 `review.coverage`는 해당 manifest의 자료만 집계한다. 후보 phase의 선택지 중 관측 0개인 항목도 표시한다. 제외한 중복 입력은 표본을 늘리지 않는다.

선택지별 `input_count`와 `report_count`는 선택을 관측한 고유 입력과 보고서 수다. 보고서가 달라도 독립 전투인지는 별도로 확인해야 한다. `fight_duration_range_ms`는 전체 전투 길이의 최솟값과 최댓값이다. `pace`는 같은 분기가 있는 평가 입력의 전투 길이를 기준으로 나누며 `cutoff_ms` 이하를 빠른 표본으로 집계한다. 표본 길이가 모두 같거나 길이 근거가 없으면 경계는 null이다. 한쪽 집계가 0이면 해당 속도 표본에서 그 선택지를 관측하지 못했다.

`first_forecast`는 선택 이후 같은 phase에서 해당 선택지에 연결된 첫 관측의 예고 결과를 선택 발생마다 집계한다. 실제 대응 표시가 있으면 그 표시의 소유권을 사용하고, 다음 선택 이후의 관측은 제외한다. 연결할 관측이나 예고가 없으면 미확인이다. 이전 보고서에는 전투 길이와 선택지의 표시 연결이 없을 수 있으므로 새 지표가 필요하면 다시 평가한다.

`signal_kind`는 KDL의 `fallback` 선언에 따라 기본 선택(`primary`)과 복구 선택(`fallback`)을 구분한다. 기존 보고서에 이 정보가 없으면 null이다. 기본 선택으로 표시되어도 신호의 고유성은 따로 검증한다. `unresolved_branches`에는 재생기가 선택 실패를 기록한 분기와 대표 발생 시각을 표시한다. 타이머로 창이 닫혔으면 원본 패킷 인덱스가 없을 수 있다. 선택 횟수가 0인 항목은 그 선택지의 미관측을 뜻하며, 분기의 미해결 횟수와 별도로 집계한다.

| 지표                                   | 의미와 한계                                                                                                                |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `choices.signal_selections`            | 실제 관측이 선택한 분기 횟수. 첫 원본 인덱스와 입력을 연결하며 표시 타이머만으로 선택을 추정하지 않음                      |
| `emitted_iterations`                   | 타이머에 의해 실행된 반복 회차. 실제 관측 확인과 별개                                                                      |
| `matched_iterations`, `matched_events` | 허용 오차 안에서 target 관측과 일대일 대응한 회차·표시 수                                                                  |
| `consecutive_anchor_pairs`             | 반복 본문 at=0의 같은 표시가 인접 모델 회차에서 각각 관측과 대응한 쌍. 첫 쌍의 두 원본 인덱스 보존                         |
| `signal_exits`                         | 원본 관측이 종료시킨 반복 횟수                                                                                             |
| `body.complete_display_bodies`         | 인접 기준점 두 개가 관측되고, 그 사이 실행된 visible 표시가 모두 구간 안 관측과 대응하며 선택과 순서가 확인된 회차         |
| `body.incomplete_display_bodies`       | 기준점 사이에서 표시 대응·선택·순서가 부족한 회차. `first_gap`에 첫 문제와 양쪽 기준점의 원본 인덱스 보존                  |
| `body.unverified_iterations`           | 다음 기준점이 관측되지 않아 본문 판정을 보류한 실행 회차. 마지막 회차·시작 전 탈출을 완전 본문으로 추정하지 않음           |
| `body.exits_with_matched_on_exit`      | 실제 until 관측 뒤 같은 전투·phase 진입의 on-exit 표시가 후속 원본 관측과 대응한 종료 횟수. 종료 신호만 관측한 경우와 구분 |
| `evidence_role`, `status`              | 선언한 개발·보류·합성 역할과 커버리지 자료의 제공 상태. 과거 보고서에 없으면 unavailable/partial                           |

기준점의 연속 대응 자체는 **전체 반복 본문 검증이 아니다**. `body`는 그 사이 실제 실행된 표시를 각각 확인하고, 반복 안 각 분기의 관측된 선택을 요구한다. 표시 일정과 관측 순서의 역전도 검사하되 100ms 안의 동시 파동은 패킷 순서를 강제하지 않는다. 누락된 표시는 평가 profile에서 빠졌더라도 본문 완료를 막으며 hidden 제어 표시는 대상이 아니다. 이는 선택한 경로의 **작성된 표시**에 대한 진단이고 모델 밖 기믹·모든 원본 패킷의 재구성을 보증하지 않는다. 본문 점검만으로 예고 점수나 입력 적격 판정을 바꾸지 않는다.

짧은 조회는 위 body 지표와 `first_body_gap`을 집계한다. `body_coverage_inputs`가 해당 loop의 본문 점검 자료 수이며 과거 보고서에 body가 없으면 0이다. 다른 manifest의 합성 테스트와 보고서 간 독립성은 따로 확인한다. 상위 선택지 안 반복의 조건은 `owner`에 보존하며 합성 입력과 실측 결과를 합쳐 독립 보류 검증으로 부르지 않는다.

## 기존 결과와의 대조

| 대상               | 선정 | 제외 | 적격 통과 |
| ------------------ | ---- | ---- | --------- |
| Mistwake 개발      | 17   | 8    | 9         |
| Mistwake 보류      | 6    | 1    | 5         |
| Clyteum 개발       | 31   | 8    | 23        |
| Clyteum 보류       | 6    | 1    | 5         |
| 산도리아 확장 개발 | 28   | 2    | 26        |
| 산도리아 새 보류   | 16   | 0    | 16        |
| 합계               | 104  | 20   | 84        |

기존 보고서와 Rust 결과의 모든 평가 대상·조회·오차·fingerprint·제외 근거·집계를 의미 값으로 대조했다. 제외 메시지는 공통 표현으로 통일했으며 판정 근거는 유지한다. 이는 같은 입력에 대한 이전 동작 보존 검사이고 새로운 독립 평가를 주장하지 않는다. 기존 manifest와 작성 validation 기록은 변경하지 않는다.

감사·조회 보강(`0f595aa`)에서도 같은 104개 입력의 예고 판정·오차·fingerprint·적격/제외 구분을 유지했다. 감사와 실패 이유·조회 상태·실제 예고 간격은 추가 메타데이터다. 예고가 통과해도 미분류 검토가 남았음을 별도로 확인할 수 있으며, 독립 평가 표본 수나 기존 KDL은 바꾸지 않았다.

이벤트 ID·회차 기반 일대일 평가에서도 위 104개 입력의 대상별 예고/재생 오차·판정·fingerprint·적격/제외 구분을 이전 감사 보고서와 대조해 유지했다. 기존 manifest의 역할은 `unspecified`로 두고 KDL·과거 기록은 수정하지 않았다. 재평가는 새 독립 평가가 아니다. 산도리아에서는 대응 없는 표시가 개발 13건(바인딩 10·미바인딩 3), 보류 11건(6·5) 드러났으며 검토 경고로 남긴다. 관측 부재만으로 이 표시들이 모두 잘못됐다고 판정하지 않는다.

| 산도리아 shijin 선택 | 개발 관측 | 기존 보류 관측 |
| -------------------- | --------- | -------------- |
| quake                | 1         | 3              |
| stonega              | 2         | 1              |
| genbu                | 2         | 0              |
| eastwind             | 1         | 0              |

분기 집계는 기존 수동 기록과 일치하며 Genbu·Eastwind의 보류 미관측을 그대로 보존한다. 반복 집계도 타이머 실행과 대응한 기준점을 구별해 출력하며, 이전 수동 본문 검증 수치를 대체하지 않는다. 재현은 위 여섯 manifest에 대응하는 profile로 `evaluate` 후 `review`를 실행한다.

이후 [산도리아 경고 검토](../timelines/sandoria.authoring.md#이벤트-id-평가가-드러낸-표시-24건-검토)에서 대안 기술·보조 시전자 누락을 보완해 24건을 발동 미관측 3건으로 줄였다. 변경 후 기존 개발·보류 자료는 합친 개발 계획에서 평가한다. 원래 보류 판정은 당시 후보의 이력으로 보존하며 현재 수정본의 독립 검증으로 재사용하지 않는다.

본문 검사 추가 후에도 세 전투의 기존 104개 입력에서 적격 84개 통과·제외 20개를 유지했다. 산도리아는 경고 검토 계획의 44개 입력·적격 42개로 포함한다. 다음 표는 **인접 실측 기준점 사이 작성된 표시**의 확인 수이며 종전 수동 전체 본문 수치와 범위가 다르다.

| 전투     | 개발 complete display bodies | 기존 보류 complete display bodies | 본문 부족 판정 |
| -------- | ---------------------------- | --------------------------------- | -------------- |
| Mistwake | 3                            | 5                                 | 0              |
| Clyteum  | 10                           | 2                                 | 0              |

Treno·Chort 등 다음 기준점이 없는 회차는 0회 완료와 미검증으로 남는다. 합성 테스트는 중간 표시 누락·순서 역전·선택 미관측을 구별하고, 동시 파동 순서와 마지막 회차 보류 및 실제 종료 뒤 on-exit 대응도 확인한다. 본문 집계는 토큰을 줄이는 진단이며 게임 밖 검증 경계를 바꾸지 않는다.

[단독 Griffin 원본 평가](../timelines/mistwake-griffin.authoring.md)는 Rust로 이전하면서 과거 보류 6개 중 적격 4개·제외 2개, 76개 대상의 원본 인덱스와 재생·예고 오차를 그대로 유지했다. 새 독립 평가를 주장하지 않으며, 원본 평가 스크립트와 중복 검사 두 개를 제거했다.

## 타임라인 작성 토큰 절감

| 단계           | 에이전트가 먼저 읽을 것                    | 상세를 읽는 조건                           |
| -------------- | ------------------------------------------ | ------------------------------------------ |
| 개발 자료 선정 | 메타데이터·진행 길이·기술/시전자 차이 요약 | 새로운 진행 또는 구분할 선택지를 조사할 때 |
| 대표 경로 작성 | 한 대표 경로의 주요 시전열·원본 인덱스     | 동시/대안/반복을 구별할 근거가 필요할 때   |
| 수정           | 실패 종류·첫 실패 위치·복구 시점           | 해당 원본 위치 주변의 제한된 관측 범위     |
| 전체 검사      | 공통 CLI의 집계                            | 실패한 입력의 상세 결과만 확인             |
| 재개           | 현재 후보·해석 결정·남은 불확실성          | 변경된 결정에 연결된 근거만 다시 확인      |

공통 검증 코드를 매 전투마다 작성하거나 읽지 않고 CLI를 실행한다. 원본과 전체 보고서는 파일로 보존하고 대화에는 필요한 일부만 전달한다. `review`의 첫 문제·미분류 예시에서 원본 인덱스를 받아 `evidence`의 제한된 범위를 조회한다. 같은 원인의 실패를 대상마다 반복해서 출력하지 않는다. 두 명령 모두 파일 해시를 반환하므로 읽은 근거를 연결할 수 있다.

스킬 본문은 공통 절차와 위 상세 조회 조건을 담고, 제어·합류·커버리지 사례는 조건부 참고 문서로 분리했다. 결정적 필터링·계산·집계는 Rust가 수행하고 에이전트는 기믹 해석과 불확실성에 집중한다. 보류 내용을 미리 읽거나 검사를 줄여 토큰을 아끼지 않는다. 실제 토큰 절감 효과와 스킬의 독립적인 작성 성공률은 아직 측정하지 않았다.

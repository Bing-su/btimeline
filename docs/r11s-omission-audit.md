# R11S occurrence and path omission audit

This audit records the inspection of the existing `out/r11s-tail.kdl`. It finds missing occurrences even when an ability ID already appears elsewhere in the output. The paths below identify local artifacts used at the time of the audit. Generator code was unchanged.

Reference timestamps are coordinates across label jumps, not elapsed fight time. This audit compares section identity, order and counts. For the shared section, offsets can be normalized to Charybdistopia/B425; no raw reference timestamp is compared directly with a generated elapsed timestamp. A reference `#Ability` row still displays an event; the comment disables its sync expression. Hidden movement/VFX rows are separated from mechanic damage rows below.

Observed counts below deduplicate identical `(trace, source, ability, millisecond)` signals, as the generator does. Casts split over adjacent milliseconds remain separate observations; they are not claimed to be extra mechanic occurrences. Reference counts identify intended mechanic waves; raw observations establish that the omitted section exists in the inputs.

## Facts, hypotheses and limits

| Status                         | Conclusion                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirmed                      | The occurrence/path losses above are visible by comparing primary reference section rows, existing KDL definitions, and input observations. They survive an ability-ID presence check.                                                                                                         |
| Confirmed                      | Evidence records later local choices as unresolved with reason `additional or non-raid choice requires phase and history support`, at joins B7BB, B425 and B459. This explains a declared unsupported area; it does not prove every nearby omitted occurrence requires a new choice mechanism. |
| Hypothesis for algorithm audit | Changes in order and in near-simultaneous group membership/multiplicity may make otherwise repeated mechanics fail forced alignment. Adjacent-millisecond B41C/B441/B447 splits are concrete data to test this against, not proof of one root cause.                                           |
| Not established here           | Whether every omitted observation can safely become a standalone event under the current execution model; whether helper support or a generic alignment change resolves all losses.                                                                                                            |
| Not checked                    | New generation, validation/compare runs, ACT packet equivalence, cactbot execution, live game behavior and all possible encounter paths. This document audits the saved artifacts only.                                                                                                        |

## Confirmed algorithm causes

| Cause                                                                         | Owning implementation                                                                                                                                                                                                                                               | Reproducing evidence                                                                                                                                                                                     | Consequence                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Near-anchor ambiguity rejects the entire interval                             | [`interval`](../src/generate/mining/occurrences.rs#L89) returns `unordered boundary` for any selected observation within 100ms of a bound; [`expand`](../src/generate/mining/occurrences.rs#L362) skips that whole interval                                         | In `4kt1bfqJn7QPCj29/2`, B453 is at 543554ms and the first B454 at 543599ms, 45ms later. Other kills show 43–49ms. Evidence reports B453→B459 unresolved.                                                | All six Atomic Impact waves and the later B456/B457 disappear even though the latter occur about 16 seconds after B453. Their own ordering is not the boundary problem.                                                                                                                  |
| A source without a unique common anchor never gets an alignment scope         | [`common::anchors`](../src/generate/mining/common.rs#L22) requires one occurrence per completed trace; [`expand`](../src/generate/mining/occurrences.rs#L337) builds source scopes exclusively from retained unique anchors                                         | Comet has B435, B438 and B43E, each repeating three nominal times. The KDL contains zero Comet-source events.                                                                                            | Three Cosmic Kiss and three Explosion occurrences are omitted despite being present in every trace. This is not missing input or a source-name mismatch.                                                                                                                                 |
| Exact-millisecond wave normalization leaves disjoint instances split by 1–2ms | [`Batch::waves`](../src/generate/mining.rs#L44) deduplicates only inside one exact timestamp; [`Group::unique`](../src/generate/mining/occurrences.rs#L78) refuses repeated signal identities in an uncertainty group, and group alignment requires equal multisets | Hk4XfbqzRBxgdJL2/17: B424 instance 9 at 150968ms, instances 1/2/3 at 150969ms; B449 instances 2/3 split between 451135/451136ms. 4kt1bfqJn7QPCj29/2: opening B41C instances split between 55159/55161ms. | A nominal wave becomes `{signal,signal}` in one trace and `{signal}` in others. Eye/Explosion, Massive Meteor, and some weapon/Majestic Meteor groups can lose correspondence. This is a demonstrated input to the rejection rules, not a claim that every lost row has only this cause. |
| Global intersection discards a mechanic when its observable ID varies         | [`Analysis::common`](../src/generate/mining.rs#L111), the exact Signal keys in alignment, and the first-choice-only limit in [`branches::discover`](../src/generate/mining/occurrences/branches.rs#L290)                                                            | NE Avalanche has two completed traces, SE three, SW one completed plus one incomplete, NW only one incomplete trace. Two-way and Four-way Fireball each have three completed traces.                     | The selected Avalanche castbar/resolution pair and both Fireball alternatives disappear. All mechanics have data, but individual alternatives have different support levels. NW has only one trace and cannot be claimed to satisfy a two-trace learning policy.                         |

The first two causes are separate: merely adding more branch support will not create a source scope for Comet, and will not bypass an interval already discarded by the boundary check. Likewise, adding more logs can introduce a millisecond split or a different alternative and shrink the global intersection; more data alone is not a coverage repair.

## Recommended follow-up order

| Priority | Generic work                                                                                                                                                               | Required regression example                                                                                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1        | Limit the effect of uncertain interval boundaries; evaluate the remaining interior without treating it as verified merely because a nearby boundary matches.               | A common anchor followed by X at +45ms, then five later X waves and Y/Z; prove the near-boundary uncertainty cannot silently discard the whole interior.                             |
| 2        | Make wave analysis account for instance provenance and packet-time uncertainty while retaining original times and counts. Do not merge all equal IDs within 100ms blindly. | Distinct instances split by 1–2ms, a real repeated cast by the same instance, and separate neighboring waves must remain distinguishable or explicitly unresolved.                   |
| 3        | Preserve choice-dependent future behavior across intermediate common events; represent supported local ID alternatives and weapon permutations.                            | A→shared→B versus B→shared→A; three-step permutations; alternative castbar/damage pairs. Do not invent unobserved combinations.                                                      |
| 4        | Align repeated helper-source observations against an established encounter context even when the helper has no unique anchor of its own.                                   | A boss with unique context plus a helper emitting X/Y three times, unrelated helper/trash, and missing context.                                                                      |
| 5        | Make acceptance checks account for occurrence and path losses.                                                                                                             | An ability emitted once must not satisfy a reference section that uses it twice or on another option; replaying all generated events must not imply full observed-mechanic coverage. |

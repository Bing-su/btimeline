# cactbot 분기·합류·루프 이탈의 시간 보정 조사

> 아래 조사는 이전 설계의 `on-exit`을 포함한다. 현재 문법에서 종료 신호 뒤 새 일정을 시작하는 방법은 [타임라인 스키마](../.agents/skills/timeline-author/references/timeline-schema.md#반복)를 따른다.

조사일: 2026-11-01. 기준은 로컬 `/home/ks2515/workspace/cactbot`의 커밋 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`이다. 조사 시 `git status --short` 출력은 비어 있었다. 링크는 해당 커밋의 소스 행으로 고정했다. 커밋된 타임라인을 게임 동작의 참조로 받아들이되, 작성자가 불확실하다고 명시한 부분은 그대로 제한한다.

**결론:** 조사한 사례는 option·merge·on-exit 안에서도 후속 sync에 의한 시간 보정이 필요함을 보여 준다. 그러나 각각 독립적으로 수정되는 clock이 필요하다는 증거는 없다. 선택된 경로의 상대 origin과 가장 가까운 phase/loop iteration의 공유 보정값을 조합하는 모델에 대한 반례는 이 표본에서 찾지 못했다. 따라서 설계상 **내부 재동기화는 유지하되, anchor별 독립 correction은 제거**하는 단순화가 이 근거와 부합한다. 이는 해당 모델의 btimeline 구현 검증이나 전체 전투에 대한 증명은 아니다.

## 공유 보정으로 표현하는 예

아래는 모델 추론이다. 보정 owner의 시작 기준을 `B`, option·merge·on-exit의 고정 상대 origin을 `O`, 행의 상대 시간을 `t`, 공유 보정값을 `Δ`라 두면 예측 시각은 `B + O + t + Δ`이다. sync 관측 시각이 `a`이면 `Δ = a - (B + O + t_sync)`로 갱신한다. origin은 보정 전 좌표로 보관해 같은 보정이 두 번 들어가지 않게 해야 한다.

Valigarmanda 이탈을 상대 `0.0`으로 놓으면 다음 보스 sync는 `+3.9`, Tulidisaster는 `+16.0`이다. 예를 들어 이탈 관측이 실제 `300.0`이고 보스 sync가 `304.9`라면, 보스 sync는 기존 예측 `303.9`보다 `1.0` 늦다. 같은 correction을 `+1.0` 갱신하면 Tulidisaster 예측은 `316.0`에서 `317.0`으로 움직인다. 이 수치는 설명을 위한 가상 관측이며 소스의 실측 로그가 아니다. 별도 on-exit correction 없이 후속 sync 효과를 표현할 수 있다.

| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 스키마에 반영한 결정

| 항목                                | 결정                                                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| option·merge·on-exit의 상대 시각    | 읽기 쉬운 작성 기준으로 유지한다. 진입 시 가장 가까운 phase 또는 회차 시간축의 좌표를 고정 기준점으로 저장한다.                             |
| 각 구간의 독립 보정값               | 제거한다. 내부 sync는 기준점과 상대 시각을 더한 목적 좌표로 공유 phase/회차를 보정한다. 같은 시간축의 다른 후속 이벤트와 window도 이동한다. |
| 분기별 서로 다른 시간표와 후속 sync | 유지한다. 최초 진입만 맞추고 후속 sync를 버리는 방식은 채택하지 않는다.                                                                     |
| 탈출 뒤 보정 대상                   | 종료된 반복 회차가 아닌 바깥 phase로 돌아간다. 종료한 반복은 다시 열지 않는다.                                                              |
| 독립적인 병렬 일정                  | 현 스키마의 보정 범위 밖으로 명시한다. 실제 필요한 사례를 찾으면 별도 설계하며 공유 보정으로 된다고 단정하지 않는다.                        |

다음은 Valigarmanda의 이탈 후 구간을 옮긴 작성 예다. 바깥 loop의 진입·탈출 조건은 생략한 조각이며 완성 전투 정의가 아니다. 표시 시각은 `1816.0 - 1800.0 = 16.0`, 중간 sync는 `1803.9 - 1800.0 = 3.9`다. window는 예시에서 명시한 2.5초를 사용한다.

```kdl
on-exit {
    event "tulidisaster-first" 16.0 name="Tulidisaster 1" {
        sync 3.9 "Ability" id="95B3" source="Valigarmanda" before=2.5 after=2.5
        sync 16.0 "Ability" id="8D67" source="Valigarmanda" before=2.5 after=2.5
    }
}
```

실게임·ACT·cactbot UI 실행, 로그 재생 및 btimeline 모델의 구현 적합성은 확인하지 않았다. 조사 결과는 위 커밋의 다섯 전투 타임라인과 공통 런타임 소스에 한정된다.

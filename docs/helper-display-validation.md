# 반복 기믹의 보조 발동 예고

2026-11-02, 구현 커밋 `690ae8e` 기준으로 이미 발견한 보스 반복에 다른 NPC의 발동 예고를 추가한다. 정확한 원본 재현이나 모든 회차의 완전한 관측을 요구하지 않는다. 기존 본체 진행·시계 보정은 유지하고, 보조 발동의 실용적인 표시 시각을 별도로 추정한다.

## 생성 정책

| 단계      | 처리와 의도                                                                                                                                                                                                                  |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위      | dungeon·alliance의 기존 보스 loop가 대상이다. 본체 시전으로 정한 회차에 원본 helper cast를 연결하며, helper 때문에 새 loop나 phase를 만들지 않는다.                                                                          |
| 보스 문맥 | 시전자 actor·instance·능력의 전체 cast/begincast 범위가 정확히 한 본체 시도 안에 있어야 한다. 보스 전후에 이어지는 배경 NPC 전투와 여러 보스에 걸친 모호한 범위는 추가하지 않는다. NPC 소속이나 적대성의 확정 증거는 아니다. |
| 발생 대응 | 한 회차 안에서 같은 활동의 첫째·둘째 발동을 따로 보존한다. 직전 본체 위치도 근거에 남기지만, 로그마다 다른 시전 사이에 끼어들거나 표시 이름이 달라도 연결할 수 있다.                                                         |
| 지지      | 두 입력 trace에서 관측되면 표시 후보로 삼는다. 같은 보고서의 다른 pull도 허용하며 별도 보고서 수는 진단에 기록한다. 모든 입력·회차에서 관측될 필요는 없다.                                                                   |
| 반대 근거 | 첫 회차에서만 관측되고, 두 trace 이상에서 완전히 관측한 회차에 빠지면 일회성·선택적 효과일 수 있어 보류한다. 미완성 회차의 부재는 반대 근거로 세지 않는다.                                                                   |
| 시간      | trace별 회차 상대 시각의 중앙값을 구한 뒤 trace 간 중앙값으로 0.1초 시각을 추정한다. 작은 지연 차이·정확한 인접 순서를 수용 기준으로 사용하지 않는다.                                                                        |
| KDL       | 독립적인 표시 event만 추가한다. helper source·actor ID·FFLogs 신호나 새로운 sync를 넣지 않는다. 본체의 기존 시계 보정으로 함께 이동하며 evidence 없이 미래 회차를 예고한다.                                                  |
| 실패      | 이름·시각 추정이 불가능하거나 회차 밖으로 추정되면 해당 표시만 보류하고 기존 loop는 유지한다. `loops[].helper_errors`에 사유를 기록한다.                                                                                     |

기술 이름이 같다는 이유로 기존 본체 event를 이동하거나 합치지 않는다. 실제 Mistwake에는 같은 이름의 Electrifying Flight가 회차의 서로 다른 위치에 있다. 보조 발동을 앞선 같은 이름 시전으로 합치면 정상 예고를 수십 초 이동시키게 된다. 별도 표시로 두면 본체 시전과 뒤의 발동을 모두 유지할 수 있다.

| 근거           | 위치                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| 원본 관측·분류 | 기존 `progression` 노드와 `unclassified`를 그대로 유지                                                  |
| 채택·보류 판단 | `loop_diagnostics[]`, `method="helper-display-context-v1"`                                              |
| 회차·발생 연결 | `loops[].model.helper_associations[]`: 활동·회차 내 발생 순번·원본 멤버·직전 본체 위치·미관측 완료 회차 |
| 실제 출력 연결 | `loops[].events[]`: `helper_association`, `sync=false`, 표시 offset·원본 노드 참조                      |

표시 연결을 채택해도 원본 미분류 NPC를 실행 신호로 승격하지 않는다. `enemyNPCs` 밖의 NPC, 이름 없는 NPC도 같은 규칙으로 표시할 수 있다. 소유자가 보고된 명단 밖 NPC와 시전 외 활동은 이 단계의 확장 대상이 아니다.

## 실제 로그 검증

대표 9개 콘텐츠·79개 입력을 재생성하고 구조 검사를 통과했다. 입력 목록·해시는 `out/manifest.json`, 이번 비교와 재생 결과는 로컬 `out/validation/helper-display/`에 있다. 모든 원본 진행 그래프와 기존 세 loop의 본체 event 근거가 동일하다. 전투별 ID·주기·이름을 생산 코드에 넣지 않았고 cactbot도 생성 입력으로 사용하지 않았다.

| 코퍼스            | 정의 수 변화 | 결과                                                                                                             |
| ----------------- | -----------: | ---------------------------------------------------------------------------------------------------------------- |
| Mistwake 12개     |      95 → 96 | Griffin의 Shock Storm 발동 한 정의, 원본 관측 12개를 연결. 기존 본체 예고·sync 유지                              |
| Clyteum 21개      |      80 → 90 | Malphas의 Scrap Gargoyle·Scrap Byblos 발동 10개 정의, 원본 관측 250개를 연결. 같은 활동의 회차 내 두 발동도 보존 |
| 나머지 7개 콘텐츠 |         동일 | R9S·R10S·R11S·Alexandria·Meso Terminal·Doomtrain 일반·Enuo 일반의 KDL 해시 유지                                  |

Mistwake의 helper는 반복 시작 기준 약 49.2초에 표시한다. 고정 cactbot 커밋 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`의 `mistwake.txt`에 있는 Shock Storm B0F4와 원본을 대조했다. 전체 참조 본문·다음 경계가 관측된 8개 범위에서 표시 대응이 **16/17 → 17/17**이 됐다. 이는 원본 노드의 표시 연결이며 helper를 sync로 출력했다는 뜻은 아니다.

| 재생                                         | 평가 원본 멤버 / helper | 보류 범위의 멤버 / helper | 최대 표시 차이: 전체 / 보류 |
| -------------------------------------------- | ----------------------: | ------------------------: | --------------------------: |
| Mistwake 기존 8개 학습 → 전체 12개           |                492 / 12 |                   156 / 4 |                 974 / 924ms |
| Mistwake 새 4개 학습 → 전체 12개             |                492 / 12 |                   336 / 8 |                 994 / 994ms |
| Clyteum 전체 21개                            |               808 / 250 |                         — |                   661ms / — |
| Clyteum 두 보고서의 3개 파일 보류, 18개 학습 |               808 / 250 |                   99 / 32 |                 654 / 613ms |
| Meso Terminal 전체 15개                      |                 132 / 0 |                         — |                 3,019ms / — |

위 재생의 예측 없음·5초 초과·ambiguous·unresolved·violation·skipped는 모두 0이다. 5초는 비교 보고서의 요약 지표이며 생성기의 정확도 요구 조건이 아니다. Mistwake는 보고서 집합이 겹치지 않는 양방향 분리다. Clyteum은 `Vr3G2DLgXtCf9YTa`와 `wN24cyJq6MxXR8AG` 보고서를 학습에서 제외했다. 재생기는 원본 cast를 Ability로 가정하고 보스 시도별로 투영한다. 활동별 가장 가까운 예고와 비교하며 일대일 경로 증명은 아니다.

```sh
bun scripts/replay_dungeon_loops.ts \
  out/validation/helper-display/final-fit8.evidence.json \
  out/validation/helper-display/final-mistwake.evidence.json \
  target/debug/btimeline out/validation/helper-display/final-fit8-replay.json
```

합성 회귀는 dungeon·alliance, 익명 시전자, 다른 기술 이름, 같은 보고서의 여러 pull, 발동의 순서 흔들림·일부 회차 누락·회차 안의 재발동, 배경 전투·겹치는 보스·일회성 효과·이름 추정 실패를 다룬다. evidence를 지운 뒤 진입 관측 하나만으로 미래 네 회차의 helper 예고가 발생하는지도 확인한다.

## 남은 범위

| 항목      | 한계와 다음 작업                                                                                                                                                                                                           |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 반복 가정 | Mistwake의 helper는 각 입력의 첫 회차에서만 직접 관측됐다. 다음 전체 발동 시점 전 전투가 끝나므로 부재를 실패로 보지 않는다. 후속 회차 예고는 보스 loop의 반복 문맥에서 추론한 것이며 직접 관측된 무한 반복 증명은 아니다. |
| 일반 귀속 | loop 밖의 유한 기믹, 여러 보스에 걸친 시전자, raid 전투 전체 loop의 helper는 남아 있다. 본체 loop가 아직 없는 두 일반 토벌전도 이번 변경으로 해결되지 않는다.                                                              |
| 선택·패킷 | 회차 내 발생 순번 대응은 누락으로 순번이 바뀌는 선택·복잡한 분절 패킷을 완전히 해결하지 않는다. 서로 다른 일정이 필요하면 조건부 진행 학습으로 확장한다.                                                                   |
| 실행      | helper의 새로운 runtime sync·신호 경쟁, 보스 처치에 따른 loop 종료, 실제 ACT 및 외부 실행기는 검증하지 않았다. 원본 그래프·표시 예측·실행 검증을 구분한다.                                                                 |

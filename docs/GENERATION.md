# 공통 시전 일정 생성: 첫 구현

현재 생성 경로는 수집 로그 → `mine`의 분석 그래프 → `generate`의 최종 스키마 KDL이다. 생성된 문서는 외부 실행기가 근거 파일 없이 사용할 수 있지만, 공통 시전의 표시 일정에 한정된 초안이다. 페이즈·분기·반복의 실행 구조와 시전 외 이벤트는 아직 생성하지 않는다.

```sh
btimeline mine first.json second.json -o process.kdl
btimeline generate process.kdl --template origin.kdl -o timeline.kdl
btimeline validate timeline.kdl
btimeline compare timeline.kdl recording.json
```

## 작성자가 제공하는 기준점

FFLogs fight 경계를 실행 시작 신호로 추측하지 않기 위해 기존 타임라인 스키마의 템플릿을 사용한다. 템플릿의 lifecycle은 그대로 보존한다. 아래는 합성 예시이며 실제 콘텐츠의 신호를 확인한 뒤 작성해야 한다.

```kdl
timeline 1 "Example" {
    start "Ability" id="B528" source="Synthetic Boss"
    wipe "ActorControl" command="4000000F"
    event "opening" 0.0 name="A"
}
```

| 항목          | 첫 구현의 조건                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| lifecycle     | 실제 실행기가 제공할 타입과 필드로 작성한다. start와 최소 하나의 초기화 신호(wipe·finish·zone-exit)가 필요하다. `FFLogs.*` 조건은 허용하지 않는다. |
| 기준점 이벤트 | 루트에 정확히 하나이며 시각은 0.0이다. 이름이 그래프의 유일한 공통 `cast` 이름과 정확히 같아야 한다.                                               |
| 시계 대응     | 작성자는 시작 조건의 실행 시각과 해당 FFLogs 시전 완료가 같은 기준점임을 확인해야 한다. 생성기가 신호 동등성을 검증하거나 변환하지 않는다.         |
| 구조          | 템플릿에는 start·wipe·finish·zone-exit과 기준점 이벤트만 허용한다. 기준점의 sync와 기존 본문을 재작성하는 기능은 아직 지원하지 않는다.             |
| 입력 그래프   | `process 1 algorithm=adjacent-batches`이며 둘 이상 완료 로그의 `observed-common-order`가 필요하다.                                                 |

동일 이름의 서로 다른 능력·시전자가 기준점 후보로 남으면 거부한다. 같은 이름이라는 사실만으로 ACT 시작 조건과 FFLogs 관측의 대응이 증명되는 것은 아니다. 템플릿의 잘못된 대응은 그대로 잘못된 시간축을 만들 수 있다.

## 생성과 근거

| 처리 | 동작                                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 일정 | 완료 로그마다 기준점 시전 시각을 빼서 상대 시각을 계산한다. 원본 fight 시작 시각을 실행 시계로 쓰지 않는다.                        |
| 시각 | 상대 시각의 아래쪽 중앙값을 선택하고 0.1초로 반올림한다. 정확히 중간이면 큰 값으로 반올림한다.                                     |
| ID   | 이름·NPC 이름·능력 ID를 조합한 ID를 사용하고 충돌은 오류로 보고한다. 템플릿 기준점 ID는 보존한다.                                  |
| 제외 | 시전 외 활동, 반복·누락 때문에 단일 공통 기준점이 아닌 활동, 어느 완료 로그에서라도 기준점보다 앞선 활동은 제외하고 이유를 남긴다. |
| 신호 | 생성 이벤트에 실행 신호를 추정해 추가하지 않는다. lifecycle은 템플릿에서 제공하며 본문은 표시 일정이다.                            |
| 저장 | 생성 후 기존 타임라인 파서로 검증하고 KDL과 `timeline.evidence.json`을 함께 새로 저장한다. 기존 파일을 덮어쓰지 않는다.            |

근거 파일은 그래프·템플릿·출력 KDL의 SHA-256, 기준점 대응 가정, 전투별 원본 시각·상대 시각, 중앙값·반올림 차이와 제외 사유를 담는다. 원본 이벤트는 기록된 그래프의 activity·trace를 통해 추적한다. 이 파일은 실행 입력이 아니다.

성공 종료와 `validate` 통과는 관측 완전성, 영어 이름 정확성, 실제 게임·ACT·외부 실행기 동작의 검증을 뜻하지 않는다. 표시 일정에는 시계 보정도 자동으로 추가하지 않으므로 전투 진행 속도 차이는 작성자가 검토해야 한다.

다음 명령은 합성 로그를 분석하고 생성된 KDL에서 근거 파일을 삭제한 뒤 재생·전멸·재시작을 검증한다.

```sh
cargo test --test generate collected_logs_generate_a_standalone_schedule_that_replays_and_restarts
```

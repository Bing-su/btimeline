# FFLogs에서 KDL 생성

`generate`는 FFLogs JSON 파일들을 직접 받는 엔드 투 엔드 명령이다. 입력 검사 → 공통 프로세스 분석·그래프 구성 → mode 정책 적용 → KDL 생성 → 구조 검증 → 저장을 한 번에 수행한다. 템플릿, 작성한 기준점, 중간 그래프 파일은 입력으로 요구하지 않는다.

```sh
btimeline generate first.json second.json --mode raid -o timeline.kdl
btimeline generate first.json second.json --mode dungeon -o timeline.kdl
btimeline generate first.json second.json --mode alliance -o timeline.kdl
btimeline generate first.json second.json third.json --mode raid -o timeline.kdl
```

| 입력        | 계약                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| JSON 파일들 | 기존 수집 완료·페이지·액터·전투 범위 검사를 통과해야 한다. 현재는 같은 encounter·난이도의 전투들을 한 번에 받는다. |
| mode        | `raid`, `dungeon`, `alliance` 중 하나. 필수 정책 입력은 이것뿐이다.                                                |
| 출력 경로   | KDL과 같은 이름의 `.evidence.json`을 새로 저장한다. 기존 파일을 덮어쓰지 않는다.                                   |

`mine`은 동일한 분석 결과를 사람이 확인할 때 쓰는 선택적 명령이다. 생성기가 디스크에 중간 KDL을 기록하거나 그 파일을 다시 읽지는 않는다.

## 대표 경로 초안과 evidence v3

`generation_method`는 실제 KDL을 만든 경로다. `representative-route-v1`은 대표 그래프, `common-backbone-v1`은 이행 중인 기존 생성 경로다. evidence에 `draft`가 있다는 사실만으로 최종 KDL이 그 그래프에서 생성됐다고 해석하지 않는다.

단일 유효 로그는 처치 여부와 관계없이 한 경로의 초안을 생성한다. 여러 로그의 발생 순서가 같거나 종료로 잘린 접두부이면 원본 노드를 대응해 표본을 모으며 두 개의 클리어를 요구하지 않는다. raid는 실행 적격 시전 전체, dungeon·alliance는 구분 가능한 보스 시도별 발생을 보존한다. 반복 시전도 개별 발생으로 표시하되 하나의 로그만으로 무한 loop를 확정하지 않는다. 시간 추정은 별도 함수에서 수행하고 같은 신호의 반복 발생에는 자동 sync를 붙이지 않는다.

```sh
btimeline generate long-wipe.json --mode raid -o draft.kdl
```

| evidence v3 필드                | 의미                                                                                                                   |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `progression`                   | 기존 trace별 원본 발생·부분 순서. 미분류·미출력 관측도 보존                                                            |
| `draft.routes`                  | 전투 또는 보스별 대표 한 경로. 활동·발생 순번·원본 노드 참조·확실한 선후 관계만 저장하며 예정 시각은 없음              |
| `draft.diagnostics`             | 대표 후보의 실제 시전 관측 범위·파동 수와 시도 범위 진단                                                               |
| `draft.routes[].peers_complete` | 해당 범위의 모든 적격 후보가 같은 순서의 전체 또는 종료 접두부로 대응됐는지 표시. 전체 경로 완성의 보장은 아님         |
| `draft.routes[].choices`        | 공통 뼈대의 `after`·`join` 노드와 선택지별 발생 그래프. 선택지에도 원본 노드 참조와 선후 관계를 보존하며 시간표는 없음 |
| `draft.routes[].repeat`         | 지원된 말단 반복의 진입 노드·본문·순서 변형 블록·trace별 원본 파동 참조. 시간표·고정 회차 수는 없음                    |
| `coverage=unconfirmed`          | 긴 진행 후보이며 전멸기 도달·경로 완성을 확인했다는 뜻은 아님                                                          |

대표 선택은 실제 시전 관측 범위 → 파동 수 → report/fight 순이다. raid는 전투 시작부터 마지막 적격 시전까지, 보스는 자신의 첫 시전부터 마지막 시전까지 비교한다. 긴 무관측 꼬리·처치 여부를 우선하지 않는다. 입력 순서와 무관하며, 겹치는 본체 개체나 미해결 시도 범위는 대표로 채택하지 않는다. 미분류 후보는 원본에만 유지한다.

같은 발생 순서로 대응된 노드는 여러 trace의 원본 참조를 가진다. 선후 관계는 대응된 모든 trace에서 확실한 관계의 교집합이다. 대표에서 A→B→C여도 다른 로그에서 A·B가 근접하면 A→C와 B→C만 유지할 수 있다. 최종 시각은 이 대응을 입력으로 별도 추정한다.

짧게 끝난 로그는 발생 순서가 대표의 정확한 접두부이고, 다음 발생의 추정 시각보다 관측 범위가 먼저 끝난 경우에만 종료 접두부로 대응한다. 마지막 대응 발생을 기준으로 같은 전체 경로 표본 각각의 다음 간격을 옮기고 가장 이른 시각을 사용한다. 던전·연합레이드는 확인된 본체 처치가 있으면 보스 시도 종료를 사용한다. 관측이 그 시각까지 계속됐는데 다음 발생이 없으면 미해결이다. 대표의 후반 노드는 유지하며 짧은 trace의 표본을 만들지 않는다. `representative-route-correspondence-v2`에 `censored`·종료·다음 추정 시각을 기록한다. 이는 원본 대응을 위한 종료 검열이며 가짜 runtime 탈출 신호가 아니다.

### 대표 그래프의 순서 선택

raid의 전투 경로와 dungeon·alliance의 보스별 경로에서 완료된 발생열들의 시전 집합은 같고 순서가 다르면 공통 접두부·접미부 사이를 선택 구간으로 학습할 수 있다. 동일 NPC의 시전으로 구성하고 선택지의 첫 신호와 공통 후속 신호는 각 trace에서 한 번만 관측돼야 한다. 선택 구간·인접 경계에서 100ms 이내의 순서 불확실성이 있거나, 같은 첫 신호가 서로 다른 선택지를 가리키면 보류한다. 전체 경로의 발생 수 차이는 아직 이 학습에 통합하지 않는다.

| 범위             | 선택 시계·배치                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| raid             | combat 시작 기준 window. 공통 접두부 없이 첫 선택부터 시작할 수 있음                                     |
| dungeon·alliance | 보스의 공통 첫 시전 기준 window. 해당 보스 phase에만 분기를 배치하며 공통 진입이 없는 도입부 선택은 보류 |

보스 window는 각 trace의 원본 시각에서 보스 진입 시각을 뺀 뒤 0.1초로 반올림한다. 이전 보스·이동 시간은 포함하지 않는다. 진입 이후의 경쟁 선택 신호는 계속 검사하며, 다음 보스 phase 진입은 이전 보스의 선택·일정을 취소한다. 선택지 본문은 두 mode 모두 실제 선택 시각 기준이다.

`A B C D` / `A C B D`는 A·D를 공유하고 B→C / C→B를 선택지로 보존한다. `A X M Y D` / `A Y M X D`는 중간 M을 포함한 전체 차이를 한 선택 구간에 두어 미관측 조합을 만들지 않는다. 실제 실행에서 선택 신호가 없으면 선택지를 추정하지 않으며 공통 후속 일정은 진행한다. `representative-order-choice-v1`에 학습 범위·옵션 수를 기록한다.

먼저 전체 경로들로 선택 구조를 학습한 뒤 짧은 로그를 대응한다. 실제 관측이 일치하는 전체 경로 각각에서 다음 간격을 옮기고 가장 이른 시각보다 종료가 먼저인지 검사한다. 선택 본문을 제거한 공통 뼈대의 다음 스킬로 종료 판단을 미루지 않으며, 다른 선택지의 간격으로 현재 선택지의 누락을 판단하지 않는다. 서로 경쟁하는 첫 선택 신호가 100ms 이내이면 기록 순서로 선택을 확정하지 않는다.

| 종료 위치       | 원본 참조 연결                                 | 선택 상태                                                    |
| --------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 선택 전         | 관측된 공통 접두부만 연결                      | `selection=unobserved`. 어느 선택지에도 넣지 않음            |
| 선택 후·합류 전 | 공통 접두부와 해당 선택지의 관측된 본문만 연결 | `selection=observed`, `option_trigger`에 실제 선택 신호 기록 |
| 합류 후         | 선택지 본문과 관측된 공통 후반 접두부까지 연결 | 관측하지 않은 후속 발생·시각은 만들지 않음                   |

연결 후 선후 관계를 다시 계산한다. `representative-choice-prefix-v2`에 종료·다음 추정 시각·지지 trace 수와 선택 상태를 기록한다. 다음 발생이 관측 범위 안에 예정되거나 관측열이 어떤 경로의 접두부와도 맞지 않으면 미해결이다. 선택지의 표시 시각은 `timing_policy=observed-option-join`에 따라 실제 합류까지 관측한 표본으로만 추정한다. 길이가 다른 접두부 표본을 섞어 중앙값의 순서가 뒤집히지 않게 하며, 짧은 로그의 원본 대응은 그래프와 `alignment.supported_observation_nodes`에 보존한다. 선택 window에는 짧은 로그의 실제 선택 관측도 사용한다. 각 선택지는 최소 한 개의 실제 합류 표본이 필요하며 미관측 합류 시각을 합성하지 않는다.

선택 그래프를 구성한 뒤 원본 노드에서 시각 표본을 읽어 기존 window 검사·branch 렌더러에 전달한다. 전체 trace의 선택 신호를 검사해 이전·이후의 다른 선택뿐 아니라 같은 선택 신호의 다른 발생도 window 밖에 둔다. 선택지의 표시는 선택 시각 기준이며 새 sync는 만들지 않는다. evidence 없이 다음 스킬을 예고하는 재생으로 검사한다.

지원하는 순서 선택은 클리어 수와 관계없이 대표 그래프에서 KDL을 생성하고 기존 선택 이력 사후 패치로 덮어쓰지 않는다. 순서 선택이 없는 단일 로그·클리어 두 개 미만의 동일 경로/종료 접두부도 대표 그래프를 사용한다. 그 밖의 다중 로그는 아직 아래 기존 분석을 사용한다. 클리어 두 개 미만에서 지원하지 않는 순서·내부 누락·불명확한 접두부는 명시적인 미지원 오류로 종료한다. 나머지 통합은 [변경 계획](REPRESENTATIVE_PATH_PLAN.md)을 따른다.

### 대표 그래프의 말단 반복

기존 말단 반복 분석이 두 trace 이상의 완전한 회차·후속 경계·두 단계를 확인하면, 대표 그래프에 `repeat`로 연결할 수 있다. 처치 로그를 요구하지 않으며 회차 수·내부 순서 변형이 다른 전멸 로그도 사용한다. 대표 선택은 반복을 접기 전의 관측 범위·파동 수로 수행한다.

| 구조      | 근거·생성 규칙                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 유한 경로 | opener와 첫 반복 경계만 유지. 서로 다른 opener는 기존 경로·선택 대응을 통과해야 함                                                     |
| 반복 본문 | `body`와 `blocks`로 기존에 검증된 본문·순서 변형을 보존. 아직 반복 안 선택 이력은 추론하지 않음                                        |
| 원본 연결 | `observed_waves`에 trace별 시간순 파동의 원본 노드 인덱스를 저장. 마지막 미완성 회차도 실제 관측만 기록                                |
| 진입      | `entry`는 유한 경로의 첫 반복 경계 노드. 현재 trace별 한 episode·단일 관측 경계만 연결하며 다중 시도·분절·동시 경계는 기존 분석에 남김 |
| 안전성    | 반복 이후에 설명되지 않은 실행 대상 발생이 있으면 접지 않음. 연결된 반복의 시간 추정·KDL 배치가 실패하면 출력 전체를 저장하지 않음     |

반복 스케줄러는 이 구조를 지지한 기존 episode의 원본 시각으로 시작·주기·window를 별도 추정한다. 유한 경계 이벤트를 생성된 무한 `loop`로 대체하며 evidence 없이 미관측 다음 회차를 예고한다. `loops[].replaced_finite_events`로 대체를 추적한다. 일반적인 반복·탈출·helper의 그래프 통합과 반복 경로의 보고서 보류 검증은 아직 미지원이며 `automatic-draft-validation-v1.not_checked`에 반복 경로 검사를 명시한다.

합성 예고 재생과 실제 코퍼스 생성 회귀의 범위는 [대표 반복 검증](REPRESENTATIVE_REPEAT_VALIDATION.md)에 구분한다.

### 대표 분기 그래프의 독립 검증

대표 그래프에서 순서 선택을 생성할 때 `alignment_diagnostics`에 `automatic-draft-validation-v1`을 기록한다. 보고서가 세 개 미만이면 `insufficient-reports`다. 세 개 이상이면 report code의 사전순 마지막 보고서에 속한 모든 fight를 먼저 보류하고, 나머지 입력만으로 발생 저장·대표 선택·그래프 학습을 다시 수행한다. 처치 로그는 필수 조건이 아니다.

`split`에 학습/보류 trace를, `model`에 임시 학습 그래프를, `checks`에 보류 trace·`source`별 결과를 기록한다. raid의 `source`는 null, dungeon·alliance는 보스 이름이다. 학습·검증은 동일한 보스 시도 범위·접두부 규칙을 사용하되 보류 관측은 임시 모델에 연결하지 않는다. 보류 입력에만 있는 보스도 `unresolved`로 보고하며 임시 학습 그래프에 추가하지 않는다.

| 결과         | 검사한 범위                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| `matched`    | 정규화된 전체 시전열이 임시 모델의 관측 경로 중 하나와 일치                                           |
| `censored`   | 관측된 접두부가 일치하고, 모든 대응 학습 경로의 다음 발생 전에 종료됨. 미관측 후반을 검증한 것은 아님 |
| `unresolved` | 미학습 순서·미완료 모델·선택 순서 불확실성·관측 범위 안의 예정 발생 누락 등                           |

`scope_end_ms`, `next_expected_ms`, `supporting_traces`로 종료 판단을 추적한다. 최종 생성은 전체 입력을 사용하므로 임시 모델의 미해결 경로가 최종 그래프에서 표현될 수 있다.

이 검사는 최종 KDL의 window·시간·예고, loop 실행, ACT 신호 동등성이나 보고서 간 통계적 독립성을 검증하지 않는다. 새로운 경로를 보고 모델을 수정한 뒤 같은 입력을 계속 독립 검증으로 세지 않는다. 기존 생성 경로의 `automatic-validation-v1`은 아래의 참조 정렬 검사로 유지한다.

## 진행 구조와 시간 추정의 분리 계획

구현은 [진행 그래프와 시간 추정의 분리 계획](PROGRESSION_AND_TIMING.md)을 따른다. trace별 모든 시전 파동 후보와 부분 순서를 먼저 보존하고, 출력 후보를 노드에 연결해 별도 시간 추정기로 전달한다. dungeon·alliance의 제한적인 말단 반복도 유한 출력 압축이 아닌 원본 발생 문맥에서 먼저 학습한다. evidence의 `progression`, 이벤트별 `observation_nodes`, `loops`의 회차별 대응으로 추적한다. raid의 제한적인 유한 블록 순서·선택 이력은 아래 `histories` 모델로 생성한다. 고유 시각 기준점이 없거나 시간 추정이 실패해도 원본 그래프는 변하지 않는다. 일반적인 선택 이력과 반복의 통합 학습, 시간 추정 실패의 부분 출력은 아직 미구현이다.

**시간은 정확히 재현할 필요가 없고 사용하기에 충분하면 된다.** 작은 기록 차이를 제거하고 기믹의 순서·선택·회차를 알아볼 수 있는 근사 일정을 목표로 한다. 0.1초는 표현 단위이며 실제 전투와 100ms 이내로 맞춘다는 보장이 아니다. 표시 시각의 실용성과 sync·window의 실행 안전성은 별도로 검증한다. 원본 시간은 파동·부분 순서·종료 판단에도 계속 사용하며 보존한다.

이는 작은 오차만 허용한다는 뜻이 아니다. 같은 진행 위치를 가리킨다는 근거가 있으면 수 초·수십 초의 차이도 시계 보정으로 다룰 수 있어야 한다. 같은 ID의 다른 회차·선택과 구분할 구조적 근거는 계속 필요하며, 큰 보정을 허용한다고 window를 무조건 넓히지는 않는다. 원본 대응이 여러 가지여도 표시·실행 결과가 실용적으로 같으면 그 모호함 때문에 구조를 버리지 않는 방향으로 구현한다.

입력은 기존처럼 FFLogs JSON과 mode만 받는다. 새 그래프·시간표를 수동 입력으로 요구하거나 KDL 실행에 evidence를 의존시키지 않는다. 이 계획은 기존 runtime 시계·시간 단위·문법을 바꾸지 않는다.

## 게임 신호와 mode 정책

cactbot의 고정 커밋 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`를 참고한다. [R9S](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/data/07-dt/raid/r9s.txt#L8-L14)와 [Valigarmanda](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/data/07-dt/trial/valigarmanda.txt#L13-L16)는 InCombat 시작, 시전·능력 ID와 NPC 이름에 의한 동기화를 사용한다. 아래 표는 이 근거를 사용하는 생성기의 정책이며 cactbot의 모든 콘텐츠에 동일한 규칙이 있다는 뜻은 아니다.

| mode       | 시작과 시각 기준                                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `raid`     | `InCombat inGameCombat="1"`로 시작한다. FFLogs fight 시작에 대한 상대 시각을 최초 일정으로 삼고 능력 관측으로 시계를 보정한다.                                              |
| `dungeon`  | FFLogs의 적대 액터 중 `subType=Boss`인 이름을 보스 범위로 삼는다. 보스별 phase와 시전 진입 조건을 만들고 각 로그·보스의 가장 이른 공통 시전을 그 phase의 상대 0으로 삼는다. |
| `alliance` | 던전과 같은 보스별 phase·시전 진입 정책을 사용한다. 보스 내부의 추가 페이즈는 아직 추론하지 않는다.                                                                         |

일반·극 토벌전도 `raid`를 사용하며 별도 trial 모드는 두지 않는다. 반복 여부는 mode가 아니라 원본 문맥에서 학습한다. mode는 전투 전체 또는 개별 보스의 분석 범위와 시작 시계를 정한다. 제한적인 말단 반복 발견은 모든 mode에서 실행한다.

보스 기준점으로 먼저 나타난 능력이 로그마다 다르면 해당 ID·NPC 이름 조건들을 start와 phase enter의 OR 대안으로 생성한다. 모든 보스의 진입 조건을 start에도 두므로 둘째 보스에서 전멸해도 그 보스부터 재시작할 수 있다. 보스 사이 이동 시간은 보스 시계에 포함하지 않는다. 잡몹 시전은 보스 본문에서 제외하고, Boss 메타데이터가 없으면 임의의 NPC를 보스로 추정하지 않고 오류로 보고한다. 표시 이름을 입력 매칭 키로 사용하지 않는다.

첫 고유 기준점 앞의 반복도 보스 자신의 첫 시전부터 표시 정렬한다. 복원된 가장 이른 공통 발생이 반복 ID여도 phase 진입 신호로 사용할 수 있으며 활성 phase의 같은 진입 신호는 다시 시작하지 않는다. 이 진입 허용은 반복 발생의 event sync 허용을 뜻하지 않는다. 이전 보스의 phase 경계와 이동은 이 보스 도입부에 포함하지 않는다. 고유 공통 시전이 전혀 없는 보스는 동일한 단일 진입 묶음을 확인한 뒤 후속 발생을 강제 정렬해 표시한다. 진입 자체가 다르거나 모호하면 그 보스는 미해결로 남긴다. [Clyteum 누락 감사](CLYTEUM_OMISSION_AUDIT.md)에 개선 범위와 전체 입력 재검증 결과를 함께 기록한다.

이는 [cactbot의 던전·연합레이드 진입 구분](CACTBOT_LIFECYCLE_RESEARCH.md)을 참고한 생성 정책이다. FFLogs에 없는 봉인 메시지의 파라미터를 만들어내는 대신 수집 자료의 Boss 분류와 실제 시전을 사용한다. 이미 발견한 dungeon·alliance 보스 반복 안에서는 [helper 표시 연결](HELPER_DISPLAY_VALIDATION.md)을 지원한다. 일반적인 helper 소속·실행 신호 판정은 아직 지원하지 않는다.

### 명단 밖 NPC의 관측과 실행 적격성

FFLogs의 `enemyNPCs`는 모든 기믹 시전자의 목록이 아니다. 기존 적대 관측에 없는 시전자 중 양수 actor ID·`type=NPC`·보고된 소유자 없음(`petOwner` 누락 또는 null)을 만족하는 비근접 `cast`와 `begincast`를 미분류 후보로 보존한다. 이를 적대 NPC나 특정 보스의 helper로 확정하지 않는다. Player·소유자가 보고된 NPC·Environment를 새 후보로 추가하지 않으며 기존 적대 목록의 선택 규칙은 유지한다. 능력 ID와 메타데이터 참조는 검사하고 원본 인덱스·시각은 보존한다.

| 경계        | 처리                                                                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 원본 후보   | `analysis.inputs[].observations[].unclassified_indices`에 해당 원본 event 인덱스를 기록한다. `begincast`도 남지만 현재 발생 그래프 노드는 `cast`만 사용한다.                                                                         |
| 발생 그래프 | `progression.traces[].nodes[].unclassified=true`는 그 신호·시각의 관측이 모두 미분류임을 뜻한다. 같은 NPC 이름·ID·시각에 기존 적대 관측도 있으면 노드는 공유하고 false다. 미분류 멤버 자체는 원본 인덱스로 계속 구분한다.            |
| 이름 누락   | 적대 명단에 있는 NPC도 이름이 비면 cast·begincast를 미분류로 남기고 `source=null`로 보존한다. 이름 없는 상태·징표·연결의 endpoint도 null이다. ID로 가짜 이름을 만들거나 원본 관측을 제거하지 않으며 실행용 source로 승격하지 않는다. |
| 학습 뷰     | 미분류 신호와 원본 멤버를 제외하되 비어 있는 batch도 유지해 인덱스가 이동하지 않게 한다. 기존 공통 정렬·보류 검증·loop 학습과 `mine`의 `common-progress`는 이 뷰를 사용한다.                                                         |
| 검토 자료   | `mine`의 원본 DFG·발생·반복 후보에는 관측을 유지하고 `observed` 아래 `unclassified`에 원본 event 인덱스를 둔다. 원본 인접 관계는 소속이나 실행 가능한 반복의 증명이 아니다.                                                          |
| 출력        | 전부 미분류인 활동은 기본적으로 제외 사유를 기록한다. 아래 반복 문맥의 표시 예외를 지원하되 자동 sync는 만들지 않는다. 일부 기존 관측과 활동 키가 같더라도 본체 학습에는 기존 적대 멤버만 사용한다.                                  |
| 후속 판정   | 보스 소속·반복 문맥·다른 신호와의 경쟁을 별도로 검증해야 한다. 시간 근접도만으로 귀속하지 않는다. 미분류 관측까지 고려한 runtime sync 경쟁 검증은 아직 미구현이다.                                                                   |

`inspect`의 적대 시전·pairing 범위와 원본 FFLogs 재생 계약은 바꾸지 않는다. 이 확장은 생성·mining의 관측 후보 경계이며 최종 KDL의 새 실행 신호나 필수 입력을 추가하지 않는다.

### 반복 안 helper의 표시 연결

이미 학습한 dungeon·alliance 보스 loop에, 본체 시도 안으로 범위가 한정된 다른 NPC의 cast를 표시용으로 추가한다. 같은 회차 안의 발생 순번을 대응하고 두 입력 trace에서 지지하면 후보로 삼는다. 같은 기술 이름·정확한 인접 순서·모든 로그의 관측 일치를 요구하지 않는다. 첫 회차에만 나타나면서 두 trace 이상의 완료 회차에 빠지면 일회성·선택적 효과일 수 있어 보류한다. 미완성 회차의 부재는 허용한다.

표시는 회차 상대 시각의 중앙값으로 추정한다. 본체 event·sync는 그대로 두고 helper의 sync는 만들지 않는다. 원본 미분류와 그래프도 유지하며, 추정 실패는 해당 표시만 보류하고 `loops[].helper_errors`에 남긴다. 이름이 같은 본체 시전을 합치거나 이동시키지 않는다. 이 연결은 유용한 반복 예고를 위한 가정이며 적대성·소속·모든 미래 회차를 증명하지 않는다. [정책·근거 필드·독립 로그 검증·남은 한계](HELPER_DISPLAY_VALIDATION.md)를 함께 확인한다.

### 보스 시도 범위와 고유 시전 없는 진행

| 항목           | dungeon·alliance의 학습 정책                                                                                                                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 본체           | 적대 `subType=Boss` actor 중 입력 검사에서 식별한 가상 helper를 제외한다. 가상 helper는 Boss로 표시되더라도 본체 종료를 정하지 않으며 시전 관측은 보존한다. actor ID·instance는 분석용이며 runtime 신호에는 NPC 이름을 쓴다.                                      |
| 시도           | 본체의 actor/instance별 첫 cast·begincast와 관측 범위를 추적한다. 없는 instance는 단일 개체 1로 취급한다. 겹치는 개체 관측은 재시도로 확정하지 않고 기존 파동 분석에 남긴다.                                                                                      |
| 처치           | 본체를 target으로 하는 death 또는 damage의 `targetResources.hitPoints=0`을 확인한다. 여러 instance가 있으면 targetInstance 없는 종료를 임의로 대응하지 않는다.                                                                                                    |
| 학습 범위      | 이름별 완료 본체 시도가 하나면 그 시작부터 처치까지의 관측을 학습한다. 여러 완료 시도나 구분되지 않는 재시도는 해당 이름의 범위를 보류한다. 단일 개체에 종료 관측이 없으면 기존 범위를 유지한다. 입력 파일 자체를 제외하지 않는다.                                |
| 원본 보존      | 원본 발생 그래프와 batch·event 인덱스는 유지한다. 학습용 뷰에서만 신호를 제한하고 `boss-attempt-scope-v1`에 본체·instance·시작·처치 인덱스와 선택 범위를 기록한다. 처치 뒤 helper도 원본에 남지만 이 학습 범위에는 포함하지 않는다.                               |
| 고유 시전 없음 | 첫 보스 묶음이 모든 완료 학습 입력에서 같은 단일 활동이면 그 진입을 구조 기준으로 사용한다. 관측 묶음 수가 가장 적은 완료 경로를 참조로, 진입 이후 모든 최적 다중집합 LCS의 강제 대응만 표시한다. 동률은 trace 이름으로 정한다. 시간 근접도로 동률을 깨지 않는다. |
| 표시와 한계    | `boss-entry-lcs-v1`은 고유 기준점이 없는 NPC에만 적용한다. 반복 ID에 event sync를 만들지 않으며 조건부 경로·반복 구조·참조보다 긴 후반을 새로 추론하지 않는다. 다른 ID의 이름이 같다는 이유로 합치지 않는다.                                                      |
| 시각·ID        | 시각은 원본 노드 참조로 별도 추정한다. 출력 발생 번호는 선택한 시도의 참조 순번이고 그래프 노드의 회차는 원본 trace 전체 순번이다. 두 번호를 동일시하지 않는다.                                                                                                   |

이 범위는 분석상의 종료다. KDL에 처치·전멸 신호를 합성하지 않으며 외부 실행기가 FFLogs 자료를 필요로 하지 않는다. 실제 runtime 처치 신호가 없는 생성본은 보스가 죽은 뒤에도 다음 phase 진입까지 미래 표시가 남을 수 있다. [Clyteum 감사](CLYTEUM_OMISSION_AUDIT.md)에 이 한계를 수량으로 기록한다.

| 전멸·재시작   | `ActorControl command="4000000F"`와 구버전 `40000010`을 wipe 조건으로 둔다. [cactbot 공통 wipe 정의](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/resources/netregexes.ts#L675-L680)를 따른다. |
| 구역 변경     | `zone-exit "ChangeZone"`으로 상태를 초기화한다. [로그 타입 정의](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/resources/netlog_defs.ts#L190-L209)에 근거한다.                                  |
| 시전 완료     | FFLogs의 시전 후보에서 능력 ID를 16진수로, NPC를 이름으로 표현해 `Ability` 동기화를 생성한다. 보고서별 actor ID를 매칭에 쓰지 않는다.                                                                                                    |
| 동기화 window | 각 로그의 상대 관측 시각을 포함하도록 잡고 양쪽 최소 2.5초를 둔다. raid의 첫 동기화는 R9S의 도입부 사례처럼 양쪽 최소 10초로 최초 시계를 보정한다.                                                                                       |

비전투 전환을 무조건 전멸·종료로 생성하지 않는다. 중간 비전투 때문에 cactbot의 자동 리셋을 끄는 [Kuribu 사례](CACTBOT_LIFECYCLE_RESEARCH.md)가 있으므로 현재 공통 리셋은 명시적인 wipe와 구역 변경에 한정한다. 처치 종료와 콘텐츠별 lifecycle 예외의 자동 처리는 남아 있다.

## 표시 보존과 동기화 검증의 개선 정책

[기법·구현 순서](PROCESS_MINING_TECHNIQUES.md#누락-감사-이후의-우선순위)와 [실제 누락 감사](R11S_OMISSION_AUDIT.md)를 함께 따른다. 표시 일정의 근거가 충분해도 시계 보정 근거가 부족하면 sync 없이 생성한다. 이 원칙은 모든 모호한 후보를 출력한다는 뜻이 아니다.

| 항목             | 현재 구현                                                                                                                                                                            | 후속 구현                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 경계의 시간 근접 | 인접 기준점 사이 표시용 정렬은 근접 관측을 포함하고 내부의 강제 대응을 보존한다. 정확한 양끝 시각의 묶음은 제외한다. 분기 선택·참조 검사·종료 검열 학습은 기존 경계 검사를 유지한다. | 경계 묶음의 구성원을 포함한 부분 순서 대응                                 |
| 파동             | 원본은 정확한 밀리초로 보존하고, 표시 정렬에서는 다른 trace의 지지와 개체 정보를 확인해 분절을 대응한다.                                                                             | 인스턴스·시전·시간 불확실성을 함께 사용한 파동 후보 분석                   |
| 대응             | 묶음 전체의 모든 최적 LCS 대응을 검사한다.                                                                                                                                           | 부분 순서와 국소 비용 정렬로 확인된 구성원만 보존하고 동률·반례를 추적     |
| 선택 이력        | 한 국소 분기만 생성한다.                                                                                                                                                             | 선행 선택의 영향을 공통 구간 너머까지 학습하고 기존 option/requires로 표현 |
| 보조 액터        | 자신의 공통 기준점이 없으면 본문을 생성하지 못한다.                                                                                                                                  | 확인된 전투 문맥과 반복 관측을 연결                                        |

원본 시각과 파동 개수, 실제 반복·종료 검열 구분을 보존한다. 최저 비용 하나를 기믹의 정답으로 확정하거나 드문 경로를 빈도만으로 삭제하지 않는다. 분석 보완은 기존 KDL의 공유 시계·신호 의미를 바꾸지 않으며 새로운 사용자 설정을 요구하지 않는다.

## 현재 생성 범위와 근거

| 항목      | 동작                                                                                                                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 공통 진행 | 둘 이상의 완료 로그에서 고유 공통 시전을 기준점으로 삼는다. 순서가 충돌하면 모든 최장 공통 순서 사슬에 포함되는 기준점만 공통 뼈대로 삼고 나머지는 국소 분기 분석·미해결 근거로 남긴다. 같은 NPC의 인접 기준점 사이에서는 모든 최적 삽입·삭제 정렬에서 강제되는 시전도 생성한다. |
| 시각      | mode 기준점에 대한 상대 밀리초의 아래쪽 중앙값을 선택하고 0.1초로 반올림한다. 정확히 중간이면 큰 값으로 정한다.                                                                                                                                                                  |
| ID        | 이름·NPC 이름·능력 ID를 조합한다. 정렬로 추가한 시전에는 기준 로그의 발생 순번(`-01` 등)을 붙인다. 구간별 참조가 같은 순번을 재사용하면 `after-…`·`before-…` 기준점 ID를 더한다. 구분 후에도 충돌하면 오류다. 이 번호는 게임의 반복 회차가 아니다.                               |
| 제외      | 시전 외 활동, 대응 미확정 관측, 보스 mode의 잡몹·미할당 helper와 공통 시전이 없는 보스의 이유를 근거에 남긴다. 일부 발생이 출력된 능력도 나머지 미대응 발생을 별도로 추적한다.                                                                                                   |
| 검증·저장 | 최종 KDL을 기존 파서로 검증한 뒤 KDL과 근거를 함께 저장한다. 실패 시 일부 새 출력만 남기지 않는다.                                                                                                                                                                               |

근거 JSON 버전은 2다. mode, 정책 기준 버전, 원본 입력 경로·해시·관측 인덱스, 분석 그래프 통계, 전투별 기준점·원본 시각·반올림 차이와 제외 사유를 보존한다. 입력 로그의 원본 이벤트는 해시와 인덱스로 추적하며 전체 원본 패킷을 출력마다 복제하지 않는다. 근거 파일은 실행 입력이 아니다.

원본 관측과 고유 기준점용 시각표는 정확히 같은 원본 밀리초의 동일 신호·NPC 이름을 한 파동으로 센다. 개체 수가 로그마다 달라도 표시 일정은 대응할 수 있다. `observations.signals`의 multiplicity·인덱스와 `alignment.waves`의 대표 batch·instances는 보존한다. instances는 적중 횟수를 뜻하지 않는다. `mine`의 원본 그래프 빈도는 개체 관측 수를 유지한다.

인접 고유 기준점 사이의 표시 정렬은 다음 조건을 모두 만족하면 다른 밀리초에 분절된 개체 관측도 한 표시 파동으로 대응시킨다. 이는 관측된 파동 대응이며 실제 기믹 동일성의 증명은 아니다.

| 조건             | 검사                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 구간 대응        | 활동의 집합으로 임시 정렬한 결과에서 모든 학습 trace의 해당 묶음 대응이 강제되어야 한다.                                                                                                                                                     |
| 다른 로그의 지지 | 적어도 한 대응 묶음은 해당 활동이 정확히 한 밀리초 파동으로 기록되어야 한다. 모든 로그에서 두 발생이면 합치지 않는다.                                                                                                                        |
| 개체와 시각      | 분절된 원본 관측들의 actor/instance 집합이 비어 있지 않고 서로 겹치지 않아야 한다. 첫 관측부터 마지막까지 100ms 이하여야 한다. 같은 개체의 반복은 합치지 않는다.                                                                             |
| 최종 대응        | 조건을 만족한 활동만 묶음 키에서 한 번으로 센 뒤 모든 최적 다중집합 LCS를 다시 검사한다. 임시 정렬의 한 경로를 정답으로 쓰지 않는다.                                                                                                         |
| 표시와 근거      | 대표 시각은 해당 trace의 첫 분절 시각이다. 새 sync는 생성하지 않는다. `alignment.fragment_policy="disjoint-instance-peer-v1"`와 `fragments`에 모든 원본 batch·시각·개체 수를 보존한다. 포함한 분절을 `unrepresented`로 중복 보고하지 않는다. |

예를 들어 한 trace의 개체 1·2가 4000·4002ms에, 다른 trace의 개체 1·2가 4000ms에 시전했다면 강제 대응과 위 조건을 확인해 하나의 표시로 만들 수 있다. 같은 개체가 두 번 시전했거나 모든 로그가 두 발생을 분리해 기록했다면 이 완화를 적용하지 않는다. 현재 적용 범위는 인접 기준점 사이와 mode별 도입부의 표시용 정렬이며, 최초 국소 옵션·후반 학습·참조 검사는 기존 묶음 규칙을 유지한다.

### 기준점 사이 반복 시전 정렬

아래 다중집합 정렬은 위 조건에 따라 분절을 대응한 뒤의 표시 묶음을 대상으로 한다. 원본 관측과 기준점용 시각표는 변경하지 않는다.

| 규칙          | 현재 구현                                                                                                                                                                                                                                                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위          | 인접 고유 공통 기준점 사이를 완료 로그로 분석한다. 첫 기준점 이전도 mode별 시작부터 표시 정렬한다. raid는 combat 시작, dungeon·alliance는 해당 보스 자신의 첫 시전부터 검사하고, 도입부 분기가 이미 해당 범위를 소유하면 중복 생성하지 않는다. 마지막 기준점 뒤는 아래 종료 검열 학습 정책을 별도로 적용한다.                                                             |
| 대응          | 같은 신호와 발생 개수를 가진 순서 미확정 묶음들을 LCS로 정렬한다. 묶음 하나를 한 토큰으로 세며 모든 최적 정렬에서 대응이 강제되는 묶음만 사용한다. 묶음 안에서 한 번만 관측된 신호를 개별 event로 생성한다. 이는 실제 기믹 동일성의 증명은 아니다.                                                                                                                        |
| 기준 로그     | 선택한 시전 관측이 가장 많은 완료 로그를 사용하고, 동률은 report/fight 순으로 정한다. CLI 입력 순서는 결과를 바꾸지 않는다.                                                                                                                                                                                                                                               |
| 순서 불확실성 | 같은 NPC의 인접 관측 간격이 100ms 이내이면 연속된 불확실성 묶음으로 분석한다. 내부 순서는 정렬에 사용하지 않으며 원본 시각은 유지한다. 표시용 정렬은 양끝과 정확히 같은 시각의 묶음을 제외하되 내부의 근접 관측은 유지한다. 내부 FFLogs phase 경계는 보류한다. 분기 선택·참조 검사·종료 검열 학습의 경계 검사는 유지한다.                                                 |
| 동기화        | 추가한 반복 시전은 표시 event만 생성한다. 같은 ID·NPC의 다른 발생에 잘못 동기화하지 않도록 시계 보정은 기존 고유 기준점에 맡긴다.                                                                                                                                                                                                                                         |
| 자원 제한     | 묶음 수로 계산한 정렬 표 하나가 1,000,000칸을 초과하면 할당 전에 구간을 보류한다. 계산 제한을 불일치로 보고하지 않는다.                                                                                                                                                                                                                                                   |
| 근거          | `events[].alignment`의 방법은 `anchor-constrained-multiset-lcs-v2`다. 양끝 기준점, 기준 로그, 입력별 개별 관측 인덱스(`batches`)와 불확실성 묶음에 속한 관측 인덱스들(`groups`)을 기록한다. `alignment_diagnostics`의 `optimal_group_matches`는 묶음 대응 수다. 동률·한쪽에만 대응된 관측·보류 사유와 미출력 시전도 남긴다. 입력 관측의 `indices`로 원본 이벤트를 찾는다. |

예를 들어 `A B B C`와 `A B C`는 어느 B가 같은 발생인지 정렬로 구분할 수 없어 B를 출력하지 않는다. `A B U B C`와 `A U B C`는 U 뒤의 B만 대응시켜 `B-02`를 출력한다. 시간 근접도만으로 동률을 깨거나 미관측 발생을 실제 게임 분기로 확정하지 않는다.

`A {B,D} {B,D} C`에서 중괄호가 순서 미확정 묶음을 뜻할 때, 다른 로그가 `A {D,B} {D,B} C`여도 각 B·D를 대응시킨다. 묶음 내부의 같은 신호 반복 `{B,B}`는 개별 발생을 구분하지 않는다. 완료 입력의 도입부·기준점 사이에서는 구간 전체의 모든 로그에 나타난 활동만 정렬 뷰로 투영할 수 있다. 예를 들어 `A {B,D} C`와 `A B C`에서 D가 상대 구간에 전혀 없으면 B의 대응은 유지하고 D는 원본·미출력 근거로 남긴다. D의 부재로 분기를 만들지 않으며 `shared-activity-interval-v1`에 제외한 활동·batch·시각을 기록한다.

이 묶음은 실제 동시 실행·독립성 판정이 아니다. 예를 들어 0·80·160ms의 세 관측은 하나로 묶어 보수적으로 내부 순서를 모두 제외한다. 로그마다 묶음 구성이 달라 기존 LCS가 대응하지 못하면, 발생 횟수가 모든 입력에서 같은 활동만 투영해 신호별 발생 순번을 대응한다. 다른 활동의 횟수 차이가 이 공통 표시를 막지 않게 하되, 횟수가 다른 활동 자체는 이 방식으로 복원하지 않는다. 묶음 내부 미구분 중복은 계속 거부한다. 투영으로 빈 묶음을 제거한 뒤에도 관측된 묶음 사이의 순서를 그래프로 이어 합쳐 순환이 없을 때만 복원한다. `A {B,D} C`와 `A B D C`는 대응하지만 B→D와 D→B가 각각 명확히 관측되면 이 보완으로 순서를 추정하지 않는다. 처리량 상한을 넘으면 기존 미해결 판정을 유지한다.

이 보완은 `consistent-partial-order-v1`과 `activity_projection="equal-count-activities"`에 원본 batch·그룹·노드 대응을 남기고 표시 이벤트를 복원한다. 새로운 sync는 만들지 않는다. 종료 검열 접미부와 무한 loop 본문에는 이 투영·부분 순서 보완을 적용하지 않는다. 발생 횟수가 다른 활동의 부분 대응과 선택 이력·반복을 함께 푸는 정렬은 여전히 후속 과제다. [실제 파동 대응 검증](WAVE_ALIGNMENT_VALIDATION.md), [Antivirus X 누락 검증](VARIS_ANTIVIRUS_VALIDATION.md)에 복원·보류·독립 재생 범위를 구분한다.

### 마지막 기준점 뒤의 종료 검열 학습

| 규칙 | 동작                                                                                                                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위 | NPC별 마지막 공통 기준점부터 관측 종료까지. 완료 로그의 조기 처치도 오른쪽 검열로 검사한다. raid는 미처치 로그도 사용한다. dungeon·alliance는 미처치 로그의 보스 시작 시계가 확정되지 않아 완료 로그만 사용한다. |
| 기준 | 구간의 관측 묶음이 가장 많은 trace를 사용하고 동률은 report/fight 문자열 순으로 정한다. kill 여부나 CLI 입력 순서로 선택하지 않는다.                                                                             |
| 진입 | 해당 기준점이 한 번 관측되어야 한다. 앞선 공통 기준점의 역전, 기준점 주변 순서 불확실성, 구간 내 FFLogs phase 경계는 미해결이다. 완료 로그의 범위가 미해결이면 그 NPC의 후반 학습을 보류한다.                    |
| 정렬 | 기존 모든 최적 접두부 정렬을 재사용한다. 각 발생은 최소 두 trace에서 강제 대응되어야 한다. 나머지 유효 trace는 모든 최적 종료 위치 뒤이며, 모든 지지 표본의 기준점 상대 시각보다 먼저 관측이 끝나야 한다.        |
| 누락 | 내부 누락·최적 대응 모호함·종료 전 침묵 구간을 중립 표본으로 취급하지 않는다. 불확실한 묶음 내부의 같은 신호 여러 회차도 추측하지 않는다.                                                                        |
| 출력 | 지지 trace의 시각 표본을 가진 표시 이벤트만 생성한다. 자동 sync는 추가하지 않는다. 기존 기준점·전멸·구역 변경 조건을 사용하며 FFLogs 종료를 실행 신호로 만들지 않는다.                                           |
| 근거 | `censored-tail-v1`에 기준점·참조·trace별 대응·종료 위치·차이·미해결 및 생성·거절 발생을 보존한다. 원본과 이벤트의 `samples`, `alignment.batches/groups`로 연결한다.                                              |
| 한계 | 마지막 기준점 뒤만 확장한다. 긴 로그의 중간 미해결 구간·추가 분기·반복 모델·보스 내부 페이즈는 별도 과제다. 두 trace의 대응은 통계적 독립성이나 기믹 동일성의 증명이 아니다.                                     |

예를 들어 두 긴 trace가 `A B B C`, 두 짧은 완료 trace가 `A`이면 A 이후의 B·B·C를 학습할 수 있다. 단, 짧은 trace의 종료가 B 예정 시각보다 빨라야 한다. B 시각 이후에도 기록이 계속되면 그 B는 학습을 막는 미해결 관측이며, 정상 검열로 숨기지 않는다.

### 미처치 로그의 참조 검사

입력의 `kill=false` 로그는 공통 기준점을 정하는 데 사용하지 않는다. 위 후반 학습에 사용한 경우에도 별도로 접두부 검사를 남기며 추가 CLI 옵션은 없다. `alignment_diagnostics`의 `method="censored-reference-prefix-v1"`에서 `training`은 해당 trace의 관측이 생성 이벤트의 시각 표본에 포함됐는지를 나타낸다. `training=true`인 검사는 독립 검증이 아니다. 이 검사는 생성 이벤트가 연결된 완료 참조 관측의 대응을 평가하며, KDL 실행·시각 검증이나 ACT 재생을 대체하지 않는다.

`kill=false`는 미처치·중단 기록을 포함한다. 실제 전멸 신호를 관측했다는 뜻으로 사용하지 않는다.

참조상 뒤의 고유 기준점이 검사 로그에서는 시작 기준점보다 먼저 관측되면 해당 범위를 `unresolved`로 남긴다. 순서가 바뀐 기준점으로 정렬을 시작해 앞서 관측된 기믹을 누락으로 오판하지 않는다.

| 항목      | 동작                                                                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기준      | 완료 로그 중 정렬용 기준 로그의 시전열을 사용한다. 출력에서 제외된 시전도 참조 시전열에 남아 있다.                                                                                       |
| 시작      | 관측된 보스 범위의 첫 묶음이 참조와 같은 단일 활동이고 모델이 그 발생을 보존하면 진입부터 검사한다. 그 외에는 한 번 관측된 가장 이른 고유 공통 기준점을 사용하며 그 앞부분은 미해결이다. |
| 정렬      | 순서 미확정 묶음의 삽입·삭제 비용은 각각 1, 일치는 0이다. 마지막 관측 이후의 참조 뒷부분은 무료로 생략한다. 모든 최적 종료 위치와 강제 대응을 보존한다.                                  |
| 제한      | 기준점 주변 순서가 미확정이거나 참조·전멸 로그의 검사 범위에 FFLogs phase 경계가 있으면 보류한다. 정렬 표 제한도 동일하게 적용한다.                                                      |
| 위치 추적 | `scopes[].result.events`의 `event.activity`, `reference_at_ms`로 생성 이벤트의 참조 sample을 찾는다. `matched`의 `batch`와 진단의 관측 인덱스는 해당 입력의 `observations`를 가리킨다.   |

| 이벤트 상태  | 뜻                                                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `matched`    | 모든 최적 정렬에서 같은 관측으로 대응된다. 실제 기믹 동일성이나 일정 시각의 정확성을 보장하지 않는다.                                                                                       |
| `ambiguous`  | 최적 정렬의 대응·종료가 다르거나 묶음 내부의 동일 신호 여러 발생을 구분할 수 없다.                                                                                                          |
| `unobserved` | 모든 최적 종료 위치 이후의 참조 뒷부분이며, 기준점에 대한 모든 학습 시각 표본도 관측 종료 이후에 놓인다.                                                                                    |
| `mismatch`   | 모든 최적 정렬에서 뒷부분 종료 이전의 참조 묶음이 삭제되고, 해당 신호 자체도 검사한 전멸 관측에 없다. 참조와 관측의 차이이며 실제 게임의 누락이나 생성기의 잘못으로 원인을 확정하지 않는다. |
| `unresolved` | 기준점·구성원 대응이 불명확하거나, 정렬상 뒷부분이어도 학습 시각이 관측 기간과 겹친다. 침묵 구간의 시전 누락을 정상 종료로 간주하지 않는다.                                                 |

예를 들어 참조 `A B B C`와 전멸 관측 `A B`의 최적 접두부는 첫 B에서 끝나지만, 관측이 두 번째 B의 학습상 예정 시각 이후까지 계속됐다면 그 B는 미해결이다. 참조 `A X C`와 관측 `A C`는 X 삭제와 C 미대응·조기 종료가 동률일 수 있으므로 단순히 X 누락으로 확정하지 않는다. 범위 결과의 `evaluated`와 명령 성공은 품질 통과가 아니다.

이 자동 참조 정렬은 분기·반복 모델의 적합도, 생성 KDL의 보정된 일정 시각, ACT 신호 동등성을 검사하지 않는다. dungeon·alliance의 유한 정렬은 보스 시도 범위에 따라 완료된 본체 시도를 학습한다. 말단 loop의 별도 원본 대응·투영 재생과 구분하며, 실패한 시도와 재시작의 전체 경로 학습·재생은 아직 지원하지 않는다.

### 입력 로그의 자동 검증

사용자는 로그들과 mode만 입력한다. 검증 로그 선택은 생성기가 수행하며 별도 holdout 옵션은 없다. 검사·정규화는 모든 입력에 공통으로 적용하고 같은 보고서/전투의 복사본·수정본이나 잘못된 입력은 기존 입력 검사에서 거부한다.

| 단계      | 정책                                                                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 선택      | 완료 로그가 3개 이상이면 보고서 코드의 사전순, 전투 ID의 숫자순으로 가장 큰 한 개를 고른다. 입력 인자 순서나 파일 이름을 바꿔도 선택이 바뀌지 않는다. 무작위 선택이나 검증 결과에 따른 재선택은 하지 않는다.             |
| 임시 모델 | 선택한 완료 로그를 제외하고 공통 진행을 학습한다. raid의 임시 모델에는 미처치 입력의 후반 학습도 포함한다. dungeon·alliance의 Boss 범위도 해당 학습 로그의 메타데이터로 한정한다. 선택한 로그를 이 임시 모델과 비교한다. |
| 최종 모델 | 모든 완료 로그와 정책상 허용되는 미처치 후반 표본으로 생성한다. 검증용 완료 로그도 최종 학습에는 포함한다. 검증 결과는 임시 모델에 대한 결과이며 최종 모델이 독립적으로 검증됐다고 표시하지 않는다.                      |
| 자료 부족 | 완료 로그가 2개면 최종 생성은 수행하되 독립 검증은 `insufficient-completed-pulls`로 기록한다. 미처치 로그는 완료 로그 수에 넣지 않는다.                                                                                  |
| 모델 실패 | 임시 학습의 순서 충돌·공통 발생 부재는 `unresolved`로 이유를 남긴다. 최종 학습이 가능하면 생성은 계속하며 실패를 검증 성공으로 간주하지 않는다.                                                                          |

계산량을 제한하기 위해 한 분할만 검사한다. 모든 분할·모든 패턴을 평가하거나 보고서 간 통계적 독립성을 증명하는 검사는 아니다.

| holdout 종류 | 정렬과 종료 처리                                                                                                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kill=true`  | `complete-reference-alignment-v1`: 참조 열 전체와 관측 열을 정렬하고 미대응 뒷부분에도 삭제 비용을 부과한다. 보스 처치가 직접 관측된 범위는 접두부 종료를 허용하고 아래 시간 검사로 검열을 확인한다. 결과의 boss_completed로 구분한다.         |
| `kill=false` | `censored-reference-prefix-v1`: 기존 접두부 검사처럼 참조 뒷부분의 무료 종료를 허용한다.                                                                                                                                                       |
| 빠른 처치    | 완료 로그의 미대응 이벤트라도 모든 학습 시각 표본이 해당 처치 종료 뒤에 놓이면 `unobserved`로 남긴다. 처치 종료 전에 놓이는 차이를 무료 종료로 숨기지 않는다. 이 시간 검사는 학습 기준점에 대한 추정이며 실제 runtime 시계 보정 검증이 아니다. |

검사 범위·미해결 처리·관측 추적은 위 접두부 검사와 같다. `analysis.inputs`에 모든 입력의 해시·언어·관측 인덱스를 보존한다. `alignment_diagnostics`에서 `method="automatic-validation-v1"`인 항목의 `policy`, `split`, `model_events`, `checks`로 선택 정책·학습 및 검증 trace·임시 모델·검사 결과를 추적한다. `model_events.samples`에는 임시 학습 입력만 들어간다. 최상위 `events[].samples`는 최종 모델에서 실제로 지지한 trace를 보존하며 후반에서는 일부 완료·미처치 입력만 포함할 수 있다. 미처치 입력의 접두부 검사는 별도로 남긴다.

완료 참조 로그에 없는 후반 이벤트는 `event not observed in completed comparison reference`로 미해결이다. 후반 표본의 비교용 시작 시각이 부족해 종료 검열을 평가할 수 없을 때도 미해결로 남긴다. 후반 학습의 자체 대응 검사와 완료 참조 검사의 범위를 혼동하지 않는다.

이 검사는 임시 학습 완료 로그의 참조 시전열과 임시 모델 이벤트에 연결된 관측을 평가한다. 최종 KDL 실행 경로 전체와 시각이 검증됐다는 뜻은 아니다. `matched`뿐 아니라 `mismatch`, `ambiguous`, `unresolved`, `peer_only`를 함께 검토해야 한다. 명령의 성공 종료와 `evaluated`는 검사 처리 완료를 뜻하며 자동 품질 통과를 뜻하지 않는다.

### 국소 순서 분기: 첫 구현

| 항목        | 현재 지원                                                                                                                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위        | raid에서 한 국소 순서 분기를 생성한다. 고유 공통 시전의 순서가 뒤바뀐 구간을 대상으로 하며, 관측 누락만으로 선택지를 만들지 않는다. dungeon·alliance의 분기와 추가 분기의 상관관계는 미해결로 기록한다.                                           |
| 공통 진행   | 100ms 해상도에서 모든 완료 로그가 동의하는 선후 관계로 그래프를 만든다. 순서 충돌이 있으면 모든 최장 사슬이 공유하는 기준점만 선택한다. 동률인 사슬 하나를 임의로 고르지 않는다.                                                                  |
| 선택        | 같은 NPC의 연속 공통 기준점 사이를 검사한다. 도입부는 combat 시작 이후부터 첫 공통 기준점까지 허용한다. 각 로그에서 가장 먼저 관측된 고유 공통 활동을 선택 신호로 사용하며, 순서 미확정 묶음 안에 여러 선택 신호가 있으면 보류한다.               |
| 옵션 본문   | 같은 선택으로 시작한 로그를 모아 다시 정렬한다. 해당 옵션의 모든 최적 정렬에서 강제되는 발생만 표시하며 묶음 내부의 동일 신호 여러 발생은 추측하지 않는다. 옵션 시각은 선택 신호를 0으로 삼고 자동 sync는 넣지 않는다.                            |
| 선택 window | 관측 범위에 최소 2.5초 여유를 시도하고 도입부는 최초 시계 오차를 고려해 10초를 시도한다. 전체 로그의 경쟁 선택 신호를 배제하고 가장 늦게 선택해도 생성 본문이 공통 후속 일정 전에 끝나도록 줄인다. 모든 관측을 포함하는 window가 없으면 보류한다. |
| 합류        | 현재는 공통 후속 일정을 branch 밖에 공유한다. 해당 일정은 phase 시각과 sync를 사용하며 분기 본문은 그 전에 끝난다. 신호마다 합류 시각이 달라지는 명시적 `merge` 생성은 후속 과제다.                                                               |
| 시계와 ID   | branch가 있으면 raid 본문을 `combat` phase에 두어 공통 sync와 옵션이 같은 phase 시계를 공유한다. 옵션별 이벤트 ID에는 합류 기준점·선택 능력 ID를 포함해 문서 전체에서 구별한다.                                                                   |
| 근거        | `consensus-backbone-v1`에 공통 뼈대 밖 활동과 표본을 기록한다. `local-order-branch-v1`에 생성·보류와 선택별 trace를 기록하고, 출력 이벤트에는 `branch`, `option`, `selection_samples`와 원본 묶음 연결을 남긴다.                                  |

예를 들어 `A B C D`와 `A C B D`는 A·D를 공유하고, 먼저 B를 관측하는 옵션과 먼저 C를 관측하는 옵션을 만든다. 선택 창은 뒤쪽의 반대 신호를 받기 전에 닫는다. `A B C D`와 `A B D`처럼 발생이 없는 것만으로 분기를 확정하지 않는다. 선택 신호가 없으면 옵션을 추정하지 않으며 공통 후속 일정은 계속 진행한다.

원본 로그로 확인한 R11S 사례는 `c36H8h2aqXwkgtjR/3`, `4kt1bfqJn7QPCj29/2`, `fDhKygMQ3VCvZat8/2`다. Raw Steel Trophy `B422`·`B423`의 약 18초/157초 순서 교환을 도입부 한 branch로 표현한다. 세 로그로 112개 이벤트 정의를 생성했으며 후속 상관 선택은 미해결이다. combat 시작을 0으로, FFLogs cast를 Ability로 가정한 합성 관측에서는 각 로그의 도입부 선택을 한 번씩 재생했다. 이 투영은 ACT 신호 동등성·실제 실행·전체 관측 커버리지 검증이 아니다.

현재는 공통 시전 본문·동기화, raid의 한 국소 순서 분기와 아래의 제한적인 유한 블록 이력, dungeon·alliance의 보스별 phase 및 제한적인 말단 loop를 생성한다. 일반적인 보스 내부 페이즈·상관 분기·가변 합류·반복과 탈출·시전 외 이벤트의 본문 생성, 서로 다른 encounter 입력의 연결과 실제 ACT/runtime 검증은 남아 있다. 자동 검증의 참조 정렬은 분기·loop·블록 이력의 실행 경로 자체를 평가하지 않으며 별도 KDL 재생과 구분한다.

### 유한 블록과 선택 이력: 첫 구현

loop 모델이 없는 raid에서, 공통 고유 경계 사이의 3–6개 기믹 블록이 서로 다른 순서 3종 이상으로 관측되면 블록 본문과 선택 이력을 학습한다. 완료된 해당 구간을 가진 전멸 pull도 사용할 수 있다. 진입부터 다음 블록까지의 표시를 학습하고 관측된 접두부를 상태로 렌더링한다. 미완료 이력은 합치지 않고 완료 상태만 공유한다. 현재는 가장 작은 한 유한 구간·최대 64개 이력 상태를 지원한다.

각 상태는 기존 `phase`로, 전환은 `Ability`·source와 `enter from`으로 작성한다. 표시 시각은 선택한 구간의 진입 기준이다. 진입 창은 이전 상태 시작부터 다른 선택 경로의 경쟁 발생·다음 미사용 블록·공통 후속 경계 전에 닫는다. 같은 진행을 식별하는 관측을 평균 시각과 멀다는 이유만으로 거부하지 않는다. 새 문법·FFLogs 전용 신호·실행용 evidence 참조는 추가하지 않는다.

블록 안에서 한 번씩 식별되는 활동은 내부 순서가 흔들려도 `unique-block-activity-v1`로 표시를 보존한다. 상대 순서·동시 실행·독립성을 확정하지 않으며 sync는 만들지 않는다. 반복되는 활동과 내부 선택은 기존 파동·부분 순서 정렬의 지지 범위를 유지한다.

`histories[]`에 경계·블록 본문·trace별 관측 순서·상태·전환과 창 정책을 기록하고 출력 이벤트는 원본 노드 및 phase로 연결한다. 블록 안의 발생 순번과 결정적인 참조 순서로 ID를 생성한다. 기존 유한·option 표시의 원본 노드가 사라지거나 기존 이후 branch·loop와 충돌하면 새 모델만 보류하고 기존 출력을 유지한다. [블록 이력 검증](BLOCK_HISTORY_VALIDATION.md)에 Varis의 실제 예측·보류 pull·경쟁 신호·미학습 경로와 남은 한계를 기록한다.

### 말단 반복: 첫 구현

| 항목      | 현재 지원과 제약                                                                                                                                                                                                                                                                                                                                                                                                |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 입력 문맥 | raid는 전투 전체의 실행 적격 적대 시전을 함께 검사하고, dungeon·alliance는 비중첩 본체 actor/instance 범위를 각각 검사한다. 미완료 시도의 후반도 사용한다. 내부 phase 경계나 동시 본체 때문에 범위가 미해결이면 그 범위의 loop를 보류한다. raid에서도 미분류 NPC를 자동 승격하지 않는다.                                                                                                                        |
| 진입      | 모든 범위에서 한 번씩 관측된 가장 가까운 공통 고유 신호가 있으면 그 신호부터 진입까지의 국소 prefix를 검사한다. 그 앞의 opener는 달라도 된다. 그런 신호가 없으면 전체 opener를 검사한다. opener까지 도달하지 못한 짧은 시도는 미관측이며, 검사하는 prefix·내부 단계·회차 경계가 빠진 기록은 뒤의 같은 ID로 대체하지 않는다.                                                                                     |
| 반복 지지 | 서로 다른 두 trace 이상에서 본문 전체와 다음 경계 및 후속 두 단계를 요구한다. 본문은 적어도 두 파동이며 경계 신호 집합은 회차 안에서 고유해야 한다. 내부 신호의 재사용은 회차 안의 발생 순서로 서로 다른 위치에 대응하며 개수도 보존한다. 뒤의 관측은 모두 같은 본문의 완전·미완성 회차로 대응돼야 한다.                                                                                                        |
| 순서 변형 | 관측된 위치 교환의 연결 성분으로 연속 블록을 만든다. 블록 전체가 재배열된 관측을 요구한다. 고정 공통 신호는 따로 보존하고 나머지는 `A / B` 중립 표시와 ID OR 신호로 표현한다. 선택 이력·독립 분기의 증명은 아니다.                                                                                                                                                                                              |
| 파동      | 같은 신호의 여러 패킷은 기존 개체 분리 근거가 있을 때만 하나의 위치에 대응한다. 같은 개체의 실제 재시전은 합치지 않는다. 위치별로 같은 신호가 여러 시각으로 분절되지 않은 파동 근거를 요구하며, 서로 다른 로그·회차가 그 지지를 나누어 제공해도 된다. 원본 멤버와 노드는 모두 보존한다.                                                                                                                         |
| 시간      | 구조를 확정한 후 회차 상대 offset·경계 간격을 추정한다. trace별 중앙값을 다시 중앙값으로 요약해 긴 기록 하나의 가중치를 제한한다. 회차 시작점은 가장 이른 구조적 진입이며 참조 타임라인의 시작점과 다를 수 있다.                                                                                                                                                                                                |
| 보정      | 관측 범위와 최소 2.5초 여유로 window를 추정한다. 같은 신호를 쓰는 다른 위치와 주기 경계를 넘어서 window가 겹치면 해당 sync를 생략하고 표시를 유지한다. 한 회차의 sync는 이후 회차 일정도 보정한다. 여러 NPC의 대안은 NPC별 ID 집합으로 나누어 관측되지 않은 source·ID 조합을 만들지 않는다.                                                                                                                     |
| 대체·실패 | 국소 문맥 신호가 최종 KDL의 유한 sync로 남아 있어야 한다. 원본 노드가 loop에 전부 대응된 유한 정의만 대체한다. 같은 정의가 opener와 본문에 걸치거나 위상이 다르면 loop를 보류하고 유한 출력을 유지한다. 시간 추정 실패로 원본을 삭제하지 않는다.                                                                                                                                                                |
| 근거      | `loop_diagnostics`에 `terminal-loop-v1` 판정을 기록한다. `loops[].model`에 context·검사한 prefix·본문·블록·모든 시도와 회차의 원본 멤버를, `loops[].events[].observations`에 trace·actor·instance·iteration·원본 노드 대응을 둔다. raid의 전투 전체 범위는 source·actor·instance가 null이고 phase origin은 combat의 0이다. 개별 신호의 NPC 이름은 유지한다. 기존 유한 정의는 `replaced_finite_events`에 남긴다. |
| 한계      | 이름이 다른 helper 소속, 회차 안에 고유 경계가 없는 반복, 선택 이력에 따른 후속 의존성, 신호 탈출·보스 처치 종료 자동 생성은 남아 있다. 처리량 상한에 걸리거나 지지가 없으면 유한 출력을 유지하며 미해결 후보의 거부 사유별 개수를 기록한다.                                                                                                                                                                    |

KDL은 횟수를 관측 수로 고정하지 않는 `loop start=… every=…`다. 상위 phase가 끝날 때 취소되며 다음 경계 관측이 없어도 미래를 표시한다. 보스 처치 시점은 분석 근거이지 가짜 runtime 신호가 아니다. 자동 검증의 기존 `allInputsPassed`는 생성 loop의 실행 성공을 뜻하지 않는다. [실제 던전 검증과 독립 보류 재생](DUNGEON_LOOP_VALIDATION.md)에 별도 결과와 한계를 기록한다.

다음 테스트는 `mine`이나 템플릿 없이 JSON들을 `generate`에 직접 넣고, 근거 파일을 삭제한 뒤 KDL 단독 재생·동기화·전멸·구역 변경·재시작을 검증한다.

```sh
cargo test --test generate
```

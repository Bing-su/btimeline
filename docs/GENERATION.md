# FFLogs에서 KDL 생성

`generate`는 FFLogs JSON 파일들을 직접 받는 엔드 투 엔드 명령이다. 입력 검사 → 공통 프로세스 분석·그래프 구성 → mode 정책 적용 → KDL 생성 → 구조 검증 → 저장을 한 번에 수행한다. 템플릿, 작성한 기준점, 중간 그래프 파일은 입력으로 요구하지 않는다.

```sh
btimeline generate first.json second.json --mode raid -o timeline.kdl
btimeline generate first.json second.json --mode dungeon -o timeline.kdl
btimeline generate first.json second.json --mode alliance -o timeline.kdl
btimeline generate first.json second.json third.json --mode raid -o timeline.kdl
```

| 입력        | 계약                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| JSON 파일들 | 기존 수집 완료·페이지·액터·전투 범위 검사를 통과해야 한다. 현재는 같은 encounter·난이도의 전투들을 한 번에 받는다. |
| mode        | `raid`, `dungeon`, `alliance` 중 하나. 필수 정책 입력은 이것뿐이다.                                                |
| 출력 경로   | KDL과 같은 이름의 `.evidence.json`을 새로 저장한다. 기존 파일을 덮어쓰지 않는다.                                   |

`mine`은 동일한 분석 결과를 사람이 확인할 때 쓰는 선택적 명령이다. 생성기가 디스크에 중간 KDL을 기록하거나 그 파일을 다시 읽지는 않는다.

## 진행 구조와 시간 추정의 분리 계획

구현은 [진행 그래프와 시간 추정의 분리 계획](PROGRESSION_AND_TIMING.md)을 따른다. 현재 trace별 모든 시전 파동 후보와 부분 순서를 먼저 보존하고, 기존 고유 기준점 중심 분석의 출력 후보를 노드에 연결해 별도 시간 추정기로 전달한다. evidence의 `progression`과 이벤트별 `observation_nodes`로 대응을 추적한다. 고유 시각 기준점이 없거나 시간 추정이 실패해도 원본 그래프는 변하지 않는다. trace 간 선택 이력·반복의 통합 학습과 시간 추정 실패의 부분 출력은 아직 미구현이다.

**시간은 정확히 재현할 필요가 없고 사용하기에 충분하면 된다.** 작은 기록 차이를 제거하고 기믹의 순서·선택·회차를 알아볼 수 있는 근사 일정을 목표로 한다. 0.1초는 표현 단위이며 실제 전투와 100ms 이내로 맞춘다는 보장이 아니다. 표시 시각의 실용성과 sync·window의 실행 안전성은 별도로 검증한다. 원본 시간은 파동·부분 순서·종료 판단에도 계속 사용하며 보존한다.

이는 작은 오차만 허용한다는 뜻이 아니다. 같은 진행 위치를 가리킨다는 근거가 있으면 수 초·수십 초의 차이도 시계 보정으로 다룰 수 있어야 한다. 같은 ID의 다른 회차·선택과 구분할 구조적 근거는 계속 필요하며, 큰 보정을 허용한다고 window를 무조건 넓히지는 않는다. 원본 대응이 여러 가지여도 표시·실행 결과가 실용적으로 같으면 그 모호함 때문에 구조를 버리지 않는 방향으로 구현한다.

입력은 기존처럼 FFLogs JSON과 mode만 받는다. 새 그래프·시간표를 수동 입력으로 요구하거나 KDL 실행에 evidence를 의존시키지 않는다. 이 계획은 기존 runtime 시계·시간 단위·문법을 바꾸지 않는다.

## 게임 신호와 mode 정책

cactbot의 고정 커밋 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`를 참고한다. [R9S](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/data/07-dt/raid/r9s.txt#L8-L14)와 [Valigarmanda](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/data/07-dt/trial/valigarmanda.txt#L13-L16)는 InCombat 시작, 시전·능력 ID와 NPC 이름에 의한 동기화를 사용한다. 아래 표는 이 근거를 사용하는 생성기의 정책이며 cactbot의 모든 콘텐츠에 동일한 규칙이 있다는 뜻은 아니다.

| mode       | 시작과 시각 기준                                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `raid`     | `InCombat inGameCombat="1"`로 시작한다. FFLogs fight 시작에 대한 상대 시각을 최초 일정으로 삼고 능력 관측으로 시계를 보정한다.                                              |
| `dungeon`  | FFLogs의 적대 액터 중 `subType=Boss`인 이름을 보스 범위로 삼는다. 보스별 phase와 시전 진입 조건을 만들고 각 로그·보스의 가장 이른 공통 시전을 그 phase의 상대 0으로 삼는다. |
| `alliance` | 던전과 같은 보스별 phase·시전 진입 정책을 사용한다. 보스 내부의 추가 페이즈는 아직 추론하지 않는다.                                                                         |

보스 기준점으로 먼저 나타난 능력이 로그마다 다르면 해당 ID·NPC 이름 조건들을 start와 phase enter의 OR 대안으로 생성한다. 모든 보스의 진입 조건을 start에도 두므로 둘째 보스에서 전멸해도 그 보스부터 재시작할 수 있다. 보스 사이 이동 시간은 보스 시계에 포함하지 않는다. 잡몹 시전은 보스 본문에서 제외하고, Boss 메타데이터가 없으면 임의의 NPC를 보스로 추정하지 않고 오류로 보고한다. 표시 이름을 입력 매칭 키로 사용하지 않는다.

첫 고유 기준점 앞의 반복도 보스 자신의 첫 시전부터 표시 정렬한다. 복원된 가장 이른 공통 발생이 반복 ID여도 phase 진입 신호로 사용할 수 있으며 활성 phase의 같은 진입 신호는 다시 시작하지 않는다. 이 진입 허용은 반복 발생의 event sync 허용을 뜻하지 않는다. 이전 보스의 phase 경계와 이동은 이 보스 도입부에 포함하지 않는다. 여전히 NPC별 고유 공통 기준점이 하나 이상 필요하며, 전혀 없을 때의 발생 대응은 후속 작업이다. [Clyteum 누락 감사](CLYTEUM_OMISSION_AUDIT.md)에 개선 범위와 전체 입력의 실패를 함께 기록한다.

이는 [cactbot의 던전·연합레이드 진입 구분](CACTBOT_LIFECYCLE_RESEARCH.md)을 참고한 생성 정책이다. FFLogs에 없는 봉인 메시지의 파라미터를 만들어내는 대신 수집 자료의 Boss 분류와 실제 시전을 사용한다. 보스 본체와 이름이 다른 helper의 소속 판정은 아직 지원하지 않는다.

| 공통 정책     | 생성 내용                                                                                                                                                                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 전멸·재시작   | `ActorControl command="4000000F"`와 구버전 `40000010`을 wipe 조건으로 둔다. [cactbot 공통 wipe 정의](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/resources/netregexes.ts#L675-L680)를 따른다. |
| 구역 변경     | `zone-exit "ChangeZone"`으로 상태를 초기화한다. [로그 타입 정의](https://github.com/OverlayPlugin/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/resources/netlog_defs.ts#L190-L209)에 근거한다.                                  |
| 시전 완료     | FFLogs의 시전 후보에서 능력 ID를 16진수로, NPC를 이름으로 표현해 `Ability` 동기화를 생성한다. 보고서별 actor ID를 매칭에 쓰지 않는다.                                                                                                    |
| 동기화 window | 각 로그의 상대 관측 시각을 포함하도록 잡고 양쪽 최소 2.5초를 둔다. raid의 첫 동기화는 R9S의 도입부 사례처럼 양쪽 최소 10초로 최초 시계를 보정한다.                                                                                       |

비전투 전환을 무조건 전멸·종료로 생성하지 않는다. 중간 비전투 때문에 cactbot의 자동 리셋을 끄는 [Kuribu 사례](CACTBOT_LIFECYCLE_RESEARCH.md)가 있으므로 현재 공통 리셋은 명시적인 wipe와 구역 변경에 한정한다. 처치 종료와 콘텐츠별 lifecycle 예외의 자동 처리는 남아 있다.

## 표시 보존과 동기화 검증의 개선 정책

[기법·구현 순서](PROCESS_MINING_TECHNIQUES.md#누락-감사-이후의-우선순위)와 [실제 누락 감사](R11S_OMISSION_AUDIT.md)를 함께 따른다. 표시 일정의 근거가 충분해도 시계 보정 근거가 부족하면 sync 없이 생성한다. 이 원칙은 모든 모호한 후보를 출력한다는 뜻이 아니다.

| 항목             | 현재 구현                                                                                                                                                                            | 후속 구현                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 경계의 시간 근접 | 인접 기준점 사이 표시용 정렬은 근접 관측을 포함하고 내부의 강제 대응을 보존한다. 정확한 양끝 시각의 묶음은 제외한다. 분기 선택·참조 검사·종료 검열 학습은 기존 경계 검사를 유지한다. | 경계 묶음의 구성원을 포함한 부분 순서 대응                                 |
| 파동             | 원본은 정확한 밀리초로 보존하고, 표시 정렬에서는 다른 trace의 지지와 개체 정보를 확인해 분절을 대응한다.                                                                             | 인스턴스·시전·시간 불확실성을 함께 사용한 파동 후보 분석                   |
| 대응             | 묶음 전체의 모든 최적 LCS 대응을 검사한다.                                                                                                                                           | 부분 순서와 국소 비용 정렬로 확인된 구성원만 보존하고 동률·반례를 추적     |
| 선택 이력        | 한 국소 분기만 생성한다.                                                                                                                                                             | 선행 선택의 영향을 공통 구간 너머까지 학습하고 기존 option/requires로 표현 |
| 보조 액터        | 자신의 공통 기준점이 없으면 본문을 생성하지 못한다.                                                                                                                                  | 확인된 전투 문맥과 반복 관측을 연결                                        |

원본 시각과 파동 개수, 실제 반복·종료 검열 구분을 보존한다. 최저 비용 하나를 기믹의 정답으로 확정하거나 드문 경로를 빈도만으로 삭제하지 않는다. 분석 보완은 기존 KDL의 공유 시계·신호 의미를 바꾸지 않으며 새로운 사용자 설정을 요구하지 않는다.

## 현재 생성 범위와 근거

| 항목      | 동작                                                                                                                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 공통 진행 | 둘 이상의 완료 로그에서 고유 공통 시전을 기준점으로 삼는다. 순서가 충돌하면 모든 최장 공통 순서 사슬에 포함되는 기준점만 공통 뼈대로 삼고 나머지는 국소 분기 분석·미해결 근거로 남긴다. 같은 NPC의 인접 기준점 사이에서는 모든 최적 삽입·삭제 정렬에서 강제되는 시전도 생성한다. |
| 시각      | mode 기준점에 대한 상대 밀리초의 아래쪽 중앙값을 선택하고 0.1초로 반올림한다. 정확히 중간이면 큰 값으로 정한다.                                                                                                                                                                  |
| ID        | 이름·NPC 이름·능력 ID를 조합한다. 정렬로 추가한 시전에는 기준 로그에서 관측한 발생 순번(`-01` 등)을 붙인다. 이는 게임의 반복 회차를 확정한 번호가 아니다. 충돌은 오류로 보고한다.                                                                                                |
| 제외      | 시전 외 활동, 대응 미확정 관측, 보스 mode의 잡몹·미할당 helper와 공통 시전이 없는 보스의 이유를 근거에 남긴다. 일부 발생이 출력된 능력도 나머지 미대응 발생을 별도로 추적한다.                                                                                                   |
| 검증·저장 | 최종 KDL을 기존 파서로 검증한 뒤 KDL과 근거를 함께 저장한다. 실패 시 일부 새 출력만 남기지 않는다.                                                                                                                                                                               |

근거 JSON 버전은 2다. mode, 정책 기준 버전, 원본 입력 경로·해시·관측 인덱스, 분석 그래프 통계, 전투별 기준점·원본 시각·반올림 차이와 제외 사유를 보존한다. 입력 로그의 원본 이벤트는 해시와 인덱스로 추적하며 전체 원본 패킷을 출력마다 복제하지 않는다. 근거 파일은 실행 입력이 아니다.

원본 관측과 고유 기준점용 시각표는 정확히 같은 원본 밀리초의 동일 신호·NPC 이름을 한 파동으로 센다. 개체 수가 로그마다 달라도 표시 일정은 대응할 수 있다. `observations.signals`의 multiplicity·인덱스와 `alignment.waves`의 대표 batch·instances는 보존한다. instances는 적중 횟수를 뜻하지 않는다. `mine`의 원본 그래프 빈도는 개체 관측 수를 유지한다.

인접 고유 기준점 사이의 표시 정렬은 다음 조건을 모두 만족하면 다른 밀리초에 분절된 개체 관측도 한 표시 파동으로 대응시킨다. 이는 관측된 파동 대응이며 실제 기믹 동일성의 증명은 아니다.

| 조건             | 검사                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 구간 대응        | 활동의 집합으로 임시 정렬한 결과에서 모든 학습 trace의 해당 묶음 대응이 강제되어야 한다.                                                                                                                                                     |
| 다른 로그의 지지 | 적어도 한 대응 묶음은 해당 활동이 정확히 한 밀리초 파동으로 기록되어야 한다. 모든 로그에서 두 발생이면 합치지 않는다.                                                                                                                        |
| 개체와 시각      | 분절된 원본 관측들의 actor/instance 집합이 비어 있지 않고 서로 겹치지 않아야 한다. 첫 관측부터 마지막까지 100ms 이하여야 한다. 같은 개체의 반복은 합치지 않는다.                                                                             |
| 최종 대응        | 조건을 만족한 활동만 묶음 키에서 한 번으로 센 뒤 모든 최적 다중집합 LCS를 다시 검사한다. 임시 정렬의 한 경로를 정답으로 쓰지 않는다.                                                                                                         |
| 표시와 근거      | 대표 시각은 해당 trace의 첫 분절 시각이다. 새 sync는 생성하지 않는다. `alignment.fragment_policy="disjoint-instance-peer-v1"`와 `fragments`에 모든 원본 batch·시각·개체 수를 보존한다. 포함한 분절을 `unrepresented`로 중복 보고하지 않는다. |

예를 들어 한 trace의 개체 1·2가 4000·4002ms에, 다른 trace의 개체 1·2가 4000ms에 시전했다면 강제 대응과 위 조건을 확인해 하나의 표시로 만들 수 있다. 같은 개체가 두 번 시전했거나 모든 로그가 두 발생을 분리해 기록했다면 이 완화를 적용하지 않는다. 현재 적용 범위는 인접 기준점 사이와 mode별 도입부의 표시용 정렬이며, 최초 국소 옵션·후반 학습·참조 검사는 기존 묶음 규칙을 유지한다.

### 기준점 사이 반복 시전 정렬

아래 다중집합 정렬은 위 조건에 따라 분절을 대응한 뒤의 표시 묶음을 대상으로 한다. 원본 관측과 기준점용 시각표는 변경하지 않는다.

| 규칙          | 현재 구현                                                                                                                                                                                                                                                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위          | 인접 고유 공통 기준점 사이를 완료 로그로 분석한다. 첫 기준점 이전도 mode별 시작부터 표시 정렬한다. raid는 combat 시작, dungeon·alliance는 해당 보스 자신의 첫 시전부터 검사하고, 도입부 분기가 이미 해당 범위를 소유하면 중복 생성하지 않는다. 마지막 기준점 뒤는 아래 종료 검열 학습 정책을 별도로 적용한다.                                                             |
| 대응          | 같은 신호와 발생 개수를 가진 순서 미확정 묶음들을 LCS로 정렬한다. 묶음 하나를 한 토큰으로 세며 모든 최적 정렬에서 대응이 강제되는 묶음만 사용한다. 묶음 안에서 한 번만 관측된 신호를 개별 event로 생성한다. 이는 실제 기믹 동일성의 증명은 아니다.                                                                                                                        |
| 기준 로그     | 선택한 시전 관측이 가장 많은 완료 로그를 사용하고, 동률은 report/fight 순으로 정한다. CLI 입력 순서는 결과를 바꾸지 않는다.                                                                                                                                                                                                                                               |
| 순서 불확실성 | 같은 NPC의 인접 관측 간격이 100ms 이내이면 연속된 불확실성 묶음으로 분석한다. 내부 순서는 정렬에 사용하지 않으며 원본 시각은 유지한다. 표시용 정렬은 양끝과 정확히 같은 시각의 묶음을 제외하되 내부의 근접 관측은 유지한다. 내부 FFLogs phase 경계는 보류한다. 분기 선택·참조 검사·종료 검열 학습의 경계 검사는 유지한다.                                                 |
| 동기화        | 추가한 반복 시전은 표시 event만 생성한다. 같은 ID·NPC의 다른 발생에 잘못 동기화하지 않도록 시계 보정은 기존 고유 기준점에 맡긴다.                                                                                                                                                                                                                                         |
| 자원 제한     | 묶음 수로 계산한 정렬 표 하나가 1,000,000칸을 초과하면 할당 전에 구간을 보류한다. 계산 제한을 불일치로 보고하지 않는다.                                                                                                                                                                                                                                                   |
| 근거          | `events[].alignment`의 방법은 `anchor-constrained-multiset-lcs-v2`다. 양끝 기준점, 기준 로그, 입력별 개별 관측 인덱스(`batches`)와 불확실성 묶음에 속한 관측 인덱스들(`groups`)을 기록한다. `alignment_diagnostics`의 `optimal_group_matches`는 묶음 대응 수다. 동률·한쪽에만 대응된 관측·보류 사유와 미출력 시전도 남긴다. 입력 관측의 `indices`로 원본 이벤트를 찾는다. |

예를 들어 `A B B C`와 `A B C`는 어느 B가 같은 발생인지 정렬로 구분할 수 없어 B를 출력하지 않는다. `A B U B C`와 `A U B C`는 U 뒤의 B만 대응시켜 `B-02`를 출력한다. 시간 근접도만으로 동률을 깨거나 미관측 발생을 실제 게임 분기로 확정하지 않는다.

`A {B,D} {B,D} C`에서 중괄호가 순서 미확정 묶음을 뜻할 때, 다른 로그가 `A {D,B} {D,B} C`여도 각 B·D를 대응시킨다. 묶음 내부의 같은 신호 반복 `{B,B}`는 개별 발생을 구분하지 않는다. 묶음 전체가 일치해야 하므로 한쪽의 `{B,D}`를 다른 쪽의 `{B}`에 부분 대응시키지는 않는다.

이 묶음은 실제 동시 실행·독립성 판정이 아니다. 예를 들어 0·80·160ms의 세 관측은 하나로 묶어 보수적으로 내부 순서를 모두 제외한다. 로그마다 관측 간격이 달라 묶음 구성이 바뀌면 대응을 보류할 수 있다. 부분 순서를 모두 활용하는 정렬과 누락된 묶음 구성원의 대응은 후속 과제다.

### 마지막 기준점 뒤의 종료 검열 학습

| 규칙 | 동작                                                                                                                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위 | NPC별 마지막 공통 기준점부터 관측 종료까지. 완료 로그의 조기 처치도 오른쪽 검열로 검사한다. raid는 미처치 로그도 사용한다. dungeon·alliance는 미처치 로그의 보스 시작 시계가 확정되지 않아 완료 로그만 사용한다. |
| 기준 | 구간의 관측 묶음이 가장 많은 trace를 사용하고 동률은 report/fight 문자열 순으로 정한다. kill 여부나 CLI 입력 순서로 선택하지 않는다.                                                                             |
| 진입 | 해당 기준점이 한 번 관측되어야 한다. 앞선 공통 기준점의 역전, 기준점 주변 순서 불확실성, 구간 내 FFLogs phase 경계는 미해결이다. 완료 로그의 범위가 미해결이면 그 NPC의 후반 학습을 보류한다.                    |
| 정렬 | 기존 모든 최적 접두부 정렬을 재사용한다. 각 발생은 최소 두 trace에서 강제 대응되어야 한다. 나머지 유효 trace는 모든 최적 종료 위치 뒤이며, 모든 지지 표본의 기준점 상대 시각보다 먼저 관측이 끝나야 한다.        |
| 누락 | 내부 누락·최적 대응 모호함·종료 전 침묵 구간을 중립 표본으로 취급하지 않는다. 불확실한 묶음 내부의 같은 신호 여러 회차도 추측하지 않는다.                                                                        |
| 출력 | 지지 trace의 시각 표본을 가진 표시 이벤트만 생성한다. 자동 sync는 추가하지 않는다. 기존 기준점·전멸·구역 변경 조건을 사용하며 FFLogs 종료를 실행 신호로 만들지 않는다.                                           |
| 근거 | `censored-tail-v1`에 기준점·참조·trace별 대응·종료 위치·차이·미해결 및 생성·거절 발생을 보존한다. 원본과 이벤트의 `samples`, `alignment.batches/groups`로 연결한다.                                              |
| 한계 | 마지막 기준점 뒤만 확장한다. 긴 로그의 중간 미해결 구간·추가 분기·반복 모델·보스 내부 페이즈는 별도 과제다. 두 trace의 대응은 통계적 독립성이나 기믹 동일성의 증명이 아니다.                                     |

예를 들어 두 긴 trace가 `A B B C`, 두 짧은 완료 trace가 `A`이면 A 이후의 B·B·C를 학습할 수 있다. 단, 짧은 trace의 종료가 B 예정 시각보다 빨라야 한다. B 시각 이후에도 기록이 계속되면 그 B는 학습을 막는 미해결 관측이며, 정상 검열로 숨기지 않는다.

### 미처치 로그의 참조 검사

입력의 `kill=false` 로그는 공통 기준점을 정하는 데 사용하지 않는다. 위 후반 학습에 사용한 경우에도 별도로 접두부 검사를 남기며 추가 CLI 옵션은 없다. `alignment_diagnostics`의 `method="censored-reference-prefix-v1"`에서 `training`은 해당 trace의 관측이 생성 이벤트의 시각 표본에 포함됐는지를 나타낸다. `training=true`인 검사는 독립 검증이 아니다. 이 검사는 생성 이벤트가 연결된 완료 참조 관측의 대응을 평가하며, KDL 실행·시각 검증이나 ACT 재생을 대체하지 않는다.

`kill=false`는 미처치·중단 기록을 포함한다. 실제 전멸 신호를 관측했다는 뜻으로 사용하지 않는다.

참조상 뒤의 고유 기준점이 검사 로그에서는 시작 기준점보다 먼저 관측되면 해당 범위를 `unresolved`로 남긴다. 순서가 바뀐 기준점으로 정렬을 시작해 앞서 관측된 기믹을 누락으로 오판하지 않는다.

| 항목      | 동작                                                                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기준      | 완료 로그 중 정렬용 기준 로그의 시전열을 사용한다. 출력에서 제외된 시전도 참조 시전열에 남아 있다.                                                                                     |
| 시작      | 같은 NPC의 고유 공통 기준점 중 전멸 로그에서 한 번 관측된 가장 이른 기준점을 사용한다. 앞부분이나 기준점 없는 NPC 범위는 미해결이다.                                                   |
| 정렬      | 순서 미확정 묶음의 삽입·삭제 비용은 각각 1, 일치는 0이다. 마지막 관측 이후의 참조 뒷부분은 무료로 생략한다. 모든 최적 종료 위치와 강제 대응을 보존한다.                                |
| 제한      | 기준점 주변 순서가 미확정이거나 참조·전멸 로그의 검사 범위에 FFLogs phase 경계가 있으면 보류한다. 정렬 표 제한도 동일하게 적용한다.                                                    |
| 위치 추적 | `scopes[].result.events`의 `event.activity`, `reference_at_ms`로 생성 이벤트의 참조 sample을 찾는다. `matched`의 `batch`와 진단의 관측 인덱스는 해당 입력의 `observations`를 가리킨다. |

| 이벤트 상태  | 뜻                                                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `matched`    | 모든 최적 정렬에서 같은 관측으로 대응된다. 실제 기믹 동일성이나 일정 시각의 정확성을 보장하지 않는다.                                                                                       |
| `ambiguous`  | 최적 정렬의 대응·종료가 다르거나 묶음 내부의 동일 신호 여러 발생을 구분할 수 없다.                                                                                                          |
| `unobserved` | 모든 최적 종료 위치 이후의 참조 뒷부분이며, 기준점에 대한 모든 학습 시각 표본도 관측 종료 이후에 놓인다.                                                                                    |
| `mismatch`   | 모든 최적 정렬에서 뒷부분 종료 이전의 참조 묶음이 삭제되고, 해당 신호 자체도 검사한 전멸 관측에 없다. 참조와 관측의 차이이며 실제 게임의 누락이나 생성기의 잘못으로 원인을 확정하지 않는다. |
| `unresolved` | 기준점·구성원 대응이 불명확하거나, 정렬상 뒷부분이어도 학습 시각이 관측 기간과 겹친다. 침묵 구간의 시전 누락을 정상 종료로 간주하지 않는다.                                                 |

예를 들어 참조 `A B B C`와 전멸 관측 `A B`의 최적 접두부는 첫 B에서 끝나지만, 관측이 두 번째 B의 학습상 예정 시각 이후까지 계속됐다면 그 B는 미해결이다. 참조 `A X C`와 관측 `A C`는 X 삭제와 C 미대응·조기 종료가 동률일 수 있으므로 단순히 X 누락으로 확정하지 않는다. 범위 결과의 `evaluated`와 명령 성공은 품질 통과가 아니다.

분기·반복 모델의 적합도, 생성 KDL의 보정된 일정 시각, ACT 신호 동등성은 아직 검사하지 않는다. 여러 시도가 한 FFLogs fight에 들어간 경우도 자동 분할하지 않는다.

### 입력 로그의 자동 검증

사용자는 로그들과 mode만 입력한다. 검증 로그 선택은 생성기가 수행하며 별도 holdout 옵션은 없다. 검사·정규화는 모든 입력에 공통으로 적용하고 같은 보고서/전투의 복사본·수정본이나 잘못된 입력은 기존 입력 검사에서 거부한다.

| 단계      | 정책                                                                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 선택      | 완료 로그가 3개 이상이면 보고서 코드의 사전순, 전투 ID의 숫자순으로 가장 큰 한 개를 고른다. 입력 인자 순서나 파일 이름을 바꿔도 선택이 바뀌지 않는다. 무작위 선택이나 검증 결과에 따른 재선택은 하지 않는다.             |
| 임시 모델 | 선택한 완료 로그를 제외하고 공통 진행을 학습한다. raid의 임시 모델에는 미처치 입력의 후반 학습도 포함한다. dungeon·alliance의 Boss 범위도 해당 학습 로그의 메타데이터로 한정한다. 선택한 로그를 이 임시 모델과 비교한다. |
| 최종 모델 | 모든 완료 로그와 정책상 허용되는 미처치 후반 표본으로 생성한다. 검증용 완료 로그도 최종 학습에는 포함한다. 검증 결과는 임시 모델에 대한 결과이며 최종 모델이 독립적으로 검증됐다고 표시하지 않는다.                      |
| 자료 부족 | 완료 로그가 2개면 최종 생성은 수행하되 독립 검증은 `insufficient-completed-pulls`로 기록한다. 미처치 로그는 완료 로그 수에 넣지 않는다.                                                                                  |
| 모델 실패 | 임시 학습의 순서 충돌·공통 발생 부재는 `unresolved`로 이유를 남긴다. 최종 학습이 가능하면 생성은 계속하며 실패를 검증 성공으로 간주하지 않는다.                                                                          |

계산량을 제한하기 위해 한 분할만 검사한다. 모든 분할·모든 패턴을 평가하거나 보고서 간 통계적 독립성을 증명하는 검사는 아니다.

| holdout 종류 | 정렬과 종료 처리                                                                                                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kill=true`  | `complete-reference-alignment-v1`: 기준점 이후의 참조 열 전체와 관측 열을 정렬한다. 미대응 참조 뒷부분도 삭제 비용을 부과한다.                                                                                                                 |
| `kill=false` | `censored-reference-prefix-v1`: 기존 접두부 검사처럼 참조 뒷부분의 무료 종료를 허용한다.                                                                                                                                                       |
| 빠른 처치    | 완료 로그의 미대응 이벤트라도 모든 학습 시각 표본이 해당 처치 종료 뒤에 놓이면 `unobserved`로 남긴다. 처치 종료 전에 놓이는 차이를 무료 종료로 숨기지 않는다. 이 시간 검사는 학습 기준점에 대한 추정이며 실제 runtime 시계 보정 검증이 아니다. |

검사 범위·미해결 처리·관측 추적은 위 접두부 검사와 같다. `analysis.inputs`에 모든 입력의 해시·언어·관측 인덱스를 보존한다. `alignment_diagnostics`에서 `method="automatic-validation-v1"`인 항목의 `policy`, `split`, `model_events`, `checks`로 선택 정책·학습 및 검증 trace·임시 모델·검사 결과를 추적한다. `model_events.samples`에는 임시 학습 입력만 들어간다. 최상위 `events[].samples`는 최종 모델에서 실제로 지지한 trace를 보존하며 후반에서는 일부 완료·미처치 입력만 포함할 수 있다. 미처치 입력의 접두부 검사는 별도로 남긴다.

완료 참조 로그에 없는 후반 이벤트는 `event not observed in completed comparison reference`로 미해결이다. 후반 표본의 비교용 시작 시각이 부족해 종료 검열을 평가할 수 없을 때도 미해결로 남긴다. 후반 학습의 자체 대응 검사와 완료 참조 검사의 범위를 혼동하지 않는다.

이 검사는 임시 학습 완료 로그의 참조 시전열과 임시 모델 이벤트에 연결된 관측을 평가한다. 최종 KDL 실행 경로 전체와 시각이 검증됐다는 뜻은 아니다. `matched`뿐 아니라 `mismatch`, `ambiguous`, `unresolved`, `peer_only`를 함께 검토해야 한다. 명령의 성공 종료와 `evaluated`는 검사 처리 완료를 뜻하며 자동 품질 통과를 뜻하지 않는다.

### 국소 순서 분기: 첫 구현

| 항목        | 현재 지원                                                                                                                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위        | raid에서 한 국소 순서 분기를 생성한다. 고유 공통 시전의 순서가 뒤바뀐 구간을 대상으로 하며, 관측 누락만으로 선택지를 만들지 않는다. dungeon·alliance의 분기와 추가 분기의 상관관계는 미해결로 기록한다.                                           |
| 공통 진행   | 100ms 해상도에서 모든 완료 로그가 동의하는 선후 관계로 그래프를 만든다. 순서 충돌이 있으면 모든 최장 사슬이 공유하는 기준점만 선택한다. 동률인 사슬 하나를 임의로 고르지 않는다.                                                                  |
| 선택        | 같은 NPC의 연속 공통 기준점 사이를 검사한다. 도입부는 combat 시작 이후부터 첫 공통 기준점까지 허용한다. 각 로그에서 가장 먼저 관측된 고유 공통 활동을 선택 신호로 사용하며, 순서 미확정 묶음 안에 여러 선택 신호가 있으면 보류한다.               |
| 옵션 본문   | 같은 선택으로 시작한 로그를 모아 다시 정렬한다. 해당 옵션의 모든 최적 정렬에서 강제되는 발생만 표시하며 묶음 내부의 동일 신호 여러 발생은 추측하지 않는다. 옵션 시각은 선택 신호를 0으로 삼고 자동 sync는 넣지 않는다.                            |
| 선택 window | 관측 범위에 최소 2.5초 여유를 시도하고 도입부는 최초 시계 오차를 고려해 10초를 시도한다. 전체 로그의 경쟁 선택 신호를 배제하고 가장 늦게 선택해도 생성 본문이 공통 후속 일정 전에 끝나도록 줄인다. 모든 관측을 포함하는 window가 없으면 보류한다. |
| 합류        | 현재는 공통 후속 일정을 branch 밖에 공유한다. 해당 일정은 phase 시각과 sync를 사용하며 분기 본문은 그 전에 끝난다. 신호마다 합류 시각이 달라지는 명시적 `merge` 생성은 후속 과제다.                                                               |
| 시계와 ID   | branch가 있으면 raid 본문을 `combat` phase에 두어 공통 sync와 옵션이 같은 phase 시계를 공유한다. 옵션별 이벤트 ID에는 합류 기준점·선택 능력 ID를 포함해 문서 전체에서 구별한다.                                                                   |
| 근거        | `consensus-backbone-v1`에 공통 뼈대 밖 활동과 표본을 기록한다. `local-order-branch-v1`에 생성·보류와 선택별 trace를 기록하고, 출력 이벤트에는 `branch`, `option`, `selection_samples`와 원본 묶음 연결을 남긴다.                                  |

예를 들어 `A B C D`와 `A C B D`는 A·D를 공유하고, 먼저 B를 관측하는 옵션과 먼저 C를 관측하는 옵션을 만든다. 선택 창은 뒤쪽의 반대 신호를 받기 전에 닫는다. `A B C D`와 `A B D`처럼 발생이 없는 것만으로 분기를 확정하지 않는다. 선택 신호가 없으면 옵션을 추정하지 않으며 공통 후속 일정은 계속 진행한다.

원본 로그로 확인한 R11S 사례는 `c36H8h2aqXwkgtjR/3`, `4kt1bfqJn7QPCj29/2`, `fDhKygMQ3VCvZat8/2`다. Raw Steel Trophy `B422`·`B423`의 약 18초/157초 순서 교환을 도입부 한 branch로 표현한다. 세 로그로 112개 이벤트 정의를 생성했으며 후속 상관 선택은 미해결이다. combat 시작을 0으로, FFLogs cast를 Ability로 가정한 합성 관측에서는 각 로그의 도입부 선택을 한 번씩 재생했다. 이 투영은 ACT 신호 동등성·실제 실행·전체 관측 커버리지 검증이 아니다.

현재는 공통 시전 본문·동기화, raid의 한 국소 순서 분기, dungeon·alliance의 보스별 phase를 생성한다. 보스 내부 페이즈·상관 분기·가변 합류·반복·시전 외 이벤트의 본문 생성, 서로 다른 encounter 입력의 연결과 실제 ACT/runtime 검증은 남아 있다. 자동 검증의 참조 정렬은 분기 경로 자체를 평가하지 않으며 합성 KDL 재생과 구분한다.

cargo test --test generate

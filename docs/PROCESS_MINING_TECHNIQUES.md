# 남은 타임라인 마이닝에 유용한 기법

확인일: 2026-11-01. 구현 제안이며 성능·정확도 검증 결과가 아니다. Rust 본체와 Bun 스크립트 안에서 진행하고 Python 런타임은 추가하지 않는다.

## 누락 감사 이후의 우선순위

[발생·경로 누락 감사](R11S_OMISSION_AUDIT.md)에서 확인한 문제는 관측 부족과 분석기의 지나치게 큰 제외 범위를 구분해야 한다. 표시 일정에 필요한 근거와 시계 보정에 필요한 근거를 분리한다. 아래 적용안은 논문의 기법을 이 프로젝트에 제한해서 도입하는 설계이며, 논문 구현을 그대로 채택하거나 성능·정확도를 보장한다는 뜻이 아니다.

| 순서 | 기법과 상태                                                   | 적용 범위                                                                                                                                                                                                                   | 검증 조건                                                                                                                                                                              |
| ---- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | 경계 불확실성의 국소 처리: 인접 기준점 사이 표시 정렬에 구현  | 기준점에서 45ms 떨어진 표시 관측 때문에 구간 전체를 버리지 않는다. 강제 대응된 내부 이벤트를 sync 없이 생성한다. 정확히 경계 시각인 묶음은 제외 근거를 보존한다. 분기 선택·참조 검사·종료 검열 학습의 경계 규칙은 유지한다. | 양끝 근처·정확한 경계 시각·실제 phase 경계·원본 시각 보존을 raid/dungeon/alliance에서 검사. 시전 순서나 새 sync를 추측하지 않는다.                                                     |
| 1    | [불확실한 이벤트 분석][uncertain]: 미구현                     | 원본 actor/instance·시전 시작/완료·시각 범위를 사용해 1–2ms로 갈라진 복수 개체 파동의 후보를 구성한다. 원본 밀리초·개수·각 후보의 지지와 반례를 보존한다.                                                                   | 같은 개체의 실제 반복, 다른 시각의 별도 파동, 누락된 인스턴스와 구분한다. 가까운 같은 ID라는 이유만으로 합치지 않는다. actor ID는 분석 근거에만 사용한다.                              |
| 2    | [부분 순서 정렬][partial-order]과 국소 비용 기반 정렬: 미구현 | 묶음 전체를 한 토큰으로만 비교하지 않고 확실한 선후 관계를 DAG로 보존한다. 삽입·누락·시간 차이는 명시적인 비용으로 다루고 계산 제한과 동률을 기록한다.                                                                      | `{A,B}`와 `{A}`에서 A의 대응을 별도로 평가한다. 0·80·160ms 관측에서 해상도상 확실한 0→160 관계까지 잃지 않는다. 최저 비용 경로 하나를 정답으로 고르거나 비용을 확률로 표시하지 않는다. |
| 3    | [Decision mining][decision]과 선택 이력 유지: 미구현          | 선행 선택을 상태로 학습해 `A→공통→B`와 `B→공통→A`를 구분한다. 선택에 종속된 미래는 기존 option에 유지하고 후속 조건부 선택에는 기존 requires를 사용한다.                                                                    | 공통 이벤트 하나만으로 합류하지 않는다. 관측된 대안·순열을 보존하되 임의 경로 조합을 만들지 않는다. 미래 관측을 runtime 선택 조건으로 사용하지 않는다.                                 |
| 4    | 액터 간 관측 연결: 미구현                                     | 자신의 고유 기준점이 없는 반복 helper도 이미 확정된 전투 구간과 대응시킨다.                                                                                                                                                 | 보스와 helper의 원본 이름·개체·범위 근거를 보존한다. 무관한 액터·잡몹, 기준점 없는 구간은 연결을 확정하지 않는다.                                                                      |
| 5    | 발생·경로별 적합도 검사: 미구현                               | 표시·sync·회차 대응의 근거를 각각 평가하고 누락·과잉 경로·잘못된 병합을 기록한다.                                                                                                                                           | ID가 한 번 출력됐거나 생성 KDL이 재생됐다는 이유로 다른 회차·다른 옵션까지 검증됐다고 하지 않는다.                                                                                     |

### 표시와 동기화의 서로 다른 기준

| 판단                                      | 표시 일정                                                                                                           | sync·실행 선택 조건                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 발생은 확실하지만 원본 개체 대응만 모호함 | 향후 분석기가 발생 개수와 일정의 일관성을 확인하면 표시 후보를 유지한다. 모든 가능한 원본 대응을 evidence에 남긴다. | 모호한 발생을 자동 sync로 승격하지 않는다.                |
| 순서만 불확실하고 개별 발생은 대응됨      | 확실한 부분만 표시하고 내부 순서의 인과관계를 만들지 않는다.                                                        | 회차·활성 구간과 경쟁 신호를 구별할 수 있어야 한다.       |
| 선택별로 시각이나 ID가 달라짐             | 선택별 일정을 유지한다. 불가능한 중간 시각으로 중앙값을 내지 않는다.                                                | 이미 관측한 선택과 현재 사용 가능한 신호만 조건으로 쓴다. |
| 근거 부족 또는 반례가 있음                | 후보와 이유를 보존하되 모든 후보를 KDL에 무조건 표시하지 않는다.                                                    | 미해결로 남긴다.                                          |

기본 활동의 ID·NPC 이름은 시간 비용으로 바꾸어 맞추지 않는다. 서로 다른 ID의 대안은 경로·후속 구조를 별도로 학습한 근거가 있어야 한다. 분석상의 불확실성은 evidence에 두고, 최종 KDL은 기존 event·branch·requires·sync로 결정적인 실행 의미를 갖게 한다. 신규 runtime 확률·시계·템플릿·CLI 정책 옵션은 추가하지 않는다.

현재 의존성을 유지하며 이 순서로 기존 정렬기를 보완한다. 별도 Inductive Miner, ML·SMT 라이브러리 도입은 이번 구현의 선행 조건이 아니다. R11S의 전투·능력 ID·고정 시각은 회귀 자료로만 사용하고, 합성 ID·시각·인스턴스 변형 및 다른 raid/dungeon으로 검증한다.

## 기존 기반 기법과 후속 과제

아래 적용 방법은 논문·라이브러리 기능을 이 프로젝트에 맞게 제한한 제안이다. 자동으로 얻을 수 있다고 확인한 기능과 구분한다.

| 순서 | 기법                                | 적용 방법·예시                                                                                                                                                                                                           | 채택 조건과 주의점                                                                                                                                                                                                                                                    |
| ---- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 구간 분리와 기준점 사이의 발생 정렬 | 보스·전투 시도·확인된 phase 경계를 먼저 분리하고 고유 기준점 사이 신호열을 삽입·삭제 허용 동적 계획법으로 대응한다. `A B B C`와 `A B C`에서 B의 순번만으로 회차를 정하지 않고 주변 신호와 구간 내 상대 시각을 함께 본다. | 최적 대응이 여럿이면 모호함을 남긴다. 같은 시각 batch는 부분 순서를 유지한다. 시간은 보조 근거로 쓰며 누락을 조용히 보정하지 않는다. 기존 crate의 정렬은 **로그↔Petri net** 정렬이므로 **로그↔로그** 정렬을 그대로 제공하는 것은 아니다. [정렬 구현][alignments]      |
| 2    | 국소 process tree 분해              | 기준점 사이 후보를 sequence·XOR·loop로 분해한다. `A X C` / `A Y C`라면 A와 C 사이의 분기·합류 후보를 찾는다. Inductive Miner의 재귀적 cut 관점이 유용하다.                                                               | XOR를 실행하려면 선택 시점에 구별 가능한 게임 신호가 필요하다. `A B C` / `A C B`만으로 AND나 독립 게임 경로를 확정하지 않는다. process tree의 soundness는 게임 의미의 정확성과 다르다. [원 논문][im-paper]                                                            |
| 3    | 반복 본문 후보와 정렬의 결합        | 현재 exact repeat를 후보로 유지하고 여러 풀·여러 회차에 대응한다. `A B A B A…`에서 끝의 A는 완전한 새 회차와 구별해 보존한다.                                                                                            | 누락된 내부 B와 전멸로 관측이 끝난 suffix를 구분한다. 무한 반복·탈출 신호·회차별 시간은 관측과 KDL 계약으로 따로 확정한다. [현재 반복 분석](../src/generate/mining/repeats.rs), [loop 연산자 정의][im-paper]                                                          |
| 4    | 전멸 prefix를 고려한 검증           | 완료 풀에서 후보 구조를 만들고 전멸 풀은 관측된 prefix까지만 대조한다. `A B`에서 끝난 wipe가 `A B C` 모델의 C를 반증하지 않게 한다.                                                                                      | 관측 종료 이전의 실제 누락은 계속 오류 후보로 남긴다. 설치된 full alignment는 최종 marking 도달도 요구하므로 그대로 wipe 점수에 사용하지 않는다. prefix 처리에는 별도 목표 상태 규칙이 필요하다. [설치 구현][alignment-goal], [프로젝트 재생 계약](OFFLINE_REPLAY.md) |
| 5    | 빈도 기반 잡음 필터와 보류 검증     | 정렬 이후에도 남는 드문 간선·신호를 후보 단계에서 가려 보고, 제외된 관측과 이유는 evidence에 남긴다. IMf는 비교용 후보 생성에 적합하다.                                                                                  | 드문 실제 기믹도 사라질 수 있으므로 빈도만으로 제거하지 않는다. 학습에 쓰지 않은 report의 완료·전멸 풀로 누락, 과도한 선택 허용, 회차 혼동을 비교한다. [필터 API][filter], [fitness·precision 구분][im-paper]                                                         |

기존의 기준점 정렬·접두부 검사는 구현되어 있다. 이제 위 누락 감사 이후의 순서로 대응 품질을 보완하고 그 결과로 국소 구조·반복 분석을 확장한다. DFG 전체를 즉시 실행 그래프로 바꾸거나 채굴기를 교체하는 것을 선행 조건으로 두지 않는다.

## 경계 표시 완화의 실제 검증

이 단계는 부분 순서 정렬 전체의 구현이 아니다. 양끝 기준점 사이 표시 관측을 포함해 기존 모든 최적 LCS 대응을 계속 검사하는 수정이다. 모든 기준점·시각·ID는 입력에서 얻으며 콘텐츠별 예외를 추가하지 않았다.

| 자료                          | 이전 → 이후      | 확인한 범위                                                                                                                                                                                                        |
| ----------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R11S 기존 8개 입력            | 150 → 162개 정의 | Atomic Impact 6회 중 5회, B456·B457 각각 1회와 B455 5회를 표시용으로 복원. 새로 복원한 행에 sync 없음. 나머지 Atomic Impact 1회는 다른 로그의 묶음 구성 차이 때문에 미해결. B455의 표시 역할은 아직 정제하지 않음. |
| R9S 기존 회귀 3개             | 54 → 54개        | 기존 정의 삭제·반올림 시각 변경 없음                                                                                                                                                                               |
| R10S 기존 회귀 3개            | 129 → 140개      | 기존 정의 삭제·반올림 시각 변경 없음                                                                                                                                                                               |
| Clyteum dungeon 기존 회귀 3개 | 45 → 45개        | 기존 정의 삭제·반올림 시각 변경 없음                                                                                                                                                                               |
| 합성 사례·회귀                | 339개 테스트     | 양끝 근접·정확한 경계 묶음·phase 경계, raid/dungeon/alliance, 기존 분기·접두부·종료 검열 검사. Clippy 경고 없음과 포맷 확인.                                                                                       |

R11S 입력은 [기존 manifest](r11s-long-inputs.csv)와 같다. 비교용 생성본은 `out/r11s-display-boundary.kdl`과 같은 이름의 evidence다. 다른 콘텐츠의 입력 trace는 [감사 전 검증 기록](R11S_TAIL_IMPROVEMENT.md#종료-검열-학습과-확대-입력-결과)과 같다. 이벤트 정의 수 증가는 실제 기믹 커버리지나 표시 품질의 보증이 아니다. 이 단계에서는 선택 이력, helper 연결, 1–2ms 파동 분절과 부분 묶음 대응을 해결하지 않는다.

같은 8개 입력의 cast→Ability, combat 시작=0 가정으로 합성 재생도 수행했다. 각 trace에서 한 도입부 옵션을 선택했고 ambiguous·unresolved·violation은 없었다. 결과는 `out/r11s-display-boundary-projection.json`이다. 이 검사는 생성된 경로의 실행만 검사하며 누락된 경로·ACT 신호 동등성·실제 실행기는 검증하지 않는다.

## Rust 라이브러리에서 실제로 쓸 수 있는 범위

| 대상                                                | 확인한 기능                                                                                                                                                                                                           | 이 프로젝트에서의 판단                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `process_mining =0.6.2`, `default-features = false` | 설치된 소스에서 `align_trace`, `align_variants`, `SyncMove`·`ModelMove`·`LogMove`, 네 종류 이동 비용과 `max_states`를 확인했다. 기본 탐색 한도는 trace당 100,000 상태다. alignments는 별도 feature로 차단되지 않는다. | 새로운 의존성 없이 **이미 만든 Petri net 후보와 관측열의 부합도**를 실험할 수 있다. 시간 비용·부분 순서·동률인 모든 대응·wipe prefix 처리를 자동 제공한다고 가정하지 않는다. 탐색 한도 초과는 불일치와 구별해야 한다. ## 검증할 최소 사례

| 사례                                         | 기대 결과                                                              |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| 반복 기술의 첫 발생만 누락                   | 뒤 회차 전체를 한 칸씩 밀지 않으며, 구분 불가능하면 모호함으로 남긴다. |
| 같은 밀리초 batch 내부 패킷 순서 교환        | 동일한 대응·후보 구조를 얻는다.                                        |
| 같은 앞뒤 기준점 사이의 두 선택지            | 공통 suffix를 중복 생성하지 않고 선택 신호와 합류 근거를 보존한다.     |
| 반복 도중 전멸 / 관측 종료 전 내부 신호 누락 | 앞 사례의 미래 suffix는 미관측, 뒤 사례는 실제 누락 후보로 구분한다.   |
| 드물지만 실제인 분기                         | 잡음 필터로 사라졌는지 독립 풀과 제외 근거에서 확인한다.               |

최종 KDL은 evidence 없이 실행 가능해야 한다. 오프라인 마이닝·정렬 결과는 ACT 신호 대응, 영어 NPC 이름, 외부 실행기 또는 실제 게임 호환성의 검증을 대신하지 않는다. [생성 계약](GENERATION.md), [구현 계획](PLAN.md)

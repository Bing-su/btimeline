# 남은 타임라인 마이닝에 유용한 기법

확인일: 2026-11-01. 구현 제안이며 성능·정확도 검증 결과가 아니다. Rust 본체와 Bun 스크립트 안에서 진행하고 Python 런타임은 추가하지 않는다.

## 현재 출발점

| 확인한 코드                                     | 현재 동작                                                                                               | 다음 작업에 미치는 영향                                                                             |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [mining.rs](../src/generate/mining.rs)          | 같은 밀리초 신호를 batch로 묶고 batch 사이 DFG를 구성한다. 원본 인덱스·시각·kill·종료 시각을 보존한다.  | 이 표현을 유지하며 발생 대응을 추가할 수 있다. 같은 batch 안에 임의 순서를 만들 필요가 없다.        |
| [common.rs](../src/generate/mining/common.rs)   | 완료 풀 둘 이상에서 한 번씩 등장하는 신호만 공통 기준점으로 삼는다. 일치하는 부분 선후 관계는 보존한다. | 반복 신호의 회차 대응이 우선 과제다. 관측 순서 불일치를 곧바로 게임의 병렬 경로로 해석하면 안 된다. |
| [repeats.rs](../src/generate/mining/repeats.rs) | phase 경계를 나누고 정확히 같은 batch 열의 최단 반복 본문을 탐욕적으로 찾는다.                          | 누락·선택지가 낀 반복과 겹치는 후보는 별도 검증이 필요하다.                                         |
| [render.rs](../src/generate/render.rs)          | 고유 공통 cast와 보스별 phase를 생성하며 공통 순서 충돌은 거부한다.                                     | 분석 후보를 얻는 것과 실행 가능한 branch·loop KDL 생성은 별도 단계다.                               |

## 추천 순서

아래 적용 방법은 논문·라이브러리 기능을 이 프로젝트에 맞게 제한한 제안이다. 자동으로 얻을 수 있다고 확인한 기능과 구분한다.

| 순서 | 기법                                | 적용 방법·예시                                                                                                                                                                                                           | 채택 조건과 주의점                                                                                                                                                                                                                                                    |
| ---- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 구간 분리와 기준점 사이의 발생 정렬 | 보스·전투 시도·확인된 phase 경계를 먼저 분리하고 고유 기준점 사이 신호열을 삽입·삭제 허용 동적 계획법으로 대응한다. `A B B C`와 `A B C`에서 B의 순번만으로 회차를 정하지 않고 주변 신호와 구간 내 상대 시각을 함께 본다. | 최적 대응이 여럿이면 모호함을 남긴다. 같은 시각 batch는 부분 순서를 유지한다. 시간은 보조 근거로 쓰며 누락을 조용히 보정하지 않는다. 기존 crate의 정렬은 **로그↔Petri net** 정렬이므로 **로그↔로그** 정렬을 그대로 제공하는 것은 아니다. [정렬 구현][alignments]      |
| 2    | 국소 process tree 분해              | 기준점 사이 후보를 sequence·XOR·loop로 분해한다. `A X C` / `A Y C`라면 A와 C 사이의 분기·합류 후보를 찾는다. Inductive Miner의 재귀적 cut 관점이 유용하다.                                                               | XOR를 실행하려면 선택 시점에 구별 가능한 게임 신호가 필요하다. `A B C` / `A C B`만으로 AND나 독립 게임 경로를 확정하지 않는다. process tree의 soundness는 게임 의미의 정확성과 다르다. [원 논문][im-paper]                                                            |
| 3    | 반복 본문 후보와 정렬의 결합        | 현재 exact repeat를 후보로 유지하고 여러 풀·여러 회차에 대응한다. `A B A B A…`에서 끝의 A는 완전한 새 회차와 구별해 보존한다.                                                                                            | 누락된 내부 B와 전멸로 관측이 끝난 suffix를 구분한다. 무한 반복·탈출 신호·회차별 시간은 관측과 KDL 계약으로 따로 확정한다. [현재 반복 분석](../src/generate/mining/repeats.rs), [loop 연산자 정의][im-paper]                                                          |
| 4    | 전멸 prefix를 고려한 검증           | 완료 풀에서 후보 구조를 만들고 전멸 풀은 관측된 prefix까지만 대조한다. `A B`에서 끝난 wipe가 `A B C` 모델의 C를 반증하지 않게 한다.                                                                                      | 관측 종료 이전의 실제 누락은 계속 오류 후보로 남긴다. 설치된 full alignment는 최종 marking 도달도 요구하므로 그대로 wipe 점수에 사용하지 않는다. prefix 처리에는 별도 목표 상태 규칙이 필요하다. [설치 구현][alignment-goal], [프로젝트 재생 계약](OFFLINE_REPLAY.md) |
| 5    | 빈도 기반 잡음 필터와 보류 검증     | 정렬 이후에도 남는 드문 간선·신호를 후보 단계에서 가려 보고, 제외된 관측과 이유는 evidence에 남긴다. IMf는 비교용 후보 생성에 적합하다.                                                                                  | 드문 실제 기믹도 사라질 수 있으므로 빈도만으로 제거하지 않는다. 학습에 쓰지 않은 report의 완료·전멸 풀로 누락, 과도한 선택 허용, 회차 혼동을 비교한다. [필터 API][filter], [fitness·precision 구분][im-paper]                                                         |

먼저 1번을 작은 합성 예제로 확인하고, 그 대응 결과로 2·3번을 확장하는 편이 좋다. DFG 전체를 즉시 실행 그래프로 바꾸거나 완성된 채굴기를 교체하는 것보다 기존 근거를 활용하기 쉽다.

## Rust 라이브러리에서 실제로 쓸 수 있는 범위

| 대상                                                | 확인한 기능                                                                                                                                                                                                           | 이 프로젝트에서의 판단                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `process_mining =0.6.2`, `default-features = false` | 설치된 소스에서 `align_trace`, `align_variants`, `SyncMove`·`ModelMove`·`LogMove`, 네 종류 이동 비용과 `max_states`를 확인했다. 기본 탐색 한도는 trace당 100,000 상태다. alignments는 별도 feature로 차단되지 않는다. | 새로운 의존성 없이 **이미 만든 Petri net 후보와 관측열의 부합도**를 실험할 수 있다. 시간 비용·부분 순서·동률인 모든 대응·wipe prefix 처리를 자동 제공한다고 가정하지 않는다. 탐색 한도 초과는 불일치와 구별해야 한다. [고정 버전 소스][alignments]                                                                                    |
| 같은 `process_mining 0.6.2`의 discovery             | case-centric discovery 모듈은 `alphappp`와 `dfg`를 공개한다. Inductive Miner는 없다. 현재 프로젝트 호출도 DFG 자료형 사용뿐이다.                                                                                      | 최신 소개나 다른 라이브러리의 IM 지원을 설치 버전의 기능으로 취급하지 않는다. [고정 버전 discovery 소스][discovery]                                                                                                                                                                                                                   |
| 별도 `inductive_miner 0.2.0`                        | 공식 crate 문서상 2026-10-06 릴리스. IM·IMf·IMc 계열과 자체 EventLog·ProcessTree 타입이 있다. control-flow 전용이며 시간 제약을 학습하지 않는다. 의존성 목록에는 선택 표시 없는 `z3 ^0.21.1`이 있다.                  | Rust 후보로는 검토할 만하지만 즉시 추가할 이유는 부족하다. 데이터 변환·Z3 빌드 환경·정확성·성능을 작은 독립 실험으로 먼저 확인한다. IMc의 incomplete-log 지원이 wipe suffix 검열 지원을 뜻한다고 가정하지 않는다. 문서의 보장도 명시한 모델 클래스와 전제를 가진 주장이다. [crate 메타데이터와 한계][new-crate], [공개 타입][new-api] |

## 검증할 최소 사례

| 사례                                         | 기대 결과                                                              |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| 반복 기술의 첫 발생만 누락                   | 뒤 회차 전체를 한 칸씩 밀지 않으며, 구분 불가능하면 모호함으로 남긴다. |
| 같은 밀리초 batch 내부 패킷 순서 교환        | 동일한 대응·후보 구조를 얻는다.                                        |
| 같은 앞뒤 기준점 사이의 두 선택지            | 공통 suffix를 중복 생성하지 않고 선택 신호와 합류 근거를 보존한다.     |
| 반복 도중 전멸 / 관측 종료 전 내부 신호 누락 | 앞 사례의 미래 suffix는 미관측, 뒤 사례는 실제 누락 후보로 구분한다.   |
| 드물지만 실제인 분기                         | 잡음 필터로 사라졌는지 독립 풀과 제외 근거에서 확인한다.               |

최종 KDL은 evidence 없이 실행 가능해야 한다. 오프라인 마이닝·정렬 결과는 ACT 신호 대응, 영어 NPC 이름, 외부 실행기 또는 실제 게임 호환성의 검증을 대신하지 않는다. [생성 계약](GENERATION.md), [구현 계획](PLAN.md)

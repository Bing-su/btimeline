# P6 독립 재생·holdout 평가

실행일: 2026-10-05. 독립 재생 도구는 구현했지만 모든 경로의 내부 검증 완료를 뜻하지 않는다. 공식 parser/runtime은 실행하지 않았다.

## 실행 계약

| 명령                                                                                                 | 산출물·검사                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `btimeline replay draft.yaml LOG_OR_DIRECTORY -o replay.json`                                        | 생성 근거를 기본 `draft.report.json` 또는 `--report PATH`에서 읽는다. 새 `replay.json`·`replay.md`를 저장하며 실패 진단도 보존한 뒤 비정상 종료한다. 기존 파일을 덮어쓰지 않는다.                           |
| `nu scripts/evaluate_replay.nu docs/evaluation-inputs.csv /tmp/p6 --binary target/release/btimeline` | SHA-256·수집 완료·전투 참조·후보 split을 검사한다. train만 생성에 사용하고 train/holdout 및 중복 후보 전체 제외 평가를 분리한다. `evaluation.json`·`evaluation.md`와 그룹별 원본·초안·재생 근거를 보존한다. |
| `nu scripts/test_evaluate_replay.nu target/release/btimeline`                                        | 새 합성 encounter의 반복 B528 재생, holdout 누출·해시 변경·후보 split 충돌·그룹 참조 오류·덮어쓰기 거부를 검사한다.                                                                                         |

| 항목      | 독립 재생 정책·한계                                                                                                                                                                                                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시계      | 매 파일의 fight start에서 0으로 시작한다. 유일한 활성 sync에 매칭한 뒤 해당 행 시각 또는 jump 목적지로 보정한다. 파일 사이 시계·소비한 행 상태를 공유하지 않는다.                                                                                                                  |
| 활성 조건 | SPEC의 default ±2.5초 또는 명시 window를 사용하며 경계는 포함한다. 여러 활성 행이 같은 신호를 받으면 선택하지 않고 `ambiguousMatches`로 보고한다. 실제 runtime의 선택 순서를 주장하지 않는다.                                                                                      |
| 원본      | 정규화에서 제외한 아군·melee·동시 instance cast까지 원본의 모든 cast/begincast를 재생한다. FFLogs의 ID·능력명·source/target 이름을 사용하며 ACT actor ID·raw line을 만들어내지 않는다.                                                                                             |
| 대응 근거 | 알려진 입력은 생성 report의 대표 index를 사용한다. holdout의 대응은 P5 정렬 근거가 reached train 경로 사이에서 일치해야 한다. 이 대응은 sync 선택 이후 판정에만 쓰며 가상 시계의 선택에 개입하지 않는다.                                                                           |
| 행 식별   | `entryIndex`는 현재 YAML `entries`의 0 기반 index다. event 행의 원래 순서·개수는 유지해야 하며 이름·시각·window·jump 편집은 재생으로 검사할 수 있다.                                                                                                                               |
| 종료·누락 | kill/wipe 뒤 미관측 완료를 `unobservedAfterEnd`로 분리한다. 시전 시작만 남은 원본은 `unfinishedStarts`에 보존한다. 관측 신호 누락, 활성 창 미검출, 대응 미확정을 별도 집계한다.                                                                                                    |
| jump·반복 | sync jump, label·시간 목적지, 유한 반복, backward jump와 합류를 검사한다. 0으로 sync jump하면 해당 재생을 멈춘다. forcejump도 신호 없는 시각에 실행하지만 동일 시각의 경쟁 exit/forcejump는 미지원으로 보고한다. 한 pull의 10,000회 jump 상한 또는 진행하지 않는 cycle은 실패한다. |
| 미지원    | ACT raw regex, FFLogs에서 확인할 수 없는 network field, 경쟁 forcejump 우선순위, 실제 lookahead 표시는 통과로 가정하지 않는다. `StartsUsing`은 엔진 신호로 지원하되 현재 생성 초안의 행은 완료 `Ability`다.                                                                        |
| 부분 범위 | 대표 행과 직접 대응한 원본만 판정한다. 비활성 sync는 관측·시간 오차를 보고하며 시계를 보정하지 않는다. `unrepresentedEventIndices`에는 oracle의 직접 대표 대응 밖의 cast가 남고 동시 instance도 포함할 수 있다. 생성 report의 `samples.eventIndices`·`collapsedCasts`로 구분한다.  |
| 무결성    | 생성 report에 원본 SHA-256을 기록한다. 새 근거는 byte 변경을 거부하고 재생 결과에 입력·YAML·근거 report SHA-256을 기록한다. 기존 해시 없는 report는 revision·종료·정규화 occurrence를 대조한다.                                                                                    |
| 상태      | 대응 미확정·미지원·재생 오류가 있으면 `draft`다. 검사한 행의 내부 재생이 통과하면 `internally_validated`이며 `runtime_compatible`은 부여하지 않는다.                                                                                                                               |

모든 그룹의 train은 통과했다. 기본·보조 평가 모두 오매칭·모호한 활성 매칭·잘못된 jump·관측 의존성 위반·window 미검출·신호 누락은 0이다. 실제 초안에는 jump가 없으므로 실제 분기 진입·합류 검증의 근거로 사용하지 않는다. 분기·합류·반복 jump·forcejump·reset은 합성 회귀 검사에서 확인했다.

# 일반 던전 보스 무한 루프 비교 기준

기준은 로컬 cactbot의 고정 커밋 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`이다. 사용자의 전제에 따라 이 커밋의 타임라인을 게임 진행의 비교 기준으로 삼는다. 아래 주기는 로그로 새로 측정한 값이 아니라 `forcejump` 좌표에서 label 좌표를 뺀 명목 주기다. Clyteum은 이 비교표의 대상이 아니다.

## 시계와 검증 범위

| 구분             | 해석과 검사 목적                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `1000/2000/3000` | 첫째/둘째/셋째 보스를 구분하는 가상 시계 좌표다. 실제 전투 시작 후 1000초를 뜻하지 않는다. 각 보스의 `7DC` 봉쇄 신호로 진입하고 `7DE` 해제 신호로 0에 복귀한다.                                                                                                                                                                                                                                                                  |
| 첫 루프 진입     | 예: Antivirus X의 `1081.4`는 해당 구간의 `1000.0` 기준으로 +81.4초다. 첫 관측 시전 기준 FFLogs 시간이나 phase 시작 시각과는 따로 정렬한다.                                                                                                                                                                                                                                                                                       |
| `forcejump`      | 닫는 좌표를 지나면 다음 반복을 예측하는 시계 이동이다. 같은 줄의 Ability가 없더라도 반복 전망이 가능하다. 해당 Ability의 관측과 시간 동기화는 별도 검사한다. [파서](https://github.com/quisquous/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/timeline_parser.ts#L647-L669), [실행기](https://github.com/quisquous/cactbot/blob/e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b/ui/raidboss/timeline.ts#L633-L655) |
| 표시와 관측      | `#Ability`는 주석이므로 활성 sync가 아니다. 표시 전용 세부타는 순서·간격의 비교 대상으로 유지하되, 해당 줄이 실제 관측으로 sync했다고 세지 않는다.                                                                                                                                                                                                                                                                               |
| 보장 범위        | 이 문서는 소스 비교다. FFLogs 생성 결과·홀드아웃·ACT 런타임의 합격을 의미하지 않는다. 원본의 TODO와 best-effort 경고는 아래에 보존한다.                                                                                                                                                                                                                                                                                          |

## 로그에서 만든 루프에 적용할 검사

| 검사             | 합격 근거 / 실패 예                                                                                                                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시작 정렬        | 봉쇄 좌표, 실제 첫 관측, 생성된 phase 원점을 각각 기록한다. 준비 ID와 피해 ID의 시간차를 임의로 같은 offset으로 맞추지 않는다.                                                                      |
| 완전한 순서 문맥 | 경계부터 다음 경계까지 대표 슬롯·대안·동시 파동·중간 반복을 비교한다. 예: Eliminator center 또는 Remains Keraunography가 다시 나왔다는 사실만으로 조기 닫지 않는다.                                 |
| 처음과 이후 회차 | 첫 진입 이전의 유한 opener와 반복 본문을 구분한다. 긴 독립 로그에서 첫 회차·둘째 이후 회차·경계를 넘는 다음 prefix가 맞아야 한다. 한 번 더 나온 동일 기술만으로 무한 반복이라고 결론 내리지 않는다. |
| 시간과 drift     | 전체 주기 외에 각 슬롯의 경계 상대 시각과 여러 회차 누적 오차를 측정한다. ID 대안·castbar/피해·가변 intermission이 만드는 차이를 별도 표기한다.                                                     |
| helper 및 다타   | helper source를 포함해 원본 eligible cast와 출력 대표 슬롯의 대응을 확인한다. 다타를 모두 독립 예측으로 만들거나 helper를 제외해 누락을 감추지 않는다.                                              |
| 예측 연속성      | 경계 Ability를 관측하기 전에도 다음 회차의 이벤트가 표시되는지 실행기로 확인한다. 닫는 sync 하나가 누락돼도 예측이 멎지 않아야 하며, 동일 ID의 내부 시전이 잘못 jump하지 않아야 한다.               |
| 짧은 처치·누락   | 루프 진입 전/중간 처치와 관측 종료 뒤 미래를 실제 누락과 구분한다. 살아 있는 구간의 opening/중간 필수 기술 누락을 종료 censoring으로 숨기지 않는다.                                                 |
| 구간 reset       | 보스 사이의 해제·재진입을 재생해 이전 보스 loop가 다음 보스로 새지 않는지 확인한다. 마지막 한 번의 reset만 시험하지 않는다.                                                                         |
| 판정 분리        | 원본 커버리지, 생성 구조, 독립 홀드아웃, 소비자 예측을 따로 보고한다. 내부 replay 합격만으로 게임·ACT 호환성이나 source 전체 커버리지를 선언하지 않는다.                                            |

검증 기록에는 보스별 입력 수, 실제 완주 회차 수, 경계 대응, 슬롯 누락/추가, 최대 상대 시간 오차, 처치 이후 제외 범위, 미검증 소비자 동작을 남긴다. 원본 TODO가 있는 보스도 동일한 항목으로 관측하되, 긴 로그가 없으면 그 한계를 그대로 보고한다.

# R9S 도입부 누락 감사

## 원인과 수정

원본에는 약 11.2초부터 시전이 있지만 기존 KDL은 171.8초부터 시작했다. 첫 공통 고유 시전 `Finale Fatale` 전의 반복 발생이 인접 기준점 정렬과 후반 학습의 범위 밖이었고, 별도 도입부 분기도 생성되지 않아 전체 도입부가 빠졌다. 시간 표본 부재나 원본 로그 부족으로 인한 누락은 아니다.

| 단계                | 확인 결과                                                                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 입력 관측           | 세 입력 모두 첫 시전이 11.184–11.247초에 있다.                                                                                      |
| trace별 발생 그래프 | 171초 이전 시전 파동 후보 55·55·61개를 보존한다.                                                                                    |
| 기존 출력           | 같은 범위에 표본을 둔 이벤트가 0개다. 첫 일정은 171.8초다.                                                                          |
| 수정                | raid에서 combat 시작부터 NPC별 첫 고유 기준점 전까지 기존 표시용 부분 정렬을 적용한다. 기존 분기가 해당 도입부를 소유하면 건너뛴다. |
| 실행 조건           | 새 발생은 표시 일정으로만 내보낸다. 반복 ID를 새 sync로 만들거나 특정 전투 ID·3분 경계를 하드코딩하지 않는다.                       |

초기 시각은 FFLogs 전투 시작을 기준으로 추정한다. phase 시작이 정확히 0이면 초기 상태로 취급하고, 도입부 안의 실제 phase 전환은 기존처럼 미해결로 남긴다. dungeon·alliance의 보스 진입 정책은 바꾸지 않는다.

## 자료와 결과

입력은 `logs/autonomous-r9s/`의 다음 파일이다. 해시·원본 인덱스·발생 대응은 재생성한 evidence의 `analysis.inputs`, `progression`, `events[].observation_nodes`에 남는다.

| 파일                       | 171초 이전 후보 | 출력 시각 표본에 직접 대응 | 직접 대응하지 않은 후보 |
| -------------------------- | --------------: | -------------------------: | ----------------------: |
| `2MTktf46gvZhBcF8_50.json` |              55 |                         24 |                      31 |
| `PpRYFy1nK98d6NTm_1.json`  |              55 |                         24 |                      31 |
| `mVCt9aDdzq2Q8BLJ_11.json` |              61 |                         24 |                      37 |

이 수는 원본 시전 파동 후보 기준이며 기믹 개수나 누락 기믹 개수가 아니다. 분절·동시 개체·활동 대안·모호한 대응이 포함될 수 있다. 원본 후보 전체를 출력해야 한다는 뜻도 아니다.

| 생성본  | 이전 → 수정 후 정의 수 | 결과                                           |
| ------- | ---------------------: | ---------------------------------------------- |
| R9S     |                58 → 82 | 도입부 표시 24개 추가, 첫 일정 171.8 → 11.2초  |
| R10S    |              142 → 155 | 같은 일반 규칙으로 도입부 표시 13개 추가       |
| R11S    |              179 → 179 | KDL 바이트 동일, 기존 분기와 Heartbreaker 유지 |
| Clyteum |                45 → 45 | KDL 바이트 동일                                |

검토용 산출물은 `out/r9s-opening.kdl`, `out/r9s-opening.evidence.json`이다. 이전 생성본은 `out/autonomous-r9s-instance-waves.kdl`이다. 출력 파일은 버전 관리 대상이 아니며 위 입력과 `generate --mode raid`로 재생성한다.

## 검증과 남은 범위

| 검사          | 결과와 한계                                                                                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 합성 회귀     | 반복만 있는 도입부, 0초 발생, 로그 간 수 초 차이, 초기 phase와 실제 전환, 대응이 유일하지 않은 회차, dungeon 정책 유지 검사                                                                              |
| R9S 합성 재생 | FFLogs cast→Ability 및 0초 InCombat을 가정한 세 기록에서 첫 이벤트가 11.2초에 표시된다. ambiguous·unresolved·violation 없이 각각 82·82·80개 이벤트를 표시하고, 마지막 기록의 종료 뒤 2개는 unobserved다. |
| 독립 검증     | 기존 자동 검증은 최초 고유 기준점부터 대응하므로 새 도입부 24개를 검증했다고 주장하지 않는다. 도입부 평가 범위 확장이 필요하다.                                                                          |
| 잔여 대응     | 171초 이전 후보 중 31·31·37개가 표시 시각 표본에 직접 대응하지 않는다. 다중집합 묶음과 활동 대안·부분 순서 대응을 후속 분석해야 한다.                                                                    |
| 실제 실행     | ACT 신호 동등성·외부 실행기·실제 게임 검증은 수행하지 않았다. 합성 재생 통과가 전체 기믹 복원을 뜻하지 않는다.                                                                                           |

진행 그래프와 시간 추정의 첫 분리만으로 도입부가 자동 복원되지는 않았다. 보존된 노드와 출력의 차이를 대조해 누락 단계를 찾았고, 도입부 범위 누락을 별도로 수정했다. trace 간 조건부 진행을 학습하는 후속 작업은 [분리 계획](progression-and-timing.md)을 따른다.

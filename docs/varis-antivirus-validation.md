# Varis EX의 선택별 시간 창과 Antivirus X 누락

후속 [에이전트 작성 P3](../timelines/varis-ex-p3-authoring.md)는 여섯 Gunshield 순서와 공통 후속 복구를 작성하고 새 보류 pull 6개에서 평가했다. 아래 자동 생성기의 지원 범위와 구분하며 Varis 전투 전체나 Antivirus X의 완성을 뜻하지 않는다.

후속 [유한 블록 이력 생성](block-history-validation.md)으로 Varis 생성본은 79→174개 정의, P3 시작 대응은 2→18개가 됐다. 아래의 79개·2/18 및 미지원 선택 이력은 초기 조사 결과다. 모든 원본 패킷·미관측 순서·helper 지원 완료를 뜻하지 않는다.

2026-11-02 기준 조사·검증 결과다. 기준 cactbot은 `e79ea7f16093be5b80cda0e2d5bc8eb899d6fb4b`이며 생성기는 이 자료를 입력으로 사용하지 않는다. 실용적인 기믹 예고를 목표로 하고 정확한 시간 재현이나 모든 경로의 정적 증명을 요구하지 않는다.

## Varis EX: 이전 구간이 다음 선택 시간을 결정한다

`ui/raidboss/data/05-shb/trial/varis-ex.txt`의 P3는 Loaded·Reinforced·Electrified Gunshield를 각각 한 번씩, 임의 순서로 실행한다. cactbot은 선택 시 가상 시각 500·700·900으로 이동하고 각 구간 끝에서 다음 선택으로 다시 이동한다. 아래의 창은 모두 ±10초다.

| 이전 선택   | 이전 구간 시작 | 다음 선택 시각 | 구간 상대 중심 | 생성 입력 6개의 실제 StartsUsing 간격 |
| ----------- | -------------: | -------------: | -------------: | ------------------------------------: |
| Loaded      |          500.0 |          554.3 |         54.3초 |                       51.995–53.948초 |
| Reinforced  |          700.0 |          752.8 |         52.8초 |                       54.929–54.943초 |
| Electrified |          900.0 |          958.7 |         58.7초 |                       58.363–58.799초 |

같은 다음 선택이어도 이전 선택에 따라 기준 시각이 다르다. 따라서 P3의 모든 후속 선택을 전투 전체의 한 평균 시각·공통 창으로 처리하면 이 관계를 잃는다. 실제 간격의 2초 안팎 차이는 회차·선택을 알아볼 수 있는 근사 일정에서 수용할 변동이다. 이 차이만으로 경로를 제외하지 않는다.

첫 branch는 P1의 Magitek Shielding 두 ID 선택에 사용됐다. 이후 두 선택 구간은 `additional or non-raid choice requires phase and history support`로 보류된다. 단순히 ‘branch 하나’ 제한을 제거하면 후속 선택을 독립적으로 조합할 위험이 있다. 다음 선택의 후보와 시각은 이전 구간·사용한 블록에 연결해야 한다.

### 스키마와 다음 구현

이번 사례 때문에 새 문법을 추가하지는 않는다. 기존 `phase`의 `enter from=... at=... before=... after=...`로 이전 선택별 시간 창과 구간 시계 초기화를 표현할 수 있다. 예를 들어 Loaded 구간으로 들어갈 때 이전 구간이 Reinforced이면 52.8초, Electrified이면 58.7초를 중심으로 받는다. `phase`는 게임의 대규모 페이즈뿐 아니라 이처럼 실행 시계를 공유하는 기믹 구간도 나타낼 수 있다.

[실행기 oracle](../tests/fixtures/timeline/varis-choice-windows.kdl)은 P3 발췌를 수동 작성한 것으로 자동 생성본과 구분한다. [회귀 테스트](../tests/varis_reference.rs)는 여섯 순서 모두에서 해당 시각의 전환·예고를 확인하고, 창 시작보다 0.1초 이른 같은 신호가 전환하지 않는지도 검사한다. 같은 테스트 파일에서 여섯 순서의 합성 FFLogs 입력을 `generate`에 직접 넣고 미지원 후속 선택이 누락 진단에 남는지 확인한다. 합성 로그는 실제 로그나 완전한 생성 지원의 증거가 아니다.

| 다음 구현                                                 | 유지할 경계                                                                 |
| --------------------------------------------------------- | --------------------------------------------------------------------------- |
| 공통 진행 경계 사이에서 선택 블록과 이전 선택 상태를 학습 | 특정 ID·NPC 이름·cactbot의 가상 시각으로 분할하지 않음                      |
| 후속 후보·창을 이전 구간의 시작에 상대적으로 추정         | 전투 전체 평균 창을 넓히는 것으로 선택 이력을 대체하지 않음                 |
| 상태별 구간과 `enter from`으로 렌더링                     | 최종 KDL 단독 실행, 관측되지 않은 순서 조합을 임의로 추가하지 않음          |
| 선택 이력·사용한 블록과 표시 시각을 함께 검증             | 실제 여섯 번째 순서와 추가 독립 보고서도 확보. 전체 runtime·ACT 검증과 구분 |

향후 같은 구간 표현으로 실제 진행을 담지 못하는 사례가 확인되면 스키마를 변경한다. 이번 oracle은 시간 창 표현의 가능성을 검증하며, 모든 방문 이력 제약·전투 수명주기를 구현한 완성본은 아니다.

## Alexandria: Antivirus X는 시작 두 정의만 남았다

기존 5개 입력에서 `generate --mode dungeon`은 성공하지만 Antivirus X 본문은 최초 Immune Response의 `8E1A`·`8E1B` 두 정의뿐이었다. Quarantine `8E20`은 다섯 입력 모두 두 번 관측되는데도 빠졌다.

| 원인                       | 확인과 처리                                                                                                                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선택별 반복 횟수·순서 차이 | 앞·옆 Immune Response의 ID와 횟수가 달라 전체 최적 정렬이 모호했다. 고유 시전이 없는 보스의 진입 정렬에서도 그 뒤의 공통 시전이 가려졌다.                                                           |
| 과도한 표시 채택 조건      | 부분 순서 복원은 구간의 모든 활동 횟수가 같아야 진행됐다. 다른 활동의 변동이 안정된 Quarantine까지 막았다.                                                                                          |
| 수정                       | 부분 순서 대응 전에 활동별 횟수가 일관된 신호만 투영한다. 제외된 파동 사이의 선후 관계는 이어서 검사하고 순환 모순은 계속 거부한다. 활동 하나의 빠진 발생을 채우거나 원본 그래프를 수정하지 않는다. |
| 실행 경계                  | 추가 표시의 sync는 생략한다. 기존 bounded/opening 표시 정렬에만 적용하고 종료 검열·loop 증명·선택 이력 판정을 완화하지 않는다.                                                                      |
| 근거                       | 추가 이벤트의 `alignment.activity_projection="equal-count-activities"`와 원본 노드 참조로 추적한다. 제외 활동은 원본·누락 진단에 남는다.                                                            |

| 검증             | 결과                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 전체 5개 생성    | Alexandria **53 → 55개**, Antivirus X **2 → 4개** 정의. Quarantine 시전 두 발생을 추가했으며 두 개의 새 게임 기믹을 뜻하지 않는다.                                 |
| 독립 보고서 보류 | `AvDf4xcj29KFHhWL`을 빼고 네 파일·세 보고서로 생성. 보류 자료의 두 시전에도 예고가 존재한다.                                                                       |
| 직접 표시 재생   | 전체 원본 노드 10개에서 예고 없음 0, 진단 0. cast→Ability 투영의 최근접 같은 이벤트 예고와 최대 차이 65ms, 보류 최대 64ms. 정확도 요구 조건이나 ACT 검증은 아니다. |
| 다른 코퍼스      | 대표 9개·79개 입력 재생성에서 원본 그래프 전부 유지. 다른 8개 KDL 해시와 기존 정의는 유지했다.                                                                     |
| 합성 회귀        | 선택별 횟수 차이가 공통 반복을 가리지 않음, 누락된 동반 활동을 만들어내지 않음, 활동 투영 뒤에도 빈 파동을 건너는 순서 모순을 검출함을 검사한다.                   |

앞/옆 선택, Interferon helper와 Purge를 포함한 전체 Antivirus X 반복은 여전히 미완료다. 기존 본체 loop는 helper 경계를 보지 못하며, 가변 ID가 있는 말단 본문을 같은 신호열로 대응하지 못한다. 유한 표시 두 발생의 복원을 이 반복 문제의 해결로 세지 않는다.

긴 관측도 부족하다. 다섯 입력 모두 최초 Immune Response 기준 약 28–38초의 도입 Purge 5파와 약 69–79초의 첫 반복 Purge 5파가 있다. 다음 반복의 첫 Purge는 `JzmkA9dqvhpB84Lg/109`의 122.445초 한 건에서만 관측된다. 나머지는 그 전에 종료되어 부재를 기믹 차이로 보지 않는다. helper·ID 대안 학습과 함께 더 오래 지속된 보스 기록을 확보하거나, 일부 로그가 제공하는 반복 지지를 다른 로그의 본문 지지와 결합해야 한다.

로컬 `out/validation/varis-antivirus/`에 생성 전후 KDL·evidence, 수집 계획·오류, `regression.json`, `varis-audit.json`, `quarantine-replay.json`과 재현용 Bun 스크립트를 남겼다. 실제 ACT와 외부 실행기는 검증하지 않았다.

# Clyteum 누락 감사

## 확인한 원인과 수정

기존 생성본은 Eye of the Scorpion·Chort·Malphas의 첫 고유 기준점 이전을 분석하지 않았다. R9S 도입부 수정은 raid에만 적용돼 dungeon에는 남아 있었다. 보스가 시작된 뒤 수십 초가 빠졌고 그 뒤의 시전을 phase 0으로 삼았다. 다음과 같이 mode 차이를 반영했다.

| 항목      | 수정                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위 시작 | raid는 combat 시작, dungeon·alliance는 해당 보스 자신의 첫 시전부터 첫 고유 기준점까지 표시 정렬한다.                                       |
| 보스 시계 | 복원된 가장 이른 공통 발생으로 phase 0을 정한다. 다른 보스·이동·앞선 phase 경계는 이 도입부에 포함하지 않는다.                              |
| 반복 진입 | 반복 ID도 첫 phase 진입에 사용한다. 활성 phase의 같은 enter는 기존 실행 계약에 따라 무시한다.                                               |
| 동기화    | 복원한 반복 발생은 표시만 생성한다. 진입 신호로 채택됐다고 반복 ID에 event sync를 추가하지 않는다.                                          |
| 대응 근거 | 기존 모든 최적 표시 정렬의 강제 대응을 사용하고 원본 표본·발생 그래프 노드 참조를 남긴다. 이름이나 근접 시각만으로 다른 ID를 합치지 않는다. |

## 도입부 복원 단계의 세 입력 결과

입력은 `logs/clyteum/AVxmgdNytFPBwLRH_31.json`, `BTxgcVRnWMpDrK9X_30.json`, `J1xNVnwWXLHDfkcG_1.json`이다. 해시·원본 관측·내부 노드 참조는 생성 evidence에 남는다. 원본 후보 수는 정규화된 동일 밀리초의 시전 파동 기준이며 기믹 개수가 아니다.

| 보스                | 기존 정의 → 수정 후 | 입력별 원본 후보 | 입력별 직접 시각 표본 대응 |
| ------------------- | ------------------: | ---------------- | -------------------------- |
| Eye of the Scorpion |              9 → 13 | 21 / 19 / 19     | 13 / 13 / 13               |
| Chort               |              6 → 32 | 45 / 35 / 43     | 32 / 32 / 32               |
| Malphas             |             30 → 35 | 39 / 35 / 39     | 35 / 31 / 35               |
| 합계                |             45 → 80 | 105 / 89 / 101   | 80 / 76 / 80               |

최초 고유 기준점은 기존 첫 시전을 기준으로 Eye 약 70.4초, Chort 약 98.4초, Malphas 약 50.9초 뒤였다. 이제 세 보스 모두 첫 시전부터 일정을 시작한다. 산출물은 `out/clyteum-boss-opening.kdl`과 `.evidence.json`, 이전 생성본은 `out/clyteum-opening.kdl`이다. 출력은 버전 관리 대상이 아니며 위 세 입력과 `generate --mode dungeon`으로 재생성한다.

### 당시 재생과 검증

| 검사              | 결과와 한계                                                                                                                                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 합성 회귀         | dungeon·alliance의 반복 도입부, 로그 간 수 초 차이, 두 보스의 같은 능력 ID, 앞선 phase 경계·이동 제외, phase 진입 후 반복 enter 무시, 반복 event sync 금지를 검사한다. evidence를 삭제한 KDL만으로도 재생한다.                           |
| 세 입력 합성 재생 | FFLogs cast→Ability와 전투 시작 투영을 가정한다. 세 보스 모두 원본 첫 시전에서 진입하고 각 기록에 phase 진입은 3회다. 표시 이벤트는 80 / 76 / 80개, 중간 기록 종료 뒤 4개는 unobserved다. ambiguous·unresolved·violation·skipped는 없다. |
| 라이브러리 이행   | `petgraph` 저장소 교체만 적용했을 때 R11S·R9S·R10S·Clyteum의 기존 KDL은 바이트 단위로 같았다. 그래프 라이브러리 자체가 누락을 복원한 것은 아니다.                                                                                        |
| 독립 검증         | 기존 자동 검증은 첫 고유 기준점부터 검사하므로 새 도입부가 독립 검증됐다고 주장하지 않는다. 학습용 세 입력의 합성 재생은 ACT 신호 동등성이나 실제 게임 검증이 아니다.                                                                    |

## 남은 누락

| 구간                | 남은 내용과 다음 작업                                                                                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Eye of the Scorpion | Petrifying Beam의 `C3FF/C401`·`C400/C402` 대안과 순서 교환, 일부 긴 trace의 후반 Surface Missile. 선택·파동과 관측 종료를 나눠 대응해야 한다.                                                  |
| Chort               | Mortifying Flesh의 `BEE5/BEE6/BEE7/BEE8/BEE9` 대안, 긴 trace의 두 번째 Bodyweight Exorcism 묶음과 후속 Ripples of Gloom. 짧은 trace의 보스 종료가 dungeon 전체 종료와 다른 점도 반영해야 한다. |
| Malphas             | 공통 Puppet Strings 두 발생 사이의 Cast-Off Halo·Metallic Miasma 순서 교환. 전체 LCS의 동률 때문에 공통 Puppet Strings도 함께 제외된다. 선택 상태와 공통 발생을 구분해야 한다.                 |

원본 후보와 출력 시각 표본의 차이를 그대로 기믹 누락 수로 해석하지 않는다. 개체 파동·대안·다른 관측 종료가 포함되며, 대응되지 않은 후보는 발생 그래프에 남는다.

## 보스 시도 분리와 전체 21개 입력 재검증

전체 파일·trace·SHA-256은 [입력 명세](clyteum-entry-inputs.csv)에 고정했다.

이전에는 `logs/clyteum/*.json` 전체 생성이 실패했다. 세 보스 모두 전체 raw trace에서 단 한 번씩 나타나는 공통 시전이 없었고, 본체 instance가 바뀌는 재시도도 한 시전열에 들어 있었다. 이제 관측된 본체 처치로 완료된 시도를 구분한다. 21개 파일의 63개 보스 범위에서 79개 본체 instance를 추적하고, 완료된 63개 시도를 학습한다. 원본 그래프는 다른 시도의 관측까지 보존한다. 입력 파일을 제외하거나 특정 전투 ID를 하드코딩하지 않았다.

예를 들어 `JGNgkPYqhm7WbdFT/7`의 Chort 본체는 instance 1에서 처치되지 않았고 instance 2에서 HP 0과 death가 관측된다. 이 기록의 Malphas는 instance 3에서 처치된다. 같은 이름의 helper instance 수로 시도 수를 추정하지 않는다. 서로 겹치는 개체 관측도 재시도로 확정하지 않는다.

완료 시도만 사용해도 Chort에는 고유 공통 시전이 없다. 같은 단일 보스 진입을 확인하고 진입 뒤의 모든 최적 정렬에서 강제되는 발생을 공통 표시로 생성한다. 복잡한 순서 교환이나 더 긴 반복 경로는 아직 이 공통 표시만으로 표현하지 못한다.

| 학습 입력    | 이전 → 현재                | 현재 보스별 정의               |
| ------------ | -------------------------- | ------------------------------ |
| 기존 세 입력 | 80 → 87개                  | Eye 13 / Chort 39 / Malphas 35 |
| 전체 21개    | 생성 실패 → 3개 phase·80개 | Eye 21 / Chort 24 / Malphas 35 |

세 입력에서 Chort 후반이 7개 더 복원된 이유는 조기 처치를 던전 전체 종료와 구분했기 때문이다. 가장 짧은 기록에서 보스가 이미 죽었다면, 던전 기록이 계속됐다는 이유로 긴 기록들의 후반 지지를 거부하지 않는다.

### 원본 대응

| 보스                | 원본 파동 후보 | 완료 시도 범위 후보 | 출력 대응 |
| ------------------- | -------------: | ------------------: | --------: |
| Eye of the Scorpion |            524 |                 460 |       252 |
| Chort               |            979 |                 834 |       504 |
| Malphas             |            986 |                 800 |       508 |
| 합계                |          2,489 |               2,094 |     1,264 |

완료 범위 후보의 약 60.4%가 출력에 대응한다. 직접 시각 표본은 1,262개이고 분절 파동 근거로 2개가 더 대응한다. 이 수는 기믹 개수나 실제 누락 기믹 수가 아니다. 앞 표의 ID 대안·순서 교환, Chort의 참조보다 긴 후반·반복은 여전히 남아 있다.

### 재생·독립 검증과 소비자 한계

| 검사                  | 관측 결과                                                                                                                                                                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 완료 범위 합성 재생   | 각 입력에서 선택한 완료 보스 범위의 cast만 Ability로 투영했다. 21개 기록 모두 보스 phase 진입이 3회이고 ambiguous·unresolved·violation·skipped는 없다. 원본 시각 표본이 있는 1,262개 표시가 모두 실행됐다. 이는 전체 실패 시도·재시작 재생이 아니다. |
| 보류 입력             | 자동 선택한 `z9wpNYrRyvGgQA74/1`을 제외한 20개 입력으로 별도 KDL을 생성했다. 보스 진입부터 비교해 Chort 24개, Eye 11개, Malphas 22개가 강제 대응했다. Malphas 1개는 미해결, 참조 후반 23개는 관측된 조기 처치 뒤 미관측이다.                         |
| 독립 모델의 표시 시각 | 강제 대응한 57개 모두 투영 재생에서 표시됐다. 원본 대응과 표시 시각의 최대 차이는 0.753초다. 대응하지 못한 기믹의 품질이나 보고서 간 통계적 독립성을 보장하지 않는다.                                                                                |
| 처치 후 표시          | 전체 21개 완료 범위 재생에서 표시 1,451개 중 189개가 보스 처치 뒤에 나타났다. 그 기록의 직접 학습 표본이 없는 후반 표시이며 다음 보스 진입 전까지 남는다. 생성 KDL에 runtime 보스 종료 신호가 없기 때문으로, 재생 성공으로 숨기지 않는다.            |
| 실제 실행             | FFLogs cast→Ability는 검증용 가정이다. 실제 ACT 신호·처치 감지·외부 실행기·실패 시도의 재시작은 검증하지 않았다. FFLogs death를 runtime 신호로 자동 주입하지 않았다.                                                                                 |

산출물은 `out/clyteum-entry-v2.kdl`, `.evidence.json`, `out/clyteum-entry-v2-audit.json`, `out/clyteum-entry-v2-clear-replay.json`이다. 별도 학습·검증 모델은 `out/clyteum-entry-training.kdl`과 `out/clyteum-entry-heldout-replay.json`에 남겼다. 기존 세 입력 생성본은 `out/clyteum-completion-v2.kdl`이다. 파일은 버전 관리 대상이 아니다.

```sh
btimeline generate logs/clyteum/*.json --mode dungeon -o out/clyteum-entry-v2.kdl
```

후속 우선순위는 실제 관측 가능한 보스 종료 신호, 대안·선택 이력·반복 경로의 통합, 실패 시도 전체의 재시작 검증이다. [분리 계획](PROGRESSION_AND_TIMING.md)에 따라 표시 구조와 시간 추정은 계속 구분한다.

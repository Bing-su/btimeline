# Clyteum 누락 감사

## 확인한 원인과 수정

기존 생성본은 Eye of the Scorpion·Chort·Malphas의 첫 고유 기준점 이전을 분석하지 않았다. R9S 도입부 수정은 raid에만 적용돼 dungeon에는 남아 있었다. 보스가 시작된 뒤 수십 초가 빠졌고 그 뒤의 시전을 phase 0으로 삼았다. 다음과 같이 mode 차이를 반영했다.

| 항목      | 수정                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 범위 시작 | raid는 combat 시작, dungeon·alliance는 해당 보스 자신의 첫 시전부터 첫 고유 기준점까지 표시 정렬한다.                                       |
| 보스 시계 | 복원된 가장 이른 공통 발생으로 phase 0을 정한다. 다른 보스·이동·앞선 phase 경계는 이 도입부에 포함하지 않는다.                              |
| 반복 진입 | 반복 ID도 첫 phase 진입에 사용한다. 활성 phase의 같은 enter는 기존 실행 계약에 따라 무시한다.                                               |
| 동기화    | 복원한 반복 발생은 표시만 생성한다. 진입 신호로 채택됐다고 반복 ID에 event sync를 추가하지 않는다.                                          |
| 대응 근거 | 기존 모든 최적 표시 정렬의 강제 대응을 사용하고 원본 표본·발생 그래프 노드 참조를 남긴다. 이름이나 근접 시각만으로 다른 ID를 합치지 않는다. |

## 세 입력에서의 결과

입력은 `logs/clyteum/AVxmgdNytFPBwLRH_31.json`, `BTxgcVRnWMpDrK9X_30.json`, `J1xNVnwWXLHDfkcG_1.json`이다. 해시·원본 관측·내부 노드 참조는 생성 evidence에 남는다. 원본 후보 수는 정규화된 동일 밀리초의 시전 파동 기준이며 기믹 개수가 아니다.

| 보스                | 기존 정의 → 수정 후 | 입력별 원본 후보 | 입력별 직접 시각 표본 대응 |
| ------------------- | ------------------: | ---------------- | -------------------------- |
| Eye of the Scorpion |              9 → 13 | 21 / 19 / 19     | 13 / 13 / 13               |
| Chort               |              6 → 32 | 45 / 35 / 43     | 32 / 32 / 32               |
| Malphas             |             30 → 35 | 39 / 35 / 39     | 35 / 31 / 35               |
| 합계                |             45 → 80 | 105 / 89 / 101   | 80 / 76 / 80               |

최초 고유 기준점은 기존 첫 시전을 기준으로 Eye 약 70.4초, Chort 약 98.4초, Malphas 약 50.9초 뒤였다. 이제 세 보스 모두 첫 시전부터 일정을 시작한다. 산출물은 `out/clyteum-boss-opening.kdl`과 `.evidence.json`, 이전 생성본은 `out/clyteum-opening.kdl`이다. 출력은 버전 관리 대상이 아니며 위 세 입력과 `generate --mode dungeon`으로 재생성한다.

### 재생과 검증

| 검사              | 결과와 한계                                                                                                                                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 합성 회귀         | dungeon·alliance의 반복 도입부, 로그 간 수 초 차이, 두 보스의 같은 능력 ID, 앞선 phase 경계·이동 제외, phase 진입 후 반복 enter 무시, 반복 event sync 금지를 검사한다. evidence를 삭제한 KDL만으로도 재생한다.                           |
| 세 입력 합성 재생 | FFLogs cast→Ability와 전투 시작 투영을 가정한다. 세 보스 모두 원본 첫 시전에서 진입하고 각 기록에 phase 진입은 3회다. 표시 이벤트는 80 / 76 / 80개, 중간 기록 종료 뒤 4개는 unobserved다. ambiguous·unresolved·violation·skipped는 없다. |
| 라이브러리 이행   | `petgraph` 저장소 교체만 적용했을 때 R11S·R9S·R10S·Clyteum의 기존 KDL은 바이트 단위로 같았다. 그래프 라이브러리 자체가 누락을 복원한 것은 아니다.                                                                                        |
| 독립 검증         | 기존 자동 검증은 첫 고유 기준점부터 검사하므로 새 도입부가 독립 검증됐다고 주장하지 않는다. 학습용 세 입력의 합성 재생은 ACT 신호 동등성이나 실제 게임 검증이 아니다.                                                                    |

## 남은 누락

| 구간                | 남은 내용과 다음 작업                                                                                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Eye of the Scorpion | Petrifying Beam의 `C3FF/C401`·`C400/C402` 대안과 순서 교환, 일부 긴 trace의 후반 Surface Missile. 선택·파동과 관측 종료를 나눠 대응해야 한다.                                                  |
| Chort               | Mortifying Flesh의 `BEE5/BEE6/BEE7/BEE8/BEE9` 대안, 긴 trace의 두 번째 Bodyweight Exorcism 묶음과 후속 Ripples of Gloom. 짧은 trace의 보스 종료가 dungeon 전체 종료와 다른 점도 반영해야 한다. |
| Malphas             | 공통 Puppet Strings 두 발생 사이의 Cast-Off Halo·Metallic Miasma 순서 교환. 전체 LCS의 동률 때문에 공통 Puppet Strings도 함께 제외된다. 선택 상태와 공통 발생을 구분해야 한다.                 |

원본 후보와 출력 시각 표본의 차이를 그대로 기믹 누락 수로 해석하지 않는다. 개체 파동·대안·다른 관측 종료가 포함되며, 대응되지 않은 후보는 발생 그래프에 남는다.

## 전체 21개 입력의 실패

`logs/clyteum/*.json` 21개를 함께 생성하면 현재도 `No common casts with a supported shared order`로 실패한다. NPC 이름과 능력 ID별로 정확한 시전 시각을 집계하면 **세 보스 모두 전체 입력에서 단 한 번씩 나타나는 공통 시전이 0개**다. 기존 생성 분석의 고유 기준점 요구가 원인이며 이번 변경은 그 요구를 없애지 않았다. 반복 수가 큰 기록의 정상 장기전·재시도 여부도 별도로 확인해야 한다.

입력을 임의로 제외하거나 능력별 첫 관측을 같은 회차로 확정해 성공으로 바꾸지 않았다. 다음 구현은 고유 시각 기준점 없이 발생·부분 순서·조건부 진행을 학습해야 한다. 전체 자료의 실패를 숨기지 않고 [진행 그래프 분리 계획](PROGRESSION_AND_TIMING.md)의 우선 회귀 사례로 유지한다.
